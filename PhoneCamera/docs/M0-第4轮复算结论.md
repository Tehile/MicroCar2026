日期：2026-09-23

方法：仍然不采信报告里的汇总结论，从逐帧原始 JSON 重算；本轮新增判据的 PASS/FAIL 双向路径都做了构造测试。

## 一、两个核心要求的现状

### 时间戳准确 —— 站得住，而且比报告写的更强

重算的四组数（144 个有效帧间隔、跨 4793 ms）：

| 量 | 实测 |
|---|---|
| 单调性 | 149 个间隔全严格递增 |
| **累积偏离理想均匀网格 min/max/终值** | **−122 / +165 / 0 ns** |
| 回归斜率 | −0.0122 ns/帧 ⇒ 全窗口 **−0.053 ppm** |
| 与回读帧时长的一致度 | **0.124 ppm** |
| 间隔结构 | **严格周期 5 的确定性拍频**（`d[i]==d[i+5]` 在 144/144 处成立） |
| 帧内读出 skew | 6 909 696 ns 恒定（占帧周期 20.8%，≈2.25 µs/行） |

**"累积偏离终值为 0 且有界"才是"时间戳准确"的实质**，而不是那个 ppm 抖动数。
上一轮报的"抖动 3.06 ppm"读起来像随机噪声，实际是确定性拍频 —— 这比噪声是**更强**的保证
（每帧偏差可复现、可精确预测），但也意味着"抖动"这个词本身就选错了。

### 内参不变 —— 单会话干净，跨会话"落点可复现"已证，**但"内参真不变"仍未证**

干净的：`active_physical_id` 恒为 **2**；13 项锁定字段 `distinct_count` 全为 1；
`crop_region` = 整个活动阵列；对焦回读 `1.001001 diopt`；回读帧时长恒定 `33287995 ns`。

G21 实测 3 轮：

| 项 | 结果 |
|---|---|
| 焦点回读 | `1.001001 / 1.001001 / 1.001001` diopt，极差 **0**（相对 0%） |
| 生效物理镜头 | `['2']` —— 跨会话未换镜 |
| 输出尺寸 | 1 种 |
| 回读帧时长 | 1 个值 |
| **会话新鲜度** | **3/3 轮首帧回到掉电默认（超焦距 0.09071941 diopt）并重新移动** ⇒ 每轮确是独立 `openCamera` |
| **逐轮帧完整性** | **r1 有 1 处帧缺口** ⇒ 该轮判废 |

**两个必须写死的限制**：

1. **回读值很可能只是"请求量化后回显"，不是实测位置。** HAL 的距离量化单位实测正好是
   **1 mm**：回读 `1.001001` diopt ⟺ `999.0000 mm`；`0.09071941` diopt ⟺ `11023 mm`。
   所以 G21 证明的是"请求的落点确定且可复现"，**证明不了镜片物理上停在同一处**。
2. 因此 **内参是否真的不变，最终只能靠 M1 做两次独立标定比对 fx**。M0 无法回答这个问题。

**仍然完全没有仪器的漂移源：热漂移。** G13 用电池温度、在 4.8 s 窗口内 delta=0，零信息量。
本轮唯一的免费（但很弱）对照：② 那一轮在 37.4 °C、③ 的三轮在 34.6 °C 下跑，
**差 2.8 °C 而所有回读值完全相同** —— 只能说明"这一档温差看不出来"，不能推广。

## 二、四处纠正与新发现

### 1. G21 的 PASS 是假的（本轮最重要）

上一轮刚上线的 G21 只查"焦点 / 物理镜头 / 输出尺寸 / 帧时长"，于是
**给它自己那三轮里丢了帧的 r1 判了 PASS**。r1 的 149 个间隔里有一个
`66575833 ns = 2× 名义值`（间隔序号 5，正好在预热边界），该轮总跨度比 r2/r3 多整整一个帧周期。

**⇒ 判据看不见自己所依赖数据的完整性，就会把坏数据当成好证据用。**
这类失效尤其阴险：它伪装成"这一项判过了"，而实际上这一项的证据是坏的。

已把 G21 扩成四层：① 证据在不在；② **每轮帧完整性**；③ **"跨会话"是否被证明**（首帧指纹）；④ 落点重复性。

**附带一个必须分清的处置差异**：帧缺口 ≠ 漂移。若不做缺口检测，那个 2× 值会把回归斜率
拉成 **−37048 ppm**，报告会把它说成"时间戳存在漂移"——**结论方向就错了**。
缺口是"采样序列里有个洞"（时间戳仍诚实，处置＝弃用该轮）；漂移是"节奏本身在变"（只能逐帧用时间戳）。

### 2. "量化到 HAL 可达网格"这个说法是错的（名字错了，不是方向错了）

上一轮把"回读值系统性偏低 0.12%"解释为量化到网格。本轮把 4 档原始比值算出来：

| 请求 | 回读 | 回读/请求 |
|---|---|---|
| 12 fps | 83 231 987 ns | 0.99878385 |
| 15 fps | 66 575 990 ns | 0.99863986 |
| 24 fps | 41 615 993 ns | 0.99878385 |
| 60 fps | 33 287 995 ns（回落） | — |

三点否掉"网格"：偏差**全部为负**（同一步长取整应正负随机）；`gcd(三个回读值) = 1`（无公共步长）；
比值不是常数，档间差 **144 ppm**。

正确说法只能到："请求被采纳，回读值按 HAL 自己的时间单位重新表达，系统性偏低 0.12%~0.14%，
偏置量随档位微变。"机制（分频？换算？）4 个点定不下来 —— 也**不需要**定，
因为实测帧间隔与回读值一致到 0.124 ppm，回读值就是物理事实本身。

**教训：给现象起名要克制。** "量化到网格"听着专业但当时没有证据，
它把"未知的固定偏置"包装成"已理解的行为"，从而挡掉了后续追问。

### 3. 输出几何：根因定位，且**是"选错了"不是"选亏了"**

`output 1920×1080 (纵横比 1.7778)` vs `crop 4096×3072 (纵横比 1.3333)`：
`scale_x = 0.46875` 而 `scale_y = 0.35156` ⇒ `fy/fx = 0.75` ⇒ 预测 `fx = 1282.5 px`、`fy = 961.9 px`。

读源码找到根因，两处：

```kotlin
// 旧 pickCaptureSize：上限恰好等于 1920×1080 的面积 ⇒ 必然选中这个 16:9 档
val cap = 1920L * 1080L
sorted.firstOrNull { 面积 <= cap }     // 1920×1080 面积 == cap，是满足条件里最大的
```

```kotlin
// 旧 buildRequest：主动要求把整个 4:3 活动阵列映射到 16:9 输出
b.set(CaptureRequest.SCALER_CROP_REGION, active)
```

`SCALER_CROP_REGION` 的语义是"把这块区域映射到输出"，纵横比不一致时映射就是各向异性的。
**这不是精度打折，是内参模型的前提（方形像元）被换掉了** —— 而标定照常收敛、程序不报错。

已修：① 选尺寸优先同纵横比（上限提到 2048×1536）② 新增 `aspectSafeCrop` 把 crop 收紧成
同纵横比居中矩形 ③ 新增判据 **G22** 直接检查并给出应设数值（本例 `(0, 384, 4096, 2304)`）。

### 4. 新增判据 G20 缺口检测 + G22 输出几何

| 判据 | 变化 |
|---|---|
| **G20** | 主判据从"抖动 ppm"改为**累积漂移**；显式区分**帧缺口**与**漂移**；报出周期结构 |
| **G21** | 扩成四层（见上） |
| **G22** | **全新**：crop 与输出纵横比必须一致。判据设计教训：要覆盖的不只是"参数值"和"数据质量"，还有**模型前提** —— 前两类失效都会留下可见痕迹，模型前提被换掉什么都不留下 |

## 四、下一步

按性价比排序：

1. **改档后重跑 ①②④**（必做）
   新尺寸 2048×1536（4:3）下重测：尺寸候选清单、锁定稳定性、**实际可达帧率**。
   面积比 1920×1080 涨 52%，30.04 fps 的上限大概率保不住 —— 这正是要测的。
   若保不住，回到 1920×1080 + `aspectSafeCrop` 的补救路径（G22 已验证可行）。
2. **长时热漂移测试（≥5 min）**（必做，"内参不变"目前唯一无仪器的漂移源）
   用图像本身当温度计：固定靶标、固定参数，每 10 s 存一帧，跟踪靶标像素坐标与
   已知尺度的比值随电池温度的变化。G13 的电池温度在 4.8 s 窗口内零信息量。
3. **M1 两次独立标定比对 fx**（"内参不变"的最终答案，M0 无法替代）
   这是唯一能证明"回读值相同 ⇒ 镜片物理位置相同"的方法。
4. **重跑 ③ 补上被丢帧污染的那一轮**
   采集协议已要求逐帧校验间隔；正式采数时把"该轮是否完整"作为准入门槛。

判定：本轮为 `WARN`（G18 上限、G21 含缺口轮、G22 几何不自洽）。
**不是退步** —— 上一轮 G21 的 PASS 是假的，这一轮的 WARN 是真的。
