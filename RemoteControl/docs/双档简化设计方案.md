## 0. 一句话结论

把现有 **5 个编译形态**（[1]~[4] + 比赛档）压成 **2 个**：

| 档 | 宏 | 说明 |
|---|---|---|
| **远程档** | `#define MOUSE_REMOTE 1` | 上位机全程接管：监视 + 参数读写 + 手动运动 + 远程发车/收车 |
| **按键比赛档** | 不定义任何宏 | 与现状比赛固件**逐字节一致** |

课程实验层（`APP/lesson_lab.c/h` + `LESSON` 命令 + 课程 14 个参数 + Flash page 116 + 上位机 `host.lesson`）**整层删除**；远程档 = 把现有 [2] 的远程运动、[3] 的参数读写、[4] 的远程发车与监视**合并为一档**；发车目标只剩两个：**实验8（无记忆走迷宫）** 与 **正式比赛入口序列**。

## 1. 两处关键事实（本方案据此大幅收窄改动面）

这两条都是本轮读代码核实的结果，直接决定了"哪些功能需要新增、哪些本来就有"：

### 1.1 参数读写**本来就不受档位门控** —— 不需要新增任何东西

`link_HandleLine()` 里 `GET` / `GET ALL` / `SETQ` / `SET` / `SAVE` / `RESET` 的命令体**全部在 `#ifdef` 之外**（`link.c:2073 / 2115 / 2135 / 2222 / 2245`）。被门控的只有三处：

- `link_NameToId()` 里课程参数名（`KPL`…`WALLMODE`）的名字表 → `#ifdef MOUSE_LESSON_LAB`
- `link_ParamSet()` 里课程参数表的回退分支 → `#ifdef MOUSE_LESSON_LAB`
- `SAVE` 里写 page 116 → `#ifdef MOUSE_LESSON_LAB`

⇒ **生产参数表（24 项 id 1–7 + 22–38，Flash page 115）的读写在任何档、任何时刻都可用**，包括现在的比赛档。你要的"不发车时允许进行参数读写"**已经成立**，删掉课程层不会损失任何参数能力 —— 只会少掉 14 个**在自走路径里没人读**的参数（见 1.2）。

### 1.2 课程 14 个参数在远程档里是**死参数**

逐个追踪消费者：

| 参数 | 变量 | 消费者 | 在自走路径里 |
|---|---|---|---|
| `KPL…KDR`（6 个） | `lessonGain.*` | **仅** `motor.c` 的 `#ifdef MOUSE_LESSON_LAB` 分支 | 删掉课程层后**无任何消费者** |
| `IRPL/IRPR/GYROP/GYROD` | `lessonStr.irLeftP…` | `LESSON_ISR()`（`lesson.c:41`） | `LESSON_ISR` 只在 `lessonStr.isTest` 置位时动作，而 `isTest=1` **只出现在 `LESSON_Motor1/Enc2/Pid3/Irs4/Cali5/Multi6/Turn7` 里**，这些函数在 `main.c` 全部被注释 ⇒ 比赛档里空转 |
| `SPEEDNEED/ALLDIS/SENSORMODE/WALLMODE` | `lessonStr.speedNeed…` | 同上 | 同上 |

⇒ 这 14 个参数**只服务课件实验剖面**，与 `LESSON_Blind8()` 和比赛冲刺流程**零关系**（已 grep 确认 `LESSON_Blind8()` 函数体内不出现 `spurtFlag / goaheadnum / spurtmode`）。删掉它们**不损失任何远程调试能力**。

若要"远程可调 PID"，那是一项**新能力**（现有架构里 PID 是红线段常量 `MOTOR_KP_L` 等，只在课程档下被覆盖），本方案不做 —— 见 §6 待拍板。

## 2. 目标形态

### 2.1 两档的能力对照

| 能力 | 远程档 `MOUSE_REMOTE` | 按键比赛档（不定义） |
|---|---|---|
| 统一帧遥测（49 通道） | ✅ | ✅（现状就有） |
| `PING` / `TELEM` | ✅ | ✅ |
| 参数读写 `GET`/`SETQ`/`SET`/`SAVE`/`RESET`（生产 24 项） | ✅ | ✅（现状就有，1.1 已证） |
| 手动运动 `MOVE FWD` / `MOVE ROT` / `MOVE RUN`（双护栏） | ✅ | ✅（现状就有） |
| 远程标定 `CAL` / `TARE` | ✅ | ✅ |
| 地图读取 `MAP DUMP` | ✅ | ✅ |
| 急停 `ESTOP` / 解锁 `STOP` | ✅ 可恢复、不休眠 | 原语义：200ms 后休眠 |
| 远程软复位 `MCU RESET` | ✅ | ❌ 不编译（比赛规则要求人工在场） |
| 远程发车 `MAZE RUN` | ✅ | ❌ 回 `ERR_VALUE` |
| 退出迷宫 `MAZE STOP` | ✅ | ❌ |
| 按键菜单 `MENU_Run` | ❌ 跳过 | ✅ 长按 4 秒进入 |
| 自走策略 `doTask*` / `LESSON_ISR` | ✅ 编译并运行 | ✅ |
| 课程实验 `LESSON START` | ❌ 删除 | ❌ 删除 |
| `STATE_SpurtTest` / `STATE_MainLoop` | ❌ 不调用（理由见 §2.3） | ✅ 编译（但在 [5] 里不可达） |
| 电机物理禁用 | ❌ 无此档（**能力损失，见 §6.1**） | ❌ |

### 2.2 远程档的三个工作阶段

```
上电
  └─ 值守态（不发车）────────────────────────────────────────
     · 遥测持续上行（TELEM 拉取）
     · 参数读写 / 标定 / MAP DUMP 全部可用
     · MOVE RUN 可手动转轮子（时间 + 红外双护栏）
     · ESTOP 锁存 / STOP 解锁
  └─ 收到 MAZE RUN [target] ────────────────────────────────
     · target = BLIND（默认）→ 实验8：无记忆走迷宫
     · target = RACE        → 正式比赛入口序列 + 无记忆走迷宫
  └─ 收车（MAZE STOP / ESTOP / MCU RESET）→ 回值守态
     · 外层 while(1) 使"发车 → 收车 → 再发车"不必断电
```

### 2.3 发车目标只有两个

| 目标 | 命令 | 执行内容 |
|---|---|---|
| **实验8** | `MAZE RUN` 或 `MAZE RUN BLIND` | `MOTION_SetAngle(0)` → `taskSt.backSearch=1` → `LESSON_Blind8()` |
| **正式比赛** | `MAZE RUN RACE` | 上面再加上比赛入口序列：`STATE_LoadMapAndSelectSpeed()`（含缺省冲刺档）→ `STATE_DetermineGoaheadNum()`（含缺省 `goaheadnum`）→ `MOTION_SetAngle(0)` → `taskSt.backSearch=1` → `LESSON_Blind8()` |

**两者在 `LESSON_Blind8()` 之后合流**，这是源码事实，不是设计选择：

- `LESSON_Blind8()` 不读 `spurtFlag` / `goaheadnum` / `spurtmode`（已 grep 确认）；
- 读它们的只有 `STATE_MazeSearch()` 与 `STATE_MainLoop()`，而 `STATE_MainLoop()` 在比赛固件里**不可达**（`LESSON_Blind8()` 是 `while(1)`，[5] 档编译后没有任何出口，见 `docs/` 上一轮的可行性分析）。

⇒ **RACE 与 BLIND 的实际走法相同**；RACE 的增量价值是：让比赛入口序列真实跑一遍，于是 `mouseTask` / `spurtmode` / `spurtSpd` / `goaheadnum` / `taskSt.spurtFlag` 这些量被真实赋值 —— 而它们**现在全都在统一帧里可见**（v2.3.0 已加）。也就是说 RACE 的用途是**"在遥测里验证比赛会选成什么样"**，不是"走出不同的路线"。

**为什么 RACE 不接 `STATE_SpurtTest()` / `STATE_MainLoop()`**：
它们在比赛固件里是死代码（不可达）。远程档若接上去，等于**运行比赛从不执行的代码**，比不接更不忠实；而且两者都是纯 `while(1)`，进去之后只能靠 `MCU RESET` 出来。故 RACE 同样到 `LESSON_Blind8()` 为止。若将来确要验冲刺状态机，再单独加一个显式开关（本方案不做）。

### 3.4 "不动比赛代码"如何被证明

上面每一处删除/替换，在 **`MOUSE_REMOTE` 未定义** 时的预处理结果都与现状比赛档**完全相同**（逐处对照）：

| 站点 | 为什么比赛档产物不变 |
|---|---|
| 删 `MOUSE_TEST_NO_MOTOR` 分支 | 比赛档从未定义它 ⇒ 走的一直是 `#else`（保留） |
| 删 `MOUSE_LESSON_LAB` 分支 | 同上（保留 `#else` = 红线段常量） |
| 删 `MOUSE_TEST_MODE` 分支 | 同上（保留 `#else` = `doTask*` switch） |
| `#ifndef MOUSE_TEST_MODE → LESSON_ISR()` 变无条件 | 比赛档 `MOUSE_TEST_MODE` 未定义 ⇒ 原本就编译 `LESSON_ISR()` |
| `MOUSE_ESTOP_RECOVERABLE / MOUSE_DATA_LOG` → `MOUSE_REMOTE` | 比赛档两个旧宏都未定义、`MOUSE_REMOTE` 也未定义 ⇒ 条件同假 |
| `main.h` 只留一行 `#define MOUSE_REMOTE 1` | 比赛档改成注释掉即可 |

⇒ **验证方式**：改动前后各编一次"不定义任何宏"的固件，比对 `Mouse.axf` / `.hex` 与 ROM 大小。预期 **ROM 仍为 91120 B**（v2.3.0 的实际值），字节完全相同。这比"剥离注释后逐文件比对"更强。

## 6. 待拍板

### 6.1 ⚠️ 会损失一个安全能力：不再有"电机绝不可能动"的固件

现状 [1] 安全测试模式的价值是：**链路调试/红外标定时，可以保证车在任何情况下都不会动**（PWM 不启用 + 输出恒 0 + 状态机不编译，三重）。压成两档后，远程档虽然值守态 `freemode=1`（不动），但 `MOVE RUN` 能转轮子 —— **再也没有"绝对不动"这一档**。

- **建议**：接受。理由是远程档的护栏已足够（`MOVE RUN` 时间 + 红外双护栏、`ESTOP` 锁存、值守态默认不动），且真机标定一般会架起轮子。
- 若你希望保留：加一个可选宏 `MOUSE_REMOTE_LOCK`（定义 = 在远程档基础上把 `MOTOR_LoopControl()` 强制置 0），相当于把 [1] 变成远程档的一个子开关，**仍是两档**（只是多了个正交开关）。请选其一。

### 6.2 缺省冲刺档的来源

§3.3(b) 推荐 **编译期常量**（零新命令、零 Flash 改动、行为可复现）。另一个选择是：把这三个值做成**可 SETQ 的参数**，落在删空出来的 **page 116**（不碰 page 115，因此**现有标定不失效**）—— 这样远程能试不同的冲刺档而不用重编。

- 触发条件：如果你希望在真机上"用不同冲刺档跑 RACE"做对照实验，选后者；否则前者足够。
- 注意：**绝不能把它们塞进生产参数表**（`LINK_P_NUM` 24 一旦改变，`link_CalibLoad()` 会因为 `cnt != LINK_P_NUM` 判定 page 115 失效 ⇒ 现有标定全部作废，需重新标定）。

### 6.3 上位机纯算参函数是否保留

§4 的"迁"一行。若你认为课程实验既然不要了、算参工具也一并删，请明示 —— 我会把 `api/lesson.py` **整个删除**而不是迁移。

### 6.4 一个已知行为，本方案**不改**

`STATE_MazeSearch()` 会在内部把 `mouseTask` 置成 `SPURT`（`state.c:561/570/604/711`），而 `LESSON_Blind8()` 的 `switch` **没有 SPURT 分支** ⇒ 落到 `default: break;` **空转、车不动**。这很可能是现场"电脑鼠卡住但链路完全正常"的一个候选解释。远程档下这个状态**在遥测里可辨**（`mazeTask=SPURT` 而 `motionTask=NULL` 且帧内容不变化），但它是**原有比赛代码的行为**，本方案不动；要不要修，另立议题。

### 6.5 `MAZE RUN RACE` 的协议版本

`MAZE RUN` 加一个**可选**动作词，帧格式未变；老上位机发 `MAZE RUN` 在新固件上仍是 BLIND，新上位机发 `MAZE RUN RACE` 在老固件上会被当成 `MAZE RUN`（静默按 BLIND 跑）。本方案建议 **`PROTO` 4 → 5**，让上位机能用 `device.proto >= 5` 判断"该固件是否支持 RACE"，与 v2.1 的处理一致。若你认为不必，可只升 `FW`。
