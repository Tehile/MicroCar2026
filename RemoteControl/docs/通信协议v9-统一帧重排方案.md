# 通信协议 v9：统一帧重排方案（49 B → 30 B）

> 状态：**已落地（2026-10-20）**。协议实现见 [`通信协议规格.md`](通信协议规格.md) §3.3/§3.4；
> `LINK_PROTO_VER` 8 → **9**，`LINK_FW_VER` 300 → **310**，host API 2.11.0 → **2.12.0**。
> 适用范围：`code_competition` 远程档。
> 原则：**帧里只留"每帧会变的动态量"**；静态规划结果走事件/参数表，本地健康计数走低频诊断通道。

## 1. 三个必须先拍板的设计点

### 1.1 `状态B` 一字节装不下，必须拆成 B0/B1

你要求「46 的 bit3(3)、bit4(4) 给 B，B 的 bit7 去掉」。算一下位数：

```
motionTask 0..107  →  7 bit
spurtFlag          →  1 bit
goOrBack           →  1 bit
合计               →  9 bit  >  8 bit
```

去掉 `irSwitch` 只腾出 1 位，还差 1 位。**只能扩字节**，所以 `状态B` 定为 **2 字节（B0/B1）**。
（若强行守 1 字节，只能把 `motionTask` 压到 6 bit，代价是丢掉 64..107 的冲刺动作码 —— 不可接受。）

### 1.2 `45 前墙档` 整个字节可以删，前墙信息无损迁进 C

原 45 的三位里，`frontNear` 与 `frontFar` **互斥且穷尽**（固件组帧时用 `min(f1,f2) < thrFrontNear` 二选一），
恒等式 `frontNear | frontFar == wallFront`。所以：

```
near = wallFront & !frontFar     ← 完全可推导
```

你要的「前墙增加 1 bit 判断是否为远墙」= `frontFar`。把它和 `wallFront` 放进同一字节 C，前墙三档信息
（有墙 / 近 / 远 / 双路互证）**一位不丢**，45 整字节删除。这不是"新增位"，是"归位"。

### 1.3 两处建议零成本保留（不额外占字节，只占空位）

| 删掉的位 | 代价 | 建议 |
|---|---|---|
| `状态B.bit7 irSwitch` | 「高速段关红外」从此没有帧内信号（`timer.c:478`，为 0 时跳过 `getdistance()`） | 复用 `flags` 的 `0x10`（原 `DUMPING` 早已恒 0）→ **`flags.0x10 = IR_SWITCH`** |
| `45.bit2 frontBoth` | 双传感器交叉验证位，**唯一不可由其他位推导**的前墙信息 | 放 `状态C.bit4`（C 有空位，白给） |

若认为这两个都不需要，C 的 bit4 与 flags 的 0x10 留 0 即可，布局不变。

## 3. 位打包明细

### 3.1 状态A（偏移 23）—— 身份 + 战略层

```
bit0-1  dir              0=UP 1=RIGHT 2=DOWN 3=LEFT
bit2-4  mazeTask         0=WAIT 1=START 2=SEARCH 3=SPURT 4=SPURT45 5=SPURT90 6=END
bit5    objectGoToFlag   1=正在按坐标回调（原 46.bit6）
bit6-7  预留
```

> 3 bit 装 `mazeTask`，最大可表达 7；当前用到 6（`END`，`stratagy.h` 新增值）。

### 3.2 状态B0（偏移 24）—— 执行层

```
bit0-6  motionTask       0..107，见 host/protocol/codec.py MOTION_TASK_NAMES
bit7    预留            （原 irSwitch，已迁至 flags.0x10）
```

### 3.3 状态B1（偏移 25）—— 冲刺控制布尔

```
bit0    spurtFlag        1=冲刺阶段已启动（原 46.bit3）
bit1    goOrBack         1=返程 / 0=去程（原 46.bit4）
bit2-5  led1..led4       1=LED 亮（v9.1 起占用，见《LED状态上报-B1位分配方案》）
bit6-7  预留
```

### 3.4 状态C（偏移 26）—— 墙位（含前墙远近）

```
bit0    wallLeft         1=有墙（原 状态A.bit5）
bit1    wallFront        1=有墙（原 状态A.bit6）
bit2    wallRight        1=有墙（原 状态A.bit7）
bit3    frontFar         1=远墙档 / 0=近墙档（仅 wallFront=1 时有效；原 45.bit1）
bit4    frontBoth        1=双路交叉验证触发（原 45.bit2，可选保留）
bit5-7  预留
```

推导关系（下游可直接用）：
```
frontNear = wallFront & !frontFar
frontFar  →  wallFront 必为 1（组帧时保证）
```

### 3.5 flags（偏移 27）

| 位 | 名称 | 含义 | 相对旧版 |
|---|---|---|---|
| 0x01 | `FREEMODE` | `freemode==1`，电机输出强制 0 | 不变 |
| 0x02 | `SLEEP` | 休眠 | 不变 |
| 0x04 | `EMERG` | 急停生效过 | 不变 |
| 0x08 | `PULLF1` | 本帧 = 本批 `RATE PULL` 的首帧 | 不变 |
| 0x10 | **`IR_SWITCH`** | 红外采样轮在跑（`irswitch==1`） | **新增**（复用原 `DUMPING` 恒 0 位） |
| 0x20 | — | 释放 | 删（原 `MOTOR_OFF` 无发送方） |
| 0x40 | `ESTOP_LOCK` | 急停锁存，新 MOVE/CAL 被拒 | 不变 |
| 0x80 | `EVQ` | 事件行被丢弃，事件流不完整 | 不变 |

### 3.6 冲刺上下文（偏移 29）

```
bit0-2  spurtMode      0=未选 1=LOW_90 2=LOW 3=MEDIUM 4=HIGH（固件 60..63）
bit3    spurtTestFlag  1=冲刺测试模式（test_spurt90 调参路径；原 46.bit5）
bit4-7  goaheadnum     冲刺前行格数 0..15（原独立字节 47）
```

> `spurtMode` 的线上名沿用旧表：`2=LOW`（固件 `LOW`=61）在旧文档里写作 `45_LOW`，是"用于 45° 冲刺路径的 LOW 档"，
> 不是独立档位。v9 起统一写作 `LOW`，映射表 `codec.SPURT_MODE_NAMES` 同步。

## 6. 删掉的三类数据，去哪了

| 数据 | 理由 | 新去处 |
|---|---|---|
| `fastwayCount` / `fastwayCount90` | **静态规划结果**，一次冲刺内恒定，217 Hz 重复传常量熵为零 | 规划完成时（find 结束）由 **ACK 附加字段**回一次，或新增一行事件 `PATHPLAN n=<c> n90=<c90>` |
| `dropCnt` | 统计的是 **TX 环写失败次数**（非帧数、u8 回绕），且帧丢了它一起丢，自证失败；停等模型下主机已能用 `seq_gap`/`bad_crc`/缺帧等价判定 | `PING` 应答或 `GET ALL` 文本里的低频诊断项 |
| `irAdc[4]` | 原始 ADC 只在红外标定时用 | 标定走 `IRDATA` 闪存 + 参数表，不需要逐帧上行 |

## 9. 代价（明确记录，不劝阻）

| 删除字段 | 失去的能力 |
|---|---|
| `motionStep` | 帧内看不到"当前是动作序列第几步"，冲刺卡死只能靠 `motionTask` + 事件流定位 |
| `critL` / `critR`（<60 mm） | 丢"临界贴墙"即时信号，贴墙调参失去帧内依据 |
| `left45` / `right45`（<150 mm） | 丢"斜墙"宽阈值判据，45° 场景排查变难 |
| `pidErr` | 丢调参核心信号（原本每帧可看误差波形） |
| `irAdc[4]` | 丢原始光强，红外二次标定须读闪存 |
| `wallThresh` | 丢"当时用的是哪个侧墙阈值"，无法解释"为什么这里没判到墙" |

若后续发现其中某项必需，正确做法是**新增按需请求命令**（如 `GET TRACE`，一次性回一段），而不是塞回每帧。
