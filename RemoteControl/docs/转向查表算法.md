# 转向/掉头的查表机制（code_competition）

> 结论先行：本工程所有"带角度"的动作都是 **时间参数化的三段式轨迹回放**——
> `turn_gyro[]`（航向参考）+ `turn_vl[]/turn_vr[]`（左右轮前馈速度），
> 由 1 kHz `SysTick` 按全局 `tick` 索引查表，前馈 + 角度 PD 修正；
> 前台（`utility.c`）只负责装表和阻塞等待。
> **表是录制/拟合出来的开环轨迹，没有任何"到位/超时/被挡"的事件能提前终止它。**

## 一、查表清单

### 1.1 生效的四组表

| 组 | 数组（每个动作 3 个） | 长度 | 定义处 | 消费模式 |
|---|---|---|---|---|
| A 探索 90° | `gyro_l_search` / `gyro_r_search` / `vinner_search` / `vouter_search` | 195 | `USER/user.c:54-57` | `LT90SEARCH` / `RT90SEARCH` |
| B 掉头 180° | `gyro_around` / `vl_around` / `vr_around` | 628 | `USER/user.c:60-62` | `TURNAROUND` |
| C 定点 90° | `gyro_l_point` / `gyro_r_point` / `vouter_point` / `vinner_point` | 232 | `USER/user.c:65-68` | `POINTL90` / `POINTR90` |
| D 竞速 45/90/135/180 | `gyro_lt90_low`…`gyro_rv135_low`、`vouter/vinner_*_low`、`*_180_low` | 152/171/187/195/294/302/391 | `UTILITY/utility.c:241-348`（`#ifdef LOW_ENABLE`，该宏在 `utility.c:71` 已定义） | `LT90L`…`R180L` |

每组三支表的分工完全一致：

- `gyro_*`：**剩余转角参考**（单位 °）。左转 `90 → 0`（表尾 −3，右转 `−90 → +3`），180° 表 `−180 → 0`。
- `vouter_* / vinner_*`：**外/内轮速度前馈**（与 `speed_ss` 同量纲）。90° 表轮廓是梯形：70 → 109（外）/31（内）→ 保持 → 回落 70，差速约 78 ⇒ 恒角速度旋转。
- 表长 = 播放毫秒数（1 项 = 1 ms）。

## 二、统一执行器

### 2.1 装表前的两个状态重置

```c
// utility.c:500
void settrack(int t) { basetrack = absolutetrack - t; track = t; }
// utility.c:506
void setangle(int a){ ganglet = -a*gangleratio*(-1); baseangle = absoluteangle + a; }
```

- `settrack(0)`：把**里程原点和累计量**都清零，后续 `track` 从 0 起算。
- `setangle(±deg)`：把**航向基准**移到"转完之后应处的朝向"，同时把陀螺积分量 `ganglet` 预置成 `a*gangleratio`。
  于是 `gangle = ganglet/gangleratio*(-1)` 在转向开始时正好等于参考表首项（左转 +90、右转 −90、掉头 −180）。
  **这是整张表能"从表头对齐"的唯一原因。**

### 2.2 1 kHz 主控（`timer.c`）

```c
const short *turn_gyro,*turn_vl,*turn_vr;   // timer.c:116  三个裸指针，切换模式即换表
double turn_kp=4, turn_kd=4;                // timer.c:61   默认；spurt 档另设 4/2、8/5、10/7

case TURN:                                  // timer.c:606
    setgangle = *(turn_gyro+tick);
    eh = e;
    e  = gangle - setgangle;                // 航向残差(°)
    tick++;
    setvl = *(turn_vl+tick) - e*turn_kp - (e-eh)*turn_kd;
    setvr = *(turn_vr+tick) + e*turn_kp + (e-eh)*turn_kd;
    break;
```

- 前馈 = 表值，反馈 = 角度 PD（左右反号）。
- `setvl/setvr` 之后还过一层**轮速 PI**（`timer.c:1165-1228`，`kpl=3,kil=2,kdl=0.1` 或 spurt 档 `13/0.7/0.8`）→ PWM。即"角度环外环 + 轮速环内环"，表中给的是内环给定。
- 注意索引差：`TURN` **先取值后自增**（索引 0 起），`TURNAROUND/POINTTURN90` **先自增后取值**（索引 1 起）。

### 2.3 两种收尾风格

**① 整表播完（`TURN`）** —— `taskturn()`，`utility.c:570-685`

```c
task = TURN;
while(tick < length/2 - 2);   // 唯一的退出条件
settrack(0);
```

`length` 被逐条手工裁剪过（`-8 / -4 / -16 / -14 / +8`），实际播放窗口：

| 模式 | 裁剪 | 播放 ms | 模式 | 裁剪 | 播放 ms |
|---|---|---|---|---|---|
| LT90SPURT/RT90SPURT | `sizeof` | **0** | LV45L / RV45L | `-14` / `-8` | 162 / 165 |
| LT90SEARCH / RT90SEARCH | `-8` / `-` | 189 / 193 | LT135L / RT135L | `-` | 300 |
| POINTL90 / POINTR90 | `-2` / `-` | 229 / 230 | LV135L / RV135L | `-` / `+8` | 292 / **296†** |
| LT90L / RT90L | `-16` / `-4` | 185 / 191 | L180L / R180L | `-` | 389 |
| LV90L / RV90L | `-` | 185 | | | |
| LT45L / RT45L | `-` | 150 | | | |

† `gyro_rv135_low[294]`，但判据是 `(588+8)/2-2 = 296` ⇒ `tick` 会走到 295，**越界读 2 项**。

**② 表只做起转，剩下靠 P 收口（`TURNAROUND` / `POINTTURN90`）** —— `timer.c:617-668`

```c
case TURNAROUND:                     // 掉头
  if(step==0){ tick++; setgangle=*(turn_gyro+tick);
      setvl = vl[tick] - e*2.5 - esum*0.01 - (e-eh)*0.1;
      setvr = vr[tick] + e*2.5 + esum*0.01 + (e-eh)*0.1;
      if(tick>200){ step=1; tick=0; } }        // 只播 200/628
  else { e=gangle; setvl=-e*2.5-(e-eh)*0.1; setvr=e*2.5+(e-eh)*0.1;
      if(|speedl|,|speedr|<2) tick++; else tick=0; }

case POINTTURN90:                    // 定点 90°
  if(step==0){ ... 同一形式 ...
      if(tick>30){ step=1; tick=0; } }         // 只播 30/232（注释里写着 "//230"，被改成 30）
  else { e=gangle; setvl=-e*1; setvr=e*1;
      if(|speedl|,|speedr|<10) tick++; else tick=0; }
```

- 掉头：`vl_around=+20 / vr_around=−20` 是**反相**的，即真·原地自旋；200 ms 时参考走到 −124°，剩余 124° 由 `e=gangle` 的 P（增益 2.5，饱和在 350 PWM）直接甩过去。
- 定点转：`vouter_point=+30 / vinner_point=−30`，30 ms 只转了约 7°，其余 83° 由增益 1 的 P 慢慢磨到 0。
- 前台的 `while(1) if(step==1 && tick>30/10) break;` 其实是在等**"连续静止 30 ms / 10 ms"**，不是等角度。

> 结论：同一个 `TURN` 任务名下有两种语义——A/D 组是"轨迹跟踪"，B/C 组是"轨迹起转 + 角度 P 收敛"。

## 三、五类动作的调用链与前/后动作

### 3.1 探索期 90° 转弯（SEARCH 表）

**调用链**：`mazeSearch()`（`utility.c:744`）→ 每格 180 mm 到点 → `mazesearchhaswall()/mazesearchnowall()` → `stratagy.c:405/413` 的 `switch(cDirTemp)` 与 `stratagy.c:541-602` 的 `rightHandMethod/leftMethod` 等选址策略 → `mouseTurnright()/mouseTurnleft()`（`utility.c:1024/1052`）。

**前动作** `before90turn(Direction)`（`utility.c:835-918`）：
- `task=BEFORE90TURN`：以 `speed_turn=30` 匀速前进；**前有墙**用 `disf2-disf1` 做横向对齐（保证垂直入射），**无前墙**用 `gangle` 保直（`timer.c:671-684`）。
- 按 `LastSearchAction`（上一次是直行 / 左转 / 右转 / 掉头）与 `turn_delay`（探索期 9，竞速期 0）算出一个**过冲量**，凑够 `track >= turn_delay±k` 就停表：
  ```c
  if(LastSearchAction==Stright)  left: turn_delay-2   right: turn_delay-3
  if(LastSearchAction==TurnLeft) left: turn_delay     right: turn_delay-5
  if(LastSearchAction==TurnRight)left: turn_delay-4   right: turn_delay-1
  if(LastSearchAction==TURN180)  left: turn_delay+27  right: turn_delay+20
  ```
  这一步的本质是**把旋转中心摆到格心**，因为表是按固定起点录的。
- 同时算侧向偏差：`turnrighto = dis2wall - mean(disl,dislh,dislhh)`，`turno = mean(disr,disrh,disrhh) - dis2wall`。
- 保护：`if(disr<50)`（右转）或 `if(disl<50)`（左转）——太贴墙就 `task=NULL; sleepmode=1` 死等闪灯，不出表。

**后动作**（`mouseTurnright` 结尾）：

```c
taskturn(RT90SEARCH);
task = SMARTSTRAIGHT;               // 立刻让位给直行
GucMouseDir = (GucMouseDir+1)%4;    // 地图朝向 +1
settrack(180 - turnrighto);         // 里程计重定标：下一格还剩 (180-o) mm
```

- **不刹车、不等静止**：表播完立刻切直行，残余角速度/角差由 `SMARTSTRAIGHT` 的 `e=gangle` 闭环吸收（`timer.c:801`）。所以"转向精度"实际上是**转向表 + 下一段直行**共同决定的。
- `settrack(180-turnrighto)` 把"因贴墙偏差多走/少走的那几毫米"折进下一格的 180 mm 里。
- `turno` 只写不读（`utility.c:24` 定义，`timer.c` 从不引用）——**死变量**，V 型斜穿之外的横向补偿已废弃。

### 3.2 竞速复合转向 45/90/135/180（LOW 表）

**调用链**：`test.c:1205 spurt(LOW)` → `actiongenerate(LOW)`（`utility.c:1553-1673`，把 `FastwayAction[]` 压缩成 `actionsequence[]`）→ `action(LOW)`（`1676-1829`）→ 非直行元素走 `mouseturn(pattern)`。

`actiongenerate` 的压缩规则（`utility.c:1572-1585`）：

| 原始动作序列（1=右,7=左,2/6=?,0=直,`getsum(i)%2`=已累计转角奇偶） | 压缩成 |
|---|---|
| 1,2,1 且偶 | `R180L` |
| 2,1 且奇 / 6,7 且奇 | `RV135L` / `LV135L` |
| 1,2 且偶 / 7,6 且偶 | `RT135L` / `LT135L` |
| 7,7 偶 / 1,1 偶 | `LT90L` / `RT90L` |
| 2 奇 / 6 奇 | `RV90L` / `LV90L` |
| 1 偶 / 7 偶 | `RT45L` / `LT45L` |
| 1 奇 / 7 奇 | `RV45L` / `LV45L` |
| 0 偶 / 0 奇 | `STRAIGHT90L` / `STRAIGHT45L`（`taskstraight90/45`，不查表） |

**前动作** `beforemouseturn(pattern)`（`utility.c:1402-1515`）：
- 按 pattern 查一个固定的**切点距离** `beforeturntrack`：`LV45L/RV45L=3`、`LV90L/RV90L=7`、`LV135L/RV135L=0`、`LT90L=60`、`RT90L=65`、`LT135L/RT135L=14/13`、`LT45L/RT45L=0`、`L/R180L=0`。竞速期 `turn_delay=0`，所以不再用转身延迟，改为**绝对毫米数**。
- 三种切点判据：
  - `BFL/BFR`：`SPURT90IR/SPURT90BLIND` 沿侧墙跑到 `lefthaswallh==1 && lefthaswall==0`（**出墙沿**）再补偿 `beforeturntrack`；
  - `BFLV/BFRV`：`STRAIGHT45` 跑到 `leftwallcriticalhhh==1 && hh==1 && h==1 && 当前==0`（**三拍历史 + 当前跃变**），用于 V 形 45° 斜穿；
  - 45° 两档额外把 `sidewall_threshold` 从 130/160 改成 110，让侧墙判定更近。
- 起点被"钉"到几何切点后，才允许进表——**表本身不含"找切点"的能力**。

**后动作** `mouseturn()`（`utility.c:1517-1523`）：

```c

taskturn(pattern);
ledoff(0);
speed_ss = 70; speed_fastss = 100;   // 转弯后巡线速度切档
```

之后 `action()` 继续下一条，通常紧跟 `STRAIGHT90L/STRAIGHT45L`（`taskstraight90/45`，IR+陀螺，不查表）。

### 3.3 180° 掉头（AROUND 表）

**调用链**：`mouseTurnback()`（`utility.c:1080`）/`specialmouseTurnback()`（`1100`）← `strategy.c:409` 与 `test.c` 多处（返回起点、目标点回退）。

- `mouseTurnback` = 完整版（含 `SaveBlockData`、`after180turn`）；`specialmouseTurnback` = 精简版（只掉头 + 坐标 + `settrack(0)`）。

**前动作** `before180turn()`（`utility.c:921-951`）：
1. `task=SMARTSTRAIGHT` 先走 5 mm；
2. 按左右墙决定 `afterturn_flag`（1=左墙、2=右墙、0=无墙）——**这是给后动作用的**；
3. 无前墙：`taskgostraight(5 或 20)`（看上一动作）→ `taskstop()`（`decdistance=10`）→ 记 `disbf180 = absolutetrack - 起点 + 30`；

- 然后无条件 `taskacc()`（ACC 段加速到 `speed_turn`）+ `taskgostraight(disbf180-35)`；

- 外层 `mouseTurnback` 收尾：`GucMouseDir=(dir+2)%4; __mouseCoorUpdate(); settrack(0);`

### 3.4 定点 90°（POINT 表）

**调用点**：

## 四、能不能被打断

分三层看，结论：**表本身不可打断，只有"整段撤离"这一种打断方式，而且它不安全。**

### 4.1 表内部（ISR）：没有任何中途退出条件

`case TURN` 只有"`tick` 自增 + 查表 + PD"，**没有** `|gangle| < 阈值就收`、没有"堵转就放弃"、没有超时。
后果：
- 打滑/被挡住 → 表照播，`gangle` 跟不住参考 → `e` 饱和，车在表播完后带着几十度误差进入下一段；
- 转向耗时是**表长的常数**，与负载无关（90° 固定 ~190 ms）。

`TURNAROUND/POINTTURN90` 看似有 `step` 分支，但进场时刻也是常数（200 ms / 30 ms），后面靠 P 收敛到 `gangle≈0` 再判静止——**判的仍是"角速度为零"，不是"角度到位"**。

### 4.2 前台阻塞循环：只有远程档能强拆

`taskturn` 的 `while(tick < length/2-2)`、`taskturnaround` 的 `while(1) if(step==1 && tick>30) break;` 等循环体内**没有** `LP_AbortRequested()` 检查（这一点与 `mazeSearch`/`mouseGoahead`/`beforemouseturn` 等循环不同）。

远程档靠 `SysTick_Handler` 里的一段**篡改判据**来解除（`timer.c:459-472`）：

```c
#ifdef MOUSE_REMOTE
if(LP_AbortRequested())          // LP_StopMotion / MAZE STOP / ESTOP / MCU RESET 置位
{
    task = 0;                    // 停表
    step = 1;                    // 让 while(1) if(step==1 ...) 成立
    tick = 60000;                // 让所有 while(tick<N) 立刻成立
    track = absolutetrack = absolutetrackl = absolutetrackr = 0x7FFFFFFF;
    setvl = setvr = 0;
}
#endif
```

因为 `tick` 每毫秒都被重写成 60000，等待循环必定退出，且**退出是粘滞的**。

比赛档（无 `MOUSE_REMOTE`）**完全没有这条通路**——转向一旦开始，只能等它自己播完。

### 4.3 急停：会把前台**挂死**

`isemergency=1`（PWM 饱和 >200 ms 或 `|setvl|>2000`，`timer.c:1270-1276`）时：

```c
if(isemergency==1){ freemode=1; task=NULL; setvl=0; setvr=0;
                    emergency_delay++; if(emergency_delay==200) sleepmode=1; }
```

`task=NULL` ⇒ `tick` **停止自增** ⇒ 前台 `while(tick < length/2-2)` 永远等不到头，`while(1) if(step==1&&tick>30)` 也永远不成立（`step` 不会再被置 1）。
**这是唯一一种"打断后不可恢复"的情形**：车停了，但固件卡在那个 while 里，只有 `MCU RESET` 能出来。

> 记忆点：`isemergency` 不写 `step`、不写 `tick`，所以它**只能停 ISR，不能解前台**；
> 能解前台的只有 `linkRunAbort`（远程档）。

### 4.4 打断后的状态污染

即使成功撤离（远程 abort），也已经发生过了：

| 已被修改、无法回滚 | 后果 |
|---|---|
| `setangle()` 已改 `baseangle` / `ganglet` | 航向基准被移到"转完之后的朝向"，实际没转完 ⇒ 之后所有 `gangle` 失真 |
| `GucMouseDir` 未更新（在 `taskturn` 返回之后才写） | 地图朝向与实际不一致 ⇒ 下一格走错 |
| `__mouseCoorUpdate()` 未调用 | 格坐标错位 |
| `settrack(180-o)` 未执行 | 里程原点错，下一格长度算错 |

⇒ **查表转向不具备"半路取消"的语义**：要么整段走完，要么整段丢弃并重新定位（`MCU RESET` / 重新 `MAZE RUN`）。这也是为什么 `ESTOP` 的恢复流程是"停 + 复位"，不是"续跑"。

### 4.5 前/后动作与打断的耦合

- **前动作能否打断**：三种前置各有不同的脱离机制——
  - `beforemouseturn` 的四个等待循环里**有显式检查** `if(LP_AbortRequested()) break;`（`utility.c:1469/1481/1493/1506`）；
  - `before90turn`（`utility.c:842-916`）的 `while(1)` 靠 `track>=阈值` 跳出，打断时 `track` 被强推成 `0x7FFFFFFF` ⇒ 下一拍即退出；
  - `before180turn`（`utility.c:925/929`）的 `while(track<5)`、`while(tick<5)` 分别靠 `track`/`tick` 强推退出。
  这四处都**尚未调 `setangle`**，所以打断是**状态无损**的。
- **转向表本身不可打断**（4.1–4.3）。
- **后动作可打断但"部分生效"**：`after180turn` 里的 `while(tick<10)`、`taskgostraight` 靠 `tick=60000`/`track=0x7FFFFFFF` 立刻穿透，但 `afterturn_flag` 已被读走、`GucMouseDir` 已 `+2`，无法回滚。

## 五、精炼算法描述

```
Turn(pattern):                              # 一次查表转向
    setangle(±deg)                          # 1. 重定航向基准（表头对齐的前提）
    (G[],VL[],VR[],N) ← TABLE[pattern]      # 2. 装表：航向参考 + 双轮前馈 + 播放窗
    tick,e,eh,esum ← 0
    task ← TURN
    wait tick ≥ N                           # 3. 阻塞，无其它出口
    settrack(0)                             # 4. 里程归零，把残余误差交给下一段

on 1 kHz tick:                              # 表在中断里推进
    if pattern ∈ {AROUND, POINT}:
        if tick < N0:                       #    N0 = 200 / 30 ms
            ref ← G[tick]; e ← gangle - ref
            vl ← VL[tick] - kp·e - ki·Σe - kd·Δe
            vr ← VR[tick] + kp·e + ki·Σe + kd·Δe
        else:                               #    表只做起转，剩下靠纯 P 收口
            e ← gangle
            vl ← -k_p·e ; vr ← +k_p·e       #    掉头 2.5，定点转 1.0
    else:
        ref ← G[tick]; e ← gangle - ref
        vl ← VL[tick] - kp·e - kd·Δe        #    kp/kd = 4/4（竞速档 4/2、8/5、10/7）
        vr ← VR[tick] + kp·e + kd·Δe
    tick ← tick + 1

TurnRight90_Search():                       # 完整"前—中—后"
    BEFORE90TURN: 匀速 30，前墙→disf2-disf1 对齐 / 无墙→gangle 保直
                  按 LastSearchAction 定过冲量，凑够 turn_delay±k
    o ← dis2wall - mean(disl,dislh,dislhh)  # 侧向偏差
    Turn(SEARCH_R)                          # ~193 ms 恒角速度 90°
    task ← SMARTSTRAIGHT                    # 不等静止，直接让位
    dir ← (dir+1) mod 4
    settrack(180 - o)                       # 偏差折进下一格
    # 残余角差由 SMARTSTRAIGHT 的 e=gangle 闭环吸收
```

一句话总结行为特征：
**"表定轨迹、PD 补误差、时间定终点；起点靠墙找、终点靠下一段直行收。"**

## 六、勘误与风险

| # | 位置 | 问题 |
|---|---|---|
| 1 | `utility.c:668` | `RV135L` 的 `length=sizeof(gyro_rv135_low)+8=596 ⇒ 296`，超出表长 294 两项，**越界读 Flash 2 项**（落在相邻常量上，值有限但无意义）。应改为 `-` 或 `-4`。 |
| 2 | `utility.c:24` | `turno` 只写不读，`timer.c` 无任何引用；`before90turn`/`mouseTurnX` 里 8 处 `turno=0` 是死代码。 |
| 3 | `utility.c:15-18` | `*_spurt[1]={0}` 使 `taskturn(RT90SPURT)` 立即返回，`task=TURN` 只被 ISR 执行 1 次。"90° 冲刺转向"实际是角度误差差速，**表名存实亡**，容易误导调参。 |
| 4 | `taskturn()` | 不复位 `step`。`TURN` 不用 `step` 所以暂时无害，但若把 `TURN` 改成两段式，会继承上一个动作的 `step=1`。 |
| 5 | `taskturn()` | 表长裁剪（`-8/-4/-16/-14/+8`）**没有编译期断言**，改表长会静默改变转角/时长。 |
| 6 | `utility.c:71` vs `1789` | `HIGH_ENABLE` 未定义 ⇒ `spurt(HIGH)` 进 `action()` 是 `while(1)` 闪灯死循环；HIGH 档的 45/135 表实际不可达。 |
| 7 | 全局 `tick` | 转向表、`KEEPWALLDISTANCE`、`BEFORE180TURN`、`taskstop` 共用同一个 `tick`。任何"进表前忘写 `tick=0`"的路径都会**穿透等待**（`test.c:836/846/855` 都是为此手工补的）。 |
| 8 | `timer.c:459-472` | 远程 abort 靠"每毫秒重写 `tick=60000`"来解等待，属于**判据篡改**而非协作式取消；新增等待循环时必须沿用同样机制，否则会挂死。 |
