## 0. 三条铁律（每一步都适用）

| # | 铁律 | 原因 |
|---|---|---|
| 1 | **上电前车必须绝对静止** | `hardware_init()` 的陀螺零偏标定是阻塞死循环（`gyro0==-1` 等 `angle_counter>1000`，而它一见 `gangle` 变化就清零）。车一动 ⇒ 永久自旋 ⇒ 标定完成前串口全程 0 字节。**症状与 NVIC 故障完全相同，极易误判。** |
| 2 | **判状态必须用新鲜帧** | `telemetry.latest()` 是缓存，链路一停就永远停在旧值。必须记帧计数 → 发 `TELEM` → 等计数真变了。**空帧 ≠ 待命**（空帧意味着链路不通，必须按"可能在跑"处理）。 |
| 3 | **安全出口宁可报失败，绝不谎报成功** | 收车判据 `rst=SW`；刚发过车的一律 `assume_busy=True`。`force_idle()` 停不住时必须报"未确认待命，请人工断电"。 |

**辅助判档**：`PING` → `PONG 8 300 16 1024 <rst>`。
`fw=300` = 远程档。若 `PING` 永远无 `PONG`，先怀疑**烧错档**（比赛档无 `LINK_Init`），
用 J-Link 读 Flash 首字确认：远程档 `0x200034F8` / 比赛档 `0x20005000`。

**收车定式**（`force_idle()` 已实现，务必用它而不是手敲）：

```
MAZE STOP  →  ESTOP  →  MCU RESET
```

- `MAZE STOP` **在迷宫阻塞等待里不可靠**（回 OK 但 `task` 仍在 `SEARCH`）；
- 发过 `MAZE STOP`/`ESTOP` 后**必须补 `MCU RESET`** —— 它们置的 `linkMazeAbort`
  全固件无处清除，不补则下次"发车 OK 却不动"（`LESSON_Blind8()` 进门即返回）。

**收车判据**：新鲜帧读到 `rst=SW`。若 `force_idle()` 返回 `ok=False`，
按提示**立即人工断电**，不要重试掩盖。
