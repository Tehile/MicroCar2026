## 1. 要解决什么

实验 8 是**无记忆走迷宫**（`LESSON_Blind8()`，`APP/lesson.c`）。它跑起来之后，上位机原先只能看到
慢帧里的 `mouseTask` + 坐标 —— 看不到"**它刚才识别到了什么**"：
是直道还是弯道？是岔路口还是死路？到没到终点？转了向没有？

这些判断**在代码里是真实存在的**（`lessonStr.roadStat` 数开口、`EXPLORE_CrosswayChoice()` 选向、
`STATE_MazeSearch()` 判终点、`MOTION_MouseTurnBack()` 掉头），只是没有回传通道。
本功能把这些状态**如实报出来**，且**不改动任何原有逻辑**。

## 2. 设计原则：只读观测，不埋点

观测层整个放在 `HARDWARE/link.c`（本项目的上位机链路模块）里，**不在 maze/state/lesson/motion 里插一行钩子**：

| 原则 | 原因 |
|---|---|
| 只读**已公开**的全局量 | `mazeState`（坐标/朝向/任务/岔路栈/终点区）、`wallSns`（前/左/右墙）、`motionCtrl.task`。这些本来就是驱动决策的量，所以"回传的状态"与"代码里的状态"天然同源 |
| 观测点在 SysTick（1 ms）上下文 | 迷宫的 `while(1)` 挡不住它；命令与遥测本身也是中断驱动的（见 `docs/数据收集与时间同步.md`） |
| 关掉本模块不影响原有逻辑 | 观测层可整体删除，比赛行为逐字不变 |

## 3. 三个通道（可分别使用）

### 3.1 事件流 `MAZE EV <EVENT> ...`（主用）

**迁移驱动** —— 只在状态**变化**时上行一行。这是"识别到"最直接的表达。

| 事件 | 何时发 | 例子 |
|---|---|---|
| `BEGIN <x> <y>` | 进入迷宫态（一次） | `MAZE EV BEGIN 0 0` |
| `EXIT` | 退出迷宫态 | `MAZE EV EXIT` |
| `TASK <from> <to>` | 任务机迁移 | `MAZE EV TASK WAIT SEARCH` |
| `ROAD <KIND> <code>` | **识别到路口类型变化** | `MAZE EV ROAD TEE_FL 4` |
| `JUNC <stack>` | 岔路口栈深度变化 | `MAZE EV JUNC 5` |
| `TURN <MOTION> <code>` | 进入转弯/掉头动作 | `MAZE EV TURN TURNAROUND 4` |
| `GOAL <x> <y>` | 首次到达终点区 | `MAZE EV GOAL 7 6` |
| `CELL <x> <y> <dir>` | 进入新格（**默认关**，量最大） | `MAZE EV CELL 3 4 1` |

### 3.2 1 Hz 状态帧 `LINK_TYPE_MAZE (0x09)`

**只在"处于迷宫态"时发送** → 空闲时零带宽增量。且与其它周期帧一致，受 `STREAM ON` 约束。

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | `task` | 迷宫任务机：0 WAIT / 1 START / 2 SEARCH / 3 SPURT / 4 SPURT45 / 5 SPURT90 |
| 1 | `road` | 路口类型码（见 §4） |
| 2 | `opens` | 前/左/右开口数 0..3 —— **与 `lessonStr.roadStat` 同义** |
| 3 | `motion` | `motionCtrl.task`（当前动作，如 2=TURN / 4=TURNAROUND / 101=LT90SEARCH） |
| 4–5 | `posX` `posY` | 当前格坐标 |
| 6 | `dir` | 朝向 0..3 = UP/RIGHT/DOWN/LEFT |
| 7 | `stack` | `mazeState.stackIdx`（支点栈深度） |
| 8 | `flags` | 见下 |
| 9 | `evMask` | 当前事件掩码（回显，便于确认配置） |
| 10–11 | `evCount` u16 | 本轮已发事件数 |
| 12–13 | `juncCnt` u16 | 累计识别到的岔路口数 |
| 14 | `turnCnt` | 累计转向/掉头次数 |
| 15 | `deadCnt` | 累计死路次数 |

`flags`：bit0 `GOAL`(已到终点) / bit1 `BACK`(回程) / bit2 `SPURT`(冲刺中) /
bit3 `JUNC`(遇到过岔路口) / bit4 `EVQ`(**有事件被丢弃 → 事件流不完整**) / bit5 `DEAD`(遇到过死路)。

> `EVQ` 很重要：事件行与 dump 共用 512 B TX 环，dump 期间环可能接近满，此时事件会**被丢弃**
> rather than 回绕覆盖（见 §6）。上位机据此知道"事件流不完整"，而不是假装完整。

### 3.3 `SNAP MAZE` 阻塞点查

命令在中断里处理，**迷宫 `while(1)` 跑着也能问**。一行纯整数，字段顺序：

```
task road opens motion x y dir stack flags evCount evDrop juncCnt turnCnt deadCnt cellCnt atGoal
```

多出的 `evDrop`（丢弃计数）与 `cellCnt`（累计格数）是周期帧里没有的量。

## 4. 路口类型判据（8 种）

由 `wallSns` 的前/左/右开口相对**当前朝向**分类；与 `LESSON_Blind8` 数 `roadStat` 用的是**同一组输入**。

| 码 | 名 | 含义（相对当前朝向） | 中文 |
|---|---|---|---|
| 0 | `NONE` | 未判定（尚未进入搜索决策态） | 未判定 |
| 1 | `THRU` | 只有前方开口 | **直道** |
| 2 | `CORNER_L` | 前 + 左 | **左弯** |
| 3 | `CORNER_R` | 前 + 右 | **右弯** |
| 4 | `TEE_FL` | 前 + 左（右侧封死） | **岔路口**(T 型) |
| 5 | `TEE_FR` | 前 + 右（左侧封死） | **岔路口**(T 型) |
| 6 | `TEE_LR` | 左 + 右（前方封死）→ 必须转向 | **岔路口**(T 型) |
| 7 | `CROSS` | 前 + 左 + 右 | **十字路口** |
| 8 | `DEAD` | 三面皆墙 | **死路** |

刻意**不含后方**：后方是来路，不参与形状判定（死路 = 前/左/右三面墙）。

**只在 `task == SEARCH`（搜索决策态）评估**，且要求连续 2 个 20 ms 采样一致（去抖）。
理由：行驶途中侧向开口会一闪而过，全程评估会大量抖动；而决策态下的 `wallSns`
正是 `LESSON_Blind8` 用来数 `roadStat` 的那一拍，语义才对得上。

### 终点判定

判据与 `APP/state.c` 里 `STATE_MazeSearch()` 的"到达终点区"**完全一致**：

```c
(x == xGoal0 || x == xGoal1) && (y == yGoal0 || y == yGoal1)
```

link.c 只是**只读复制**这个判据，不动 state.c 一行。

## 5. 命令

| 命令 | 作用 |
|---|---|
| `MAZE EV [mask\|OFF\|DEF\|ALL]` | 设置事件掩码（0..63 十进制）；**不带参数 = 查询**（回 `MAZE EVMASK <n>`） |
| `MAZE RST` | 清迷宫统计（事件计数/岔路口/死路/转弯/格数）；**掩码保留** |

掩码位：`1` TASK / `2` ROAD / `4` JUNC / `8` TURN / `16` GOAL / `32` CELL（默认关）。缺省 `31`。

> 注意：发车前的 `MAZE RUN` 是**另一个**命令（见 `docs/数据收集与时间同步.md`），二者同属 `MAZE` 命令组。

## 6. 带宽与不丢数据

- **事件**：迁移驱动。一次真实迷宫跑下来 `ROAD` 是主体（每格变化一次），实测约 **5~6 条/秒**（含 TASK/TURN），
  单条约 25 B → **≈150 B/s**，且只在跑迷宫时才有。
- **状态帧**：24 B/s（16 B 载荷 + 8 B 开销），**只在迷宫态**。
- **空闲时增量为零**：既不发帧也不发事件。
- **事件空间门**：发一条事件前要求 TX 环空闲 ≥ 64 B，不足则**丢弃并计数**（`evDrop`），
  并在状态帧置 `EVQ` —— 宁可少发，也不让长文本在 dump 期间回绕覆盖尚未发出的数据。

## 7. 上位机用法

```python
mc.maze.state()          # 最近一帧状态帧(1Hz); 未跑迷宫 → None
mc.maze.history()        # [(单调时刻, 状态帧)] 用于看"什么时候变成这样"
mc.maze.snap()           # 阻塞点查 SNAP MAZE(迷宫跑着也能问)
mc.maze.events()         # 已收到的事件(时间正序), 可 kind="ROAD" 过滤
mc.maze.watch(dur=10)    # 只收不阻塞地观察 10 秒, 返回这段时间的事件
mc.maze.on_event(cb)     # 订阅(在调度线程回调)
mc.maze.summary()        # 汇总: 任务/路口分布/动作分布/终点/计数/任务序列
mc.maze.explain()        # 上面那份汇总的人话版(逐行)
mc.maze.set_events("OFF"|"DEF"|"ALL"|0..63)   # 查/设掩码
mc.maze.reset()          # 清固件侧统计 + 本地事件缓冲
mc.maze.monitor_view()   # 给实时面板的紧凑视图(不发命令)
```

CLI：

```bash
python -m host.cli maze                      # 墙图(原行为; 省略 action 即 map)
python -m host.cli maze state                # 最近 1Hz 状态帧
python -m host.cli maze snap                 # 阻塞点查 SNAP MAZE
python -m host.cli maze events --n 50 --kind ROAD
python -m host.cli maze watch --seconds 30   # 实时跟随事件流
python -m host.cli maze summary              # 汇总
python -m host.cli maze ev DEF               # 查/设事件掩码
python -m host.cli maze rst                  # 清统计
```

`monitor` 在收到状态帧后会自动多出一节 **迷宫状态机**（任务 / 路口 / 岔路栈 / 位置朝向动作 /
累计计数 / 标志 / 最近 3 条事件）；没跑迷宫时这一节不出现。

## 8. 本轮踩的三个坑（都做成了回归）

1. **BEGIN 被无限重发**（模拟器侧，实测 6 秒 299 条）。
   原因：用 `maze_flags` 的一个高位记"上一拍在迷宫态"，而 `reset()` 会清 `flags` → 边沿每拍都成立。
   修法：改用**独立字段**（与固件 `linkMaze.inMaze` 同构）。回归：`maze_smoke` 断言 `BEGIN` 只能 1 条。

2. **进入迷宫的 `TASK` 迁移被 reset 吞掉**。
   原因：`reset()` 把 `task_prev` 设成"当前值"，正好吃掉 `WAIT → SEARCH`。
   修法：进入迷宫时显式退回 `WAIT`；手动 `MAZE RST` 不走这条路径（故不会误报）。回归：断言事件流含 `TASK`。

3. **`push_time` 的 `self._notify("time", rec)` 被挤进新函数**（上位机侧）。
   往 `ring.py` 插 `push_maze` 时锚点选在 `push_time` 最后一行之前，结果那行被留在了 `push_maze` 末尾
   → **TIME 帧不再通知**（时间同步样本恒为 0，`timesync_smoke` 掉了 5 项），而迷宫帧冒名通知成 `"time"`。
   **编译与 import 都不报错**。修法：把那行放回 `push_time`，新函数自己 `_notify("maze", rec)`。
   回归：`contract_test [S5]` 新增静态断言 —— **每个帧 sink 只 notify 自己的 stream**。

> 另外把模拟器上电初值 `mouse_task` 从 2 改成 **0 (WAIT)**，与固件一致 ——
> 原来上电就"在迷宫里"，会让"进入迷宫态"的边沿永远不出现。
