## 2. 改动清单

### 2.1 文件同步（v9.1 → v10）

| 文件 | 动作 |
|---|---|
| `REMOTE/link.c` | 从 `code_competition/REMOTE/` 覆盖（FW 311 → **314**） |
| `REMOTE/link.h` | 同上（PROTO 9 → **10**） |
| `REMOTE/link_port.c` / `.h` | 原本已逐字节相同，**未动** |

v10 相对 v9.1 的实质变化：帧长仍 30 B，但**字段偏移整体前移 5 B**（删 ENCANG，IRMM 并入），
并新增**建图增量通道**（偏移 23..29，每帧最多 3 条、每条 2 B 自带绝对坐标）。
后者正好解决旧 `MAP DUMP` 只能读 Flash 快照、跑完才知道结果的问题。

### 2.2 门控宏 `REMOTE_FULL`（核心）

原工程有 **44 处** `#ifndef MOUSE_REMOTE`（"只有比赛档才编译"）。远程档既要链路层
（`#ifdef MOUSE_REMOTE`），又要 V5/V6 算法本体，两者原本互斥。

做法：新增 `REMOTE_FULL`，把其中 **41 处**改为

```c
#if !defined(MOUSE_REMOTE) || defined(REMOTE_FULL)
```

即"比赛档 OR 保真远程档"。剩下 **3 处不动**，因为它们包的是

```c
#define FLASHSAVE   /* 飞行记录开关 */
```

`FLASHSAVE` 定义时会吃掉 ~9.5 KB RAM（`save_num` 1136 vs 1），远程档必须保持关闭。
**这三处仍用 `#ifndef MOUSE_REMOTE`，是刻意的**，不要"顺手统一"。

分布（改写 41 处）：`utility.c` 25、`test.c` 6、`timer.c` 5、`stratagy.c` 3、`adc.c` 2、
`stmflash.c` 2、`utility.h` 1。

### 2.3 `v5_diag` 解耦（连带依赖的根因）

`v5_diag`（`V5_STOP_DIAGNOSTICS`，**正好 256 B**，`search_guard_v5.h:41` 有静态断言）
原本定义在 `stmflash.c` 的 `#ifdef FLASHSAVE` 块里 —— 于是"关飞行记录"顺带把
V5 诊断与 V6 连续弯状态字节（`V6_TURN_CHAIN = v5_diag.reserved`）一起关掉了。

改法（`HARDWARE/STMFLASH/stmflash.c`）：

```c
#ifndef FLASHSAVE
const u16 save_num=1;
const u8 per_timer=2;
volatile V5_STOP_DIAGNOSTICS v5_diag={0};   /* 新增：REMOTE_FULL 也要 */
#endif

#ifdef FLASHSAVE
const u16 save_num=1136;
volatile V5_STOP_DIAGNOSTICS v5_diag={0};   /* 原文未动 */
const u8 per_timer=2;
#endif
```

比赛档走 `#ifdef` 分支，与原文**逐字节相同**；远程档走 `#ifndef` 分支拿到 `v5_diag`。
两个分支各自定义、互不重复。

### 2.4 补中止钩子（2 处）

V6 新增的两个忙等循环里原本没有中断检查，远程档跑起来 `MAZE STOP` 会拦不住：

| 位置 | 原 | 改 |
|---|---|---|
| `utility.c` `v6SlowSearchTurn90()` | `while(tick<end_tick);` | `#ifdef MOUSE_REMOTE` 下改成 `while(tick<end_tick){if(LP_AbortRequested())break;}`，`#else` 保留原样 |
| `utility.c` `goalDepartureAfterTurnback()` | `while(track<distance);` | 同上 |

用 `#ifdef MOUSE_REMOTE` 包裹 ⇒ **比赛档预处理结果完全不变**。

其余冲刺路径（`spurt_grid90` / `gridFastStraight90` / `gridSearchWait90` / `gridSearchNode90`）
本来就走 `spurtSearchRunning()`，而它内部已有 `#ifdef MOUSE_REMOTE if(LP_AbortRequested()) return 0;`
（`utility.c:1830`），因此**无需重复加**。反汇编确认 `LP_AbortRequested` 被引用 19 处。

### 2.5 类型冲突修正（编译器暴露的既有隐患）

`link_port.h` 按真实定义声明 `long disf1...`/`long setvl,setvr`/`u16 dataf1[250]`，
而 `test.c`、`utility.c`、`stratagy.c` 里几处 `extern` 写的是 `u16`/`int`/`[240]`
（比赛档不 include link_port.h，所以从没报错）。

修法：这几处 extern **还原成 `#ifndef MOUSE_REMOTE`**，远程档交给 `link_port.h`。
比赛档声明保持原样，避免改变代码生成。

| 文件:行 | 内容 |
|---|---|
| `test.c:86` | `extern u16 disf1,...,disl45hh,disr45hh;`（其中 4 个变量在 test.c 里**从未使用**） |
| `test.c:91` | `extern int setvl,setvr;` |
| `test.c:114` | `extern u16 dataf1[240],...;` |
| `utility.c:113` | `extern u16 disl45,disr45;` |
| `utility.c:119` | `extern int setvl,setvr;` |
| `stratagy.c:57` | `extern int setvl,setvr;` |

### 2.6 `case SPURT_90` 重复标签

`test.c:1183-1184` 在比赛档提供 `case SPURT_45: case SPURT_90:`，而 `test.c:1346` 又用
`#ifdef MOUSE_REMOTE` 给远程档补了一个空 `case SPURT_90`。REMOTE_FULL 下两边同时成立 ⇒ 重复标签。

改为 `#if defined(MOUSE_REMOTE) && !defined(REMOTE_FULL)`：保真远程档走真正的 grid 冲刺分支。

## 4. 红线验证（关键：基线本身已过期）

### 4.1 经过

改完后重编，四个比赛 hex 里 **V6_4mm 没变、另外三个变了**，看似红线被破坏。

排查方法：把**改动前**的源码备份（`_backup/V6plus_pre_remote_20261105_110807.tar.gz`）
解压到临时目录，用同一台 Keil 重编同样四个 Target，得到：

| Target | 改动前源码重编 | 改动后重编 | 判定 |
|---|---|---|---|
| V6_0mm | `49f4ddb7…` | `49f4ddb7…` | 一致 |
| V6_2mm | `9224fda7…` | `9224fda7…` | 一致 |
| V6_4mm | `a642c6b6…` | `a642c6b6…` | 一致 |
| V6_6mm | `3e93709c…` | `3e93709c…` | 一致 |

结论：**hex 变化与本次改造无关**。文档 §4.5 记的 `54f2c30f/a7baf349/a642c6b6/1b6b76b4`
是 10-29 的产物，10-29 之后源码改过但没重编，所以基线过期。V6_4mm 恰好当时编过，才没变。

## 6. 怎么用

1. 用 Keil 打开 `code_competition - V6+/USER/TEST.uvprojx`，Target 选 **`Target_Remote`**，
   编译产物在 `USER/Remote/TEST.hex`。
2. 烧录后上电（**必须静止**，陀螺标定是阻塞死循环），主机会收到 PONG，`fw` 应报 **314**、`proto` **10**。
3. 上位机用现役 host 工具（API ≥ 2.13.0，支持 PROTO 10）。
4. 发车/收车安全纪律见记忆与 `docs/` 既有文档（`--mark-n 2`、禁用 `RATE FIX` 等）。
