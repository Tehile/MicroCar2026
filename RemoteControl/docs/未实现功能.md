## 1. 未实现（需要时可接通）

### 1.1 `MAP LIVE` —— 实时墙图的全量拉取

**缺什么**：`LP_SyncMap()`（`link_port.c:293`）负责把实时墙图 `GucMapBlock/GucMapGet`
拷进回传镜像，但**全仓无任何调用点** ⇒ `MAP DUMP` 只能给出"Flash 存档快照"。

**v10 的做法**：不去修 `MAP DUMP`，而是**另开建图增量通道**（`LinkMapD`，每帧 3 条 × 2 B）
绕开它。所以实时建图能力已经有了，但"一次性拉整张实时图"的命令仍然没有。

**接通步骤**（零回归，约 10 行）：

```c
/* link.c, MAP 分支内 */
if (link_TokIs(&p, "LIVE"))
{
    LP_SyncMap();          /* link.h -> link_port.h 已能看到声明, 不用加 include */
    link_SendMap();
    link_Ack(seq, "OK");
    return;
}
```

`MAP DUMP` 行为逐字节不变 ⇒ 现有 host 与文档零回归；host 侧加一条 `maze.live`，
复用现成 `decode_map`。代价：一次 512 B 拷贝 ≈28 µs，低频命令可忽略。

**替代方案（一行但有回归面）**：在 `link_SendMap()` 开头直接调 `LP_SyncMap()`。
这会让 `MAP DUMP` 语义从"存档图"变成"实时图"，与现行规格冲突，且 `CAL BLOCK`
之后不再是"读回刚校验的那份图"。

## 4. 已知边界（不是缺陷，但看图/调参时会遇到）

- **容量硬闸**：`N/RTT ≤ 13.3 Hz` 存活，`≈25 Hz` 必死。真机拉取档位只在这三档里选：
  **N=1（4.6 Hz，最省）/ N=2（6.9 Hz）/ N=4（13.3 Hz，跑满）**。
  `link_pull_evt.py` 的 `--max-hz`（默认 13.3）会自动钳制 N。
- **低 4 位全 0 有两义**：`GucMapBlock` 的低 4 位为 0 表示"这格没探过"（正常数据），
  UI 无法把它和"四面皆墙"区分开 —— 靠访问图（v10 增量通道）区分。
- **显示层**：外框永远画（`maze_view.py:108`），即使数据里外圈位是可通行；
  `test.c:779-790` 环形搬运会填 `0xf0/0xD0`（低 4 位为 0）⇒ 出现个别"四面皆墙孤格"。
- **红外阈值上限**：v10 把 `irMm[4]` 压成 u8 后，参数表里任何红外阈值必须 **≤254**
  （当前默认最大 245）。`SET` 能写任意 u16，host 侧需钳位。
- **旧工程 `code_stm32f1_mouse/`**（课程固件，MAZETYPE 7）仅作参考，不再是主线；
  同名副本目录 `code_competition - 副本/` 是本地备份，不入库。
