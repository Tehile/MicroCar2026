## 1. 比赛固件远程化移植（P0–P5，2026-10-16 完成）

**问题**：`code_competition/` 是一套架构完全不同的比赛代码——无 `link.c`、无分层，
`main()` 是 1250 行单体状态机，运动原语是 `taskgostraight/taskturn` **忙等函数**，
参数是 `user.c` 里的 `const` 常量。被替代基线是 `code_stm32f1_mouse/`（课程固件，MAZETYPE 7）。

**结论**：可以移植，且上位机几乎不动。因为远程层本就是"协议与平台解耦"的：

| 维度 | 结果 |
|---|---|
| 通信协议（帧/CRC16/幂等重放/停等与批式） | ✅ 原样 |
| 命令集、参数表（41 项 Q16.16 + page115） | ✅ 原样（名字不变，宿主变量换绑） |
| `link.c` 协议引擎 | ✅ 原样 90%+ |
| 上位机 `host/` | ✅ 绝大多数原样 |
| 平台相关（电机停止/发车握手/flash/LED/USART/1ms 节拍） | 🔧 新写适配层 |

**核心工作量 = 一个新文件 `link_port.c`（平台适配层）+ 约 10 处 1~3 行门控插入。**

**最高风险 = 协作式中止**（新固件全是忙等循环，`MAZE STOP` 这类软停止会永远卡住）。
解法：在 `objectGoTo` 入口、`mapStepEdit` 循环内、`maze_done` 三处打补丁，
另加 `LINK_Tick` 见「abort + linkMazeRun」持续 2 s 软复位兜底。
判兜底看**回待命耗时**（~1 s 优雅 / ≥2 s 兜底）。

## 3. 参数工具链（v2.0 设计 → v3.0 常量化）

**v2.0 四处收敛**（相对 v1）：

| v1 | v2 依据 | 结果 |
|---|---|---|
| "JSON 与固件只允许相等" | 用户：存储数据与固件**不一定一致** | 引入 `fw`（固件只读快照）/ `store`（人工受管值）/ `policy`（策略）三件套，分歧是被分级管理的状态 |
| 写无依赖 C 词法扫描器 | 用户建议正则；14 个文件是 GBK+CRLF | 改为 **ASCII 字节正则库** `regexlib.py`（9 条正则，在 `bytes` 上匹配，全流程不解码）⇒ 编码/行尾零风险 |
| 默认值取文档 | 用户：数据以现在新固件为准 | `fw.value` 一律由源码抽出，文档值降级为参考 |
| 只有方案 | 本轮要求写代码 | 实现 `extract / apply / check / audit / render` 五子命令，幂等/写回/定点三关全绿 |

**v3.0 六项拍板（B1–B6）**：

| # | 拍板 | 落地 |
|---|---|---|
| B1 | 参数应是**全量整定常量** | 范围从"有链路 id 的 41 项"扩到固件里全部影响运动/感知/路径的数值（≈72 值位），目标是可重复性 |
| B2 | 多套建模用一致命名 | `<参数名>@<时期>`，同一逻辑参数各套共享基名 |
| B3 | 先完成固件侧 | 只做"JSON ⇄ 固件源码"，不碰 `LINK_P_NUM`/page115 |
| B4 | 有初值的量把初值作为一个时期 | `init`（编译期初值）与 `search`/`spurt` 平级 |
| B5 | 读出默认值 → 备份 → 写入测试 → 检查编译后是否变动 | 验收流程 = 冻结 → 抽取 → 回写（应 0 变更）→ 双档重编 → 比红线 hex |
| B6 | 先处理比赛这边 | 远程档镜像只登记不动作 |

**当前状态**：v3.0 已跑通并归档 v3.0.0；**P3 剩余（CAL 矩阵）未完成**，见

## 4. 遥测拉取器统一（v2.10.0，已实施 + 真机 41/41）

把**停等式**（`PullRequester`，单条 `TELEM` 阻塞）与**批式**（`PacePull`，一条
`RATE PULL n t` 取多帧）合并为一个 `TelemetryPuller`——统一轴就是 **n**（每条命令取几帧），
**n=1 即停等**，退化发生在调度器层面而不只是参数层面。

- 四件共同持有：在途不变量、让路（suspend/resume）契约、断连判定、时间锚维护，合并后各只有一处。
- 门面 `mc.stream` 对外符号一个不删 ⇒ 下游 `Control` 与全部测试套件零改动。
- 顺带补两个缺口：批式**从不刷新时间锚**（`RATE PULL` 的 ACK 不带时基）⇒ 设备复位后
  ms8 同余还原永久失锁；停等式**没有断连判定**（只数 lost，永不自停）。
- 实施细节：旧类名**不留别名**；自节流信号由帧基改为 **ACK 基**（实测教训）。

## 6. 协议 v10（字段瘦身 + 建图增量通道，2026-10-23 落地）

基线 v9.2.1（`PROTO 9` / `FW 313` / 载荷 30 B）→ `PROTO 10` / `FW 314` / **载荷仍 30 B**。

| 项 | 决策 | 依据 |
|---|---|---|
| `irMm[4]` u16→u8 | 省 4 B | 全部红外阈值 ≤ 245 < 255，饱和不改变任何 `<thr` 判决 |
| `battMv` u16→u8 | 省 1 B | `round(mV/50)`，低电闸 7000 mV ↔ 140 整，零量化误差 |
| `encAng` 删除 | 省 2 B | 唯一消费者是 monitor 一行显示，无算法依赖 |
| 腾出的 7 B | 全部给建图增量通道 | 变长尾部更省字节，但本链路速率由 RTT 决定，与帧长无关 |
| 每帧带宽 | 3 条 × 2 B | 实际需求 ≤2 条/周期，供给 15 条 ⇒ 余量 7.5 倍 |
| 每条编码 | **自带绝对坐标** | 链式 1 B/条 能省一半，但某条方向错会**静默污染整批** |
| 缓冲深度 | 32 条（RAM 64 B） | 覆盖 14.4 s 搜索 / 4.1 s 冲刺的完全静默 |
| 方向字段 | 不上帧，由坐标差反推 | 免疫掉头/坐标跳变/回绕 |

固件改动面**只在 `REMOTE/`**（采样在 `LINK_Tick`，不动 `utility.c`/`test.c`）
⇒ 比赛档 hex 逐字节不变（已复核）。host API 2.13.0 → 2.14.0。

**为什么需要增量通道**：`MAP DUMP` 是"Flash 存档快照"，实时图进不来（详见
[`迷宫数据回传与重建.md`](迷宫数据回传与重建.md)）。v10 没有去修 `MAP DUMP`，
而是**另开一条增量通道**绕开它。

## 7. LED 状态上报（B1 预留位分配）

统一帧状态字节 B1（载荷偏移 25）原为 bit0 `spurtFlag` / bit1 `goOrBack` / **bit2–7 预留 6 位**。
分配 4 位给 LED（低位连续、留高位扩展）：bit2 LED1(PA8) / bit3 LED2(PC9) / bit4 LED3(PC8) / bit5 LED4。

数据源 = **读 GPIO ODR 再取反**（低电平点亮）。`UNIFIED_CHANNELS` 29 → 33，
`led1..led4` **必须追加在末尾**（否则 RingBuffer/CSV 历史数据错列）。

**后续发现**：FW 313 修过一个"基准灯每 tick 重钉"的缺陷 —— 基准灯只在**电平变化沿**
写 LED4（1 Hz ⇒ "亮"仅 <1 ms），而 `ledBeaconLock` 在远程档无消费者，
`timer.c` 的电池/状态灯每 SysTick 把它写回 ⇒ L2 翻转判据间歇性归零。
**规律：这块板子上想让某个灯表达语义，必须每 tick 重钉。**

## 8. 发车数据空窗（方案 E 已验收，方案 C 冻结）

**症状**：发车时必须先停拉流、让命令走完、再恢复拉流 ⇒ 发车后一段时间收不到数据（旧 440~2430 ms）。

**四层根因**：L1 透传半双工（物理）；L2 `RATE PULL` 一次性批量；
L3 host 等 ACK 才收帧（真痛点）；L4 发车连擦 **6 页** Flash（单 bank F103 从 Flash
取指被 stall，118 ms 级，SysTick 停）。

> 修正一处旧结论：远程档**只擦 6 页不是 7 页** —— `test.c:673` 的 `erase_run_data()`
> 在 `#ifdef FLASHSAVE` 内，而 `FLASHSAVE` 只在 `#ifndef MOUSE_REMOTE` 时定义 ⇒ 远程档不编译。

**方案 E（已落地）**：复合命令 `MAZE RUN [BLIND|RACE] [PULL <n> <t_ms>]` —— 一条命令 =
发车 + 启动**恰好一批** N 帧，省掉"发车后再下 RATE PULL"的一个 RTT。
批次停等模型不变（不自续订、在途 ≤1）。FW 312→313；host 侧配套三态状态机
`IDLE/PENDING/RESETTING`。

**实测**：空窗 440~2430 ms → **157.9 ms**（判据 ≤250 ms）。N=2 六次复测 142~232 ms（中位 155），
与 N=8 同量级 ⇒ **N 只影响上行密度，不影响空窗**。

**方案 C（页间放行）冻结**：空窗模型是 `158 ≈ 118 黑窗 + 40 计时`，两项都占；
只在间隙插延时等于白改（计时被吞），有效形式是"间隙主动泵帧"（≈20~45 ms）。
但 6 处钩子都在 `test.c:671-685` 这段**比赛档共用代码**里，必须逐点门控并重验红线 hex，
而收益只是"发车瞬间的可视性"、250 ms 判据已满足 ⇒ 维持冻结。

## 9. 两个已修复缺陷的取证

**USART1 NVIC 未使能**：烧录成功但串口全静默。根因是 `LINK_Init` 没显式写
`NVIC->ISER`（USART1 的 ISER 位）。修复后 `host/basic_cmd_smoke.py` 端到端通过。
判静默要先区分三种：NVIC 漏配 / 上电陀螺标定阻塞（车不静止永久自旋）/ 透传模块被灌满。

**`ERR_ESTOP` 死锁**：`setvl/setvr` 绝不能回写。收车定式 `force_idle()`：
`MAZE STOP` → `ESTOP` → `RESET`。
