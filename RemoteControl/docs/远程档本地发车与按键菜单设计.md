# 远程档本地发车与按键菜单 —— 现状确认与设计方案

> 目标：远程档（`-D MOUSE_REMOTE`）恢复**按键控制**与**右前红外手势发车**。
> - **红外手势发车**：要求远程链路全程在线（帧率不降、ACK 照回、`MAZE STOP` 可中止）。
> - **按键菜单**：直接复用现有比赛档那一套，**不要求远程可控**，进菜单后按不通就复位。
>
> 基线：PROTO 10 / FW 314 / host API 2.14.0；远程档 ROM 96808 / RAM 13568。
> 修订：2026-10-27 第二版（按用户决定推翻第一版的"有界菜单"路线）。

---

## 一、现状确认（行号均为当前代码）

### 1.1 WAIT 值守循环（`USER/test.c:303-320`）

	sleepmode=0;         /* 312 */

#endif
	freemode=0;                               /* 376 */
	switch(keyfunc) { ... }                    /* 378-659 */

- 只等上位机 `MAZE RUN`，**不看按键、不看红外**。
- 循环周期 500 ms（两次 `delay_ms(250)`），按键采样率远不够做菜单（原菜单需要 5 ms 级）。
- `freemode=1 / sleepmode=0 / irswitch=1` 是待命态安全设置，**必须保留**（见 §二 C3）。

## 二、四条硬约束

### C1 红外发车必须在 WAIT 判，且**必须消费 `linkMazeReq`**

原闸留在 `maze_run` 里就是 §1.3 的死锁。放到 WAIT 后，循环体每 10 ms 判一次
`LINK_MazeRequested()`，请求一到位立即 `break` 走远程路径 ⇒ 不存在"req 挂着没人管"。

### C2 远程"不断开"靠的是 SysTick，不是靠主循环

`delay_ms()` 是 **SysTick 忙等**，`LINK_Tick()` 在 `SysTick_Handler` 末尾照常抢占
⇒ 值守循环里 `delay_ms(10)` 期间：组帧 40 ms 不变、下行命令照收、ACK 照回。
所以**红外等待期间远程链路天然在线**，帧率不降。10 ms 节拍影响的只是
`linkMazeReq` 的**消费延迟**（≤10 ms，而 `MAZE RUN` 本身就要 200~350 ms 才真正起步）。

### C3 本地发车必须置 `linkMazeRun`

只 `goto maze_run` 而不动链路状态会坏三件事：
1. host 的 `running_now()` 判为待命 ⇒ 收车网 `force_idle()` 不升级；
2. `link.c:3655` 的 2 s 软复位兜底条件不成立；
3. 忙判据全 0 ⇒ host 能在本地跑位途中再发 `MAZE RUN` 打断/重入。

⇒ 本地发车走与 `MAZE RUN` **同一段受理内核**，并置 `linkMazeRun`。

### C4 `sleepmode` 必须保持 0、`irswitch` 保持 1

`sleepmode=1` 会让 `getdistance()` 停摆 ⇒ `disf2` 变陈旧 ⇒ 红外手势永远不触发。
菜单里 `case 1/2/7/8/default` 都设 `sleepmode=1`，所以 **每次回到 `fuction_Choose` 必须重设这三行**
（现 311-313 那三行要从 `#ifdef` 里挪出来，供两档共用）。

## 三、设计方案

### 3.1 链路侧：抽出受理内核 + 新增本地发车入口

`REMOTE/link.c`，全部在 `#ifdef MOUSE_REMOTE` 内：

```c
/* 发车受理内核：远程 MAZE RUN 与本地(红外)发车共用。
 * 返回 0=受理 / 1=忙 / 2=急停锁存。
 * ※ 不含 PULL 复合命令 —— 那个只对远程路径有意义，留在 MAZE RUN 分支里。 */
static u8 link_MazeAccept(u8 target)
{
	if (linkMazeReq || linkMazeRun) return 1;
	if (linkEStop)                  return 2;

	linkMazeTarget = target;
	linkMazeReq    = 1;   /* 让 main() 的消费边沿照旧生效；本地路径由 main 立即消费 */
	linkMazeRun    = 1;   /* ★ 本地/远程一律置位：host 侧行为完全同构 */
	link_MapReset();      /* v10 建图增量环 + resync */
	LED1 = 0; LED2 = 0; LED3 = 0; LED4 = 0;
	linkLaunchMarkEnd = linkTimeMs + LINK_LAUNCH_MARK_MS;
	return 0;
}

/* main() 在 WAIT 值守态检测到红外手势后调用 */
u8 LINK_MazeLaunchLocal(u8 target) { return link_MazeAccept(target); }
```

`MAZE RUN` 分支（2972-3048）改为：

```c
			linkMazeTarget = LINK_MAZE_BLIND;
			if (link_TokIs(&p, "RACE"))       linkMazeTarget = LINK_MAZE_RACE;
			else if (link_TokIs(&p, "BLIND")) linkMazeTarget = LINK_MAZE_BLIND;

			switch (link_MazeAccept(linkMazeTarget))
			{
				case 1: link_Ack(seq, "ERR_BUSY");  return;
				case 2: link_Ack(seq, "ERR_ESTOP"); return;
			}
			/* ↓ PULL 复合命令原样保留在此 */
			if (link_TokIs(&p, "PULL")) { ...不动... }
			link_Ack(seq, "OK");
			return;
```

`link.h` 增加（门控）：

```c
#ifdef MOUSE_REMOTE
u8 LINK_MazeLaunchLocal(u8 target);   /* 0=受理 1=忙 2=急停 */
#endif
```

要点：
- 本地路径置 `linkMazeReq=1` 是刻意的 —— 让 `LINK_MazeStarted()`（3834）的"消费边沿"语义
  在两条路径上**完全一致**，不出现"本地发车 req 恒 0"的第二种状态。
- `linkLaunchMarkEnd` 与 `link_MapReset()` 两条路径都走 ⇒ 上位机/录像看到的发车时刻一致。

### 3.3 红外手势：`SEEK_FAR → ARMED → LAUNCH`（近→远边沿）

```c
#define IR_ON      20u   /* 沿用原 disf2<20（手/挡板贴脸） */
#define IR_OFF     45u   /* 移开判定，回差 25 防抖 */
#define IR_N        5u   /* 连续 5 tick(5 ms) 才认，滤单点毛刺 */

#define IR_SEEK_FAR 0    /* 必须先看到一次"远"，才有资格武装 */
#define IR_SEEK_NEAR 1   /* 已武装，等贴近 */
#define IR_ARMED    2    /* 已贴近，等移开 => 发车 */
#define IR_LAUNCH   3    /* 一次性：本 tick 请发车 */
```

```c
static void ir_step(void)
{
	switch (irPhase)
	{
	case IR_SEEK_FAR:
		if (disf2 >= IR_OFF) { if (++irFar >= IR_N) { irFar = 0; irPhase = IR_SEEK_NEAR; } }
		else irFar = 0;
		break;
	case IR_SEEK_NEAR:
		if (disf2 < IR_ON)   { if (++irNear >= IR_N) { irNear = 0; irPhase = IR_ARMED; } }
		else irNear = 0;
		break;
	case IR_ARMED:
		if (disf2 >= IR_OFF) { if (++irFar >= IR_N) { irFar = 0; irPhase = IR_LAUNCH; } }
		else irFar = 0;
		break;
	case IR_LAUNCH:
		break;                      /* 由调用处消费 */
	}
}
```

**为什么必须是"近→远"而不是"近就发"**（这是与原逻辑唯一的语义改动）：

| 场景 | 原「近就发」 | 新「近→远」 |
|---|---|---|
| 起跑格三面是墙 / 车头贴墙（`disf2` 恒 <20） | 待命瞬间**自动跑飞** | 停在 `IR_ARMED`，永不发车 ✅ |
| 收车回 WAIT 时手停在车头 | 立刻二次发车（跑飞） | 状态从 `SEEK_FAR` 起，手没移开过 ⇒ 不武装 ✅ |
| 上电时手就在车头 | 上电即发车 | 同上，不武装 ✅（需先移开、再挡、再移开，第一次不触发） |
| 正常使用 | 碰一下就发 | 挡一下再拿开才发 ✅（与人退开的动作同步，车不会撞手） |

`SEEK_FAR` 这一态就是**冷启动保护**，不需要额外计时器：合法性前提是"先确认环境是空的"。

### 3.4 按键菜单：直接复用现有代码 + 一条安全守卫

- 去掉 `#else`，`test.c:322-373` 的 `while(1)` 菜单段**一字不改**，两档共用。
- `switch(keyfunc)`（378-659）**一字不改**，`case 1/2/3/7/8/default` 的 `while(1)` 保留 ——
  用户明确接受"进菜单后不要求远程可控，之后复位即可"。
- ★ **唯一必须改的一行**：远程档下 `case 0` 不能让流程落到跑位段。

  ```c
  	switch(keyfunc)
  	{
  		case 0:
  #ifdef MOUSE_REMOTE
  			/* 远程档守卫: `keyfunc` 初值 0(250), 而"按满 1 s(keydelay==200)"会直接
  			 * break 出菜单 => keyfunc 仍是 0 => 落到 maze_run 段真跑车。
  			 * 但这条路**没走 LINK_MazeStarted**, linkMazeRun 恒 0 =>
  			 *   · host 判待命, 收车网不升级;
  			 *   · 菜单期间若发过 MAZE RUN, linkMazeReq 悬着 => 此后永久 ERR_BUSY;
  			 *   · 2 s 软复位兜底不触发。
  			 * 远程档的本地发车出口只有红外手势(已置 run), 菜单不承担发车职责,
  			 * 故此处回值守。 */
  			goto fuction_Choose;
  #else
  			break;
  #endif
  ```

- 进菜单后链路的真实状态（写进文档避免误解）：**帧照发、ACK 照回**（SysTick 抢占），
  但 `linkMazeReq` 不被消费 ⇒ 菜单期间发的 `MAZE RUN` 会回 OK 却要等出菜单才生效。
  这是"不要求远程可控"的具体含义，不是"串口断了"。

### 3.5 优先级与互斥

```
远程 MAZE RUN  >  红外手势  >  按键菜单
```

- 远程 `MAZE RUN` 到达 ⇒ 下一个 10 ms 节拍即 `break`，手势状态被丢弃。
- 按键按下 ⇒ 跳出值守进菜单；**红外手势在菜单里不生效**（不要求）。
- 本地受理失败（忙 / 急停锁存）⇒ 不起步，LED6 长亮 1 s，回 `IR_SEEK_FAR` 需重做手势。
- 红外发车途中 host 发 `MAZE RUN` ⇒ `ERR_BUSY`（**正确行为**，证明 `linkMazeRun` 已置）。
- 红外发车途中 host 发 `MAZE STOP` ⇒ 走既有 abort 路径（与发车来源无关，天然有效）。

### 3.6 红线与预算（实测值）

- 全部改动在 `#ifdef MOUSE_REMOTE` 内（`test.c` 值守段 + `ir_step()`；`link.c` 两个函数）。
  `test.c` 的 `freemode/sleepmode/irswitch` **留在门控内**（见 §3.2 的 ★★ 说明）。
- 红线实测：比赛档全量重编后 hex = `68ad6be2…8141`，**逐字节不变**，ROM 82040 / RAM 20480。
- 远程档实测：ROM 97352 → **101184 B**（+3832）/ RAM 13640 → **13648 B**（+8）。

  ROM 增量**远大于**第一版预估的 +200~300 B，原因不是状态机：`ir_step()` + `link_MazeAccept()`
  合计约 300 B，剩下 **~3.5 KB 是原 `switch(keyfunc)` 菜单段**（8 个 case 的标定/走马灯/

## 六、定稿决定（不再是待拍板项）

| 项 | 决定 | 依据 |
|---|---|---|
| 红外触发形式 | **近→远边沿**（`SEEK_FAR → ARMED → LAUNCH`） | 用户："检测到近距离移开后发车"；同时天然规避贴墙/手没拿开两种误发 |
| 菜单实现 | **直接复用现有 `while(1)` + `switch(keyfunc)`** | 用户："直接转到现有的就可以，这部分不要求远程控制，之后复位即可" |
| 菜单里是否加远程轮询 | **不加** | 同上；仅在值守态保证远程在线 |
| `case 0` 落到跑位 | **远程档改为回值守** | 否则车跑了但 `linkMazeRun=0`，host 不知情且 `linkMazeReq` 悬空导致永久 `ERR_BUSY` |
| 本地发车上报来源（flags 位） | **本次不做** | 非必需；红外是唯一本地上车出口，LED 与 `task` 已足够区分 |
