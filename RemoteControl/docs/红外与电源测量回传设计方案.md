## 1. 现状核查结论（实施前的问题）

**提问**：现在版本的代码是否无法进行「红外测距」与「电源电平」相关参数的回传？

**结论：分两句，都不是简单的是或否。**

### 1.1 「电源电平」—— 帧里有，但**比赛固件下恒为 0，且信息不完整**

| 事实 | 证据 |
|---|---|
| 电压**已经**在回传：快帧 1B @0.1V、慢帧 s16 @0.01V | `link.c:1026`；`link.c:1072`；`codec.py:183,232` |
| 采样在 1ms 中断里，**1 kHz** | `isr.c:908` → `safety.c:24` `SAFETY_Monitor()` |
| **但** `battMon.enabled` 只有测试档/数据档和 `LESSON_Cali5` 打开 | `main.c:125`（[1][2][3]）、`main.c:152`（[4]）、`lesson.c:350` |
| **比赛固件（第 5 档）从不打开** → 上位机永远显示 0.00 V | `main.c:122-124` 注释原文即写明这一点 |
| 回传速率：快帧默认 5 Hz（0.1 V 分辨率）、慢帧 **0.5 Hz**（0.01 V） | `link.c:38,53` |
| **没有**电量档 `percent`(1–8)、低电标志 | 结构体有 `core.h:322-330`，帧里没有 |
| **没有**电池 ADC 原始值、没有分压系数 | `ADC_BATTARY` 仅 `safety.c:40` 用一次 |
| 分压比 3、参考 3.3 V、低电 700、步进 12、档位 1–8 **全部写死** | `safety.c:40-46` |

### 1.2 「红外测距」—— 帧里有 mm 值，但**速率与信息量不足以做"测距"**

| 事实 | 证据 |
|---|---|
| 4 路距离（f1/f2/l/r，查表后的 **mm 索引**）已经在慢帧里 | `link.c:1054-1057`；`codec.py:212-235` |
| 采样在 1 kHz（`doWallDetect()` 每 1 ms） | `isr.c:777` → `isr.c:667` → `irs.c:119` |
| **但慢帧只有 0.5 Hz** → 2 秒才回 1 个点，1 kHz 里 **丢 1999/2000** | `link.c:53` `LINK_SLOW_DIV 2000` |
| **原始 ADC / 卡尔曼后的 ADC 完全不上行** | `irs.c:164-168,208-212` 只把查表**索引**写进 `irDist` |
| 值域被表长钳死：表 250 点，`<data[0]`→0，`<data[248]`→249 | `irs.c:31-63,18-21` |
| 前方综合距离 `irDist.f` **不上行** | `isr.c:668` 计算，帧里没有 |
| `irDist.l45 / r45` 等 12 个字段是**死字段** | `isr.c:663-666`；`core.h:165-180`；侧墙 45° 判定实际复用 `irDist.l/r`（`isr.c:693-698`） |
| 没有峰值/极值/饱和统计 | 仅 `MOVEDONE RUN` 附一次 `ir_min` |
| **红外标定表不可读** | 参数命名空间内无任何 IR 项 |
| 阈值全部写死 | `core.h:12-18`：160/150/60/230/240/245/80 |

### 1.3 「参数回传」这一层：两类的确一个都没有

参数命名空间原共 21 项（生产 1–7 + 课程 8–21），**红外测距与电源电平相关：0 项**。

> 另有一处独立缺陷（与本方案正交，仍未修）：固件 `GET ALL` 只遍历 `LINK_P_NUM`，
> `GET <name>` 只查生产表（`link.c:1983,1994-2015`），课程 14 项读不回来。
> 本方案新增的 17 项是**生产命名空间**，因此不受该缺陷影响。

### 1.4 一句话总结

原状态是"**有数据但不合用**"：红外 0.5 Hz / 无原始 ADC / 无饱和标志 / 无法标定；
电压在比赛固件恒 0、无电量档、分压系数写死；两者都不在参数体系内。
本方案的目标是把它们变成**可确认、可标定、可记录、可分析**。

### 2.2 回传通道 ①：`SNAP` 阻塞式测量快照（D2 / D4）

```
下行  SNAP [MOTION|ODOM|SENSE|POWER|TIME|ALL]        (无参数 = ALL)
上行  SNAP MOTION <speedL> <speedR> <tgtL> <tgtR> <pidErr> <pwmL> <pwmR> <gyroAngle> <task> <flags>
      SNAP ODOM   <cellOdom> <trackL> <trackR> <gyroRaw> <gyroDiff> <encAngle> <gyroBias> <angleAbs>
      SNAP SENSE  <adcF1> <adcF2> <adcL> <adcR> <irF1> <irF2> <irL> <irR> <irF>
                  <irSat> <wallBits> <posX> <posY> <mouseTask> <irSwitch> <wallThresh>
      SNAP POWER  <adcBatt> <battMv> <battPct> <battLow> <battEnabled> <cpu> <drop> <emergActive> <emergCounter>
      SNAP TIME   <upMs> <armMs> <devMs> <armed> <mazeRun> <led> <streamOn>
      ACK <seq> OK
```

**设计要点**

- **不依赖 `STREAM ON`**：走命令/应答通道，因此**上电默认静默时也能问**，且零常驻带宽。
  这解决了"只想确认当前值却必须先开流"的别扭。
- **字段名与既有帧解码字典同名**（`decode_fast/mid/slow`），所以 `monitor`/`analyze`
  可以直接复用字段，不需要为 SNAP 单开一条显示分支（`SnapAPI.as_frames()` 做映射）。
- **`irSat`**：4 通道 × 2 bit（bit0-1=F1, bit2-3=F2, bit4-5=L, bit6-7=R），
  取值 `0` 正常 / `1` 近端饱和（`adc > tbl[0]`，查表返回 0mm）/ `2` 远端超量程
  （`adc < tbl[248]`，返回 249mm）。判据与 `IR_FindDis()` **同源**，
  由 `link_IrSat()` 在应答时现算 —— 因此 **`irs.c` 一行未改**。
- **TX 空间门**：`link_TxStr()` 走的是 `link_TxPut()`，**不做空间检查**
  （对比 `link_SendFrame` 在 `link.c:395` 有检查）。一条完整快照 ≈250B，
  在 dump 期间（`FLAG_DUMPING`）TX 环可能接近满，强行写会**回绕覆盖尚未发出的数据**。
  因此处理开头加 `if (link_TxSpace() < LINK_SNAP_NEED_SPACE(320)) → ERR_BUSY`，
  上位机把 `ERR_BUSY` 当"本轮跳过"，不重试不报警。
  **配套把 TX 环从 256B 提到 512B**（+256B RAM），否则 250B 快照基本塞不进去。

**上位机 `mc.snap`**（`host/host/api/snap.py`）

| 方法 | 作用 |
|---|---|
| `read(domains=None, timeout=3.0)` | **阻塞**取一次；先清缓存再发命令、等读取线程填缓存（与 `params.get_raw()` 同构，保证拿到的是本次回话） |
| `read_flat()` | 同上但把所有域并成一个 dict |
| `latest()` / `age_ms()` | 本地缓存（不发命令）/ 缓存年龄 |
| `poll(hz, dur, domains, on_sample, stop)` | 按频率轮询，**纯主机侧定时器**，固件无需知道 |
| `as_frames()` | 映射成 `{fast, mid, slow, time}` 视角（并补 `volt` 派生键） |
| `ir_channels()` | 四路合并视图 `{adc, mm, sat, sat_text, trustworthy}` + `F` 前向综合 |
| `battery()` | `{adc, mv, volt, pct, low, enabled}`；`enabled=0` 时明确区分"没采"而非"没电" |
| `check_battery(low_mv=None)` | 可判定结论（`OK`/`LOW_BATTERY`/`BATT_DISABLED`），阈值默认取固件的 `BATTLOWMV` |
| `explain()` | 人可读多行（CLI / 日志） |

### 2.3 回传通道 ②：`SCOPE` 录制剖面（D3，高分辨率）

`run_data[]` 8B × 1200 = **9600 B**，1 kHz，**一次只录一种**（20KB RAM 装不下 4 通道并行）：

| 剖面 | 8 B/点 | 用途 |
|---|---|---|
| `A`（默认） | motionTask, gangle, speedl, speedr | 运动学，**逐位等于旧行为** |
| `B` | irF1, irF2, irL, irR（各 u16） | **1 kHz 红外测距**（治"只有 0.5Hz"） |
| `C` | adcF1, adcF2, adcL, adcR（各 u16） | 1 kHz 红外原始 ADC（拟合标定曲线的一手数据） |
| `D` | irF, battMv, adcBatt, rsvd | 1 kHz 电压（看电机启停瞬间的跌落/内阻） |
| `E` | irF2, irF1, battMv, motionTask | 混合 |

- 命令：`SCOPE START [A|B|C|D|E]`（无参数 = A，旧语义一字不变）。
- **`DUMP_HDR.channels` 字节兼作剖面标识**：A 仍报 `4`，B..E 报 ASCII `'B'`..`'E'`。
  于是旧的 `channels == 4 → 运动学` 解析路径一行未改，新剖面又能被识别。
- 实现要点：非 A 剖面把 8B 点当 **4 个 u16** 写（`run_data[]` 元素只含 s16，
  结构体按 2 字节对齐，Cortex-M3 上按 u16 访问安全）。
- 上位机：`mc.scope.start(profile)` / `profile()` / `profile_channels()` / `last_data()` /
  `fetch_data(profile, collect_s)`；剖面 A 的 `fetch()` 与 `dump_arrays()` 保持原样。
- `decode_dump_blk()` **双解**：`records`（旧语义，剖面 A 的消费方零改动）+ `words`（原始 4×u16）。
- 落盘按剖面写表头（`session.open_dump()` → `dump_meas_<剖面>_*.csv`），
  否则红外波形会被贴上 `speedl` 表头 —— 数据看起来对、含义全错。

### 2.4 数据完整性与时间对齐

`SNAP` 带完整 `upMs`（比帧里的低 8 位更强）；剖面 B–E 的 dump 复用
`DUMP_HDR.startMs`（`t = startMs + i`），与 `ARM` 发车时刻、1Hz 基准灯**同一时基**；
链路丢帧仍由既有 SEQ 间隙统计（`seq_gap`/`seq_lost`）量化。

| V10 | 双流不退化 | dump ≈7 s；实时流 ~172 B/s | ✅ dump ~8 s/次；实时流实测 192 B/s，`bad_crc=0 seq_lost=0` |
| V11 | 轮询健壮性 | `SNAP` 多次问答稳定 | ✅ 全程 `timeouts=0`（修 1.5.1 的 0.5 s 超时后） |
| V12 | 零回归 | 九套件全绿 | ✅ 本方案落地时 553 项；当前 667 项 |

**交叉验证**（同一个物理量走两条独立路径得到一致结果，这是可信度的关键）：
- 剖面 B 的 1 kHz `irF1=249 / irF2=248..249 / irL=34 / irR=24` **与 `SNAP` 的瞬时读数完全一致**；
- 剖面 D 的 `distF=248..249` 正好等于 `(irF1+irF2)/2` → **`IRFRONTMODE=0`（均值）算法正确**；
- 剖面 C 的 `adcF1=1..4`（极低）与 `sat=2`（远端超量程）**互相印证**；
- `SNAP` 的 `battMv=7154` 与剖面 D 的 1 kHz `7107..7111` 同量级（差异来自 IIR 滤波与采样时刻）。

### 3.3 真机联调暴露的两个问题（已在 v1.5.1 修复）

**都是模拟器不会复现的**，只在真机的"高延迟 + 单一 DMA 通道"下才出现：

1. **链路往返延迟 221 ms ≥ 主机的 200 ms 命令超时** → 每条命令重发 1~4 次，
   运气差时报 `TIMEOUT`（即使设备已执行）。修复：`TIMEOUT_S` 0.20 → **0.50 s**。
2. **`SCOPE DUMP` 的 ACK 被 dump 大帧挤后约 1 s**（两者共用 TX 环 + DMA1_Channel4，
   而 `link_DumpService()` 只在环空且 DMA 空闲时才发起下一块）→ `fetch()` 误判失败。
   修复：上位机 `fetch()` 对 `TIMEOUT` 不再放弃、改为等 `DUMP_DONE`；
   固件把 `link_Ack()` 提到 `link_StartDump()` 之前（**已编译，待烧录**）。

详细证据（原始字节流 + 时刻戳）见 `docs/CHANGELOG.md` 的 `[1.5.1]`。

## 4. 未做项（明确记录）

1. **急停三阈值未参数化**（`EMERGIPWM`/`EMERGCNT`/`EMERGSPD`）：

   本方案新增参数不受影响。

## 5. 待你拍板的小项（不影响本次已实现范围）

1. **`BATTKV` 默认值**：2417 µV/LSB 是按"3.3V × 3 倍分压 ÷ 4096"**推算**的。
   真机上应先用万用表 vs `SNAP` 的 `adcBatt` 反算实测值，再 `SETQ BATTLOWMV/BATTKV` 落盘。
2. **`IRKALQ/IRKALP` 的表示**：现用"1e-4 整数比例"（存 100 = 0.0100，**精确无量化噪声**）。
   若希望与其它参数统一成 Q16.16，可以说一声 —— 代价是 0.01 会变成 0.0099945。
3. **剖面 `E`（混合）是否保留**：若红外与电压从不需要同时看，可砍掉以省一处解析分支。
4. **前墙 4 个阈值是否全暴露**：现全暴露（25–28）；也可只留 `IRTHRFNEAR` + 一个"远距总开关"。
