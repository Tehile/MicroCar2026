## 1. 一句话结论

**课件里的实验代码与最终交付代码是分开的。**

- 全部课程调参逻辑集中在 `APP/lesson_lab.c`，整体被 `#ifdef MOUSE_LESSON_LAB` 包住；
  生产/比赛固件里**一个字节都不占**（`fromelf` 实测：只定义模式宏时 `LESSONLAB_*` 全部存在；
  注释掉后 `MENU_Run`/`STATE_MainLoop`/`doTask*` 全部回来、`LESSONLAB_*` 一个不剩）。
- 课程参量单独落在 Flash 的 **page100**，与生产标定页（page99）**互不覆盖**。
- 参数命名空间也分开：生产标定用 id 1–7，课程调参用 id 8–21。
- 上位机侧集中在 `host/host/api/lesson.py` + `host/host/lesson.py`。

**停止判定与剖面推进全在固件的 1 ms 引擎里**（`LESSONLAB_Tick`），上位机只负责"设参 / 启停 / 算参"。
所以上位机被 kill、蓝牙掉线，实验照样会按每实验自带的时间护栏停下来 —— 与电机远程控制实验同一条可靠原则。

## 2. 五档模式开关

`code_stm32f1_mouse/USER/main.h` 顶部现在是**五档（五选一）**（本文后续又添了数据收集档，见
`docs/数据收集与时间同步.md`）：

```c
/* #define MOUSE_TEST_NO_MOTOR 1 */   /* [1] 安全测试模式(电机物理禁用) —— 静态标定/回传 */
/* #define MOUSE_TEST_MOTOR_LAB 1 */  /* [2] 电机远程控制实验(电机可控 + 双护栏) */
#define MOUSE_LESSON_LAB 1            /* [3] 课程调参实验(本阶段 ← 当前) */
/* #define MOUSE_DATA_LOG 1 */        /* [4] 数据收集档(含自走策略 + 远程发车) */
/* 四个都注释掉 */                    /* [5] 原比赛固件(自走 / 按键菜单 / 课程实验) */
```

- 四者**互斥**，同时定义两个以上会 `#error`；**[1][2][3] 任一被定义即派生 `MOUSE_TEST_MODE`**。
- **[3] 与 [2] 的区别**：两者电机都**可控**（走正常 PWM 闭环），但
  - [2] 只有显式命令 `MOVE RUN/FWD/ROT` 能驱动，**没有实验剖面**；
  - [3] 多了一层"按课件剖面自动跑"的引擎，且电机六增益变成**运行时变量**（可在线调），
    而 [2] / [4] / [5] 用的是 `motor.h` 里的**编译期红线常量**（数值一字未改）。

| 模式 | 电机 | 自走策略 | 剖面引擎 | 在线调 PID | `MOUSE_TEST_MODE` |
|---|---|---|---|---|---|
| [1] `NO_MOTOR` | 禁用 | 无 | 无 | — | 定义 |
| [2] `MOTOR_LAB` | 可控 | 无 | 无 | 否（红线常量） | 定义 |
| **[3] `LESSON_LAB`** | **可控** | **无** | **有** | **是** | 定义 |
| [4] `DATA_LOG` | 可控 | **有** | 无 | 否 | **不定义** |
| [5] 比赛固件 | 可控 | 有 | 无 | 否 | 不定义 |

> **要跑课程实验，固件必须是 [3]。** 若烧的是 [1]，上位机会立刻返回 `MOTOR_DISABLED`（不空等，见 §5.4）。
> **[4] 是唯一不定义 `MOUSE_TEST_MODE` 的档** —— 它就是要跑自走策略，这正是它与前三档的本质差别。

### 3.2 命令组：`LESSON`

```text
LESSON START <exp> [a] [b] [c] [d] [#seq] *CRC16   →  ACK <seq> OK | ERR_*
LESSON STOP                                        →  ACK <seq> OK
LESSON STATUS                                      →  LESSON STATUS <exp> <running>  + ACK <seq> OK
```

`ERR_*` 取值：

| 码 | 含义 |
|---|---|
| `ERR_ESTOP` | 设备处于急停锁存（先 `STOP` 解锁） |
| `ERR_BUSY` | 已有实验在跑（或 `MOVE RUN` 正在跑） |
| `ERR_VALUE` | 参数越界 / 缺失（见各实验校验） |
| `ERR_EXP` | 实验号不支持（如 4/7/8） |

参数含义**随实验号而定**（同一位置在不同实验里意义不同 —— 这是为了让命令短）：

| exp | 课件 | a | b | c | d |
|---|---|---|---|---|---|
| **2** | 实验三 编码器测距 | v (cm/s) | dist (mm) | ms（护栏） | — |
| **3** | 实验四 匀变速直线 | v (cm/s) | t_acc (ms) | t_cruise (ms) | t_dec (ms) |
| **5** | 实验六 陀螺标定 | angle (度) | v (cm/s) | ms（护栏） | — |
| **6** | 实验七 多传感器直行 | v (cm/s) | dist (mm) | ms（护栏） | — |

各实验的校验（与固件 `LESSONLAB_Start` 一致）：

- **2/6**：`0 < v ≤ 300`、`dist > 0`、`ms > 0`；
- **3**：`0 < v ≤ 300`、`t_acc ≥ 0`、`t_cruise ≥ 0`、`t_dec ≥ 0`，且 **`t_acc`、`t_dec` 不得为 0**
  （否则不是阶跃实验）；内部护栏自动设为 `t_acc+t_cruise+t_dec+500 ms`；
- **5**：`angle ≠ 0 且 |angle| ≤ 3600`、`0 < v ≤ 300`、`ms > 0`；启动时 `MOTION_SetAngle(0)` 把姿态清零；
- **4（红外）/7（转向）**：`ERR_EXP` —— 红外标定走既有 `CAL IRDATA` 四步（见 §6），转向搜索数组是 `const`，未纳入在线调参。

### 3.3 明细回传：`LESSON DONE`

实验结束时固件上行**一行文本**（异步，不走遥测帧）：

```text
LESSON DONE <exp> <REASON> <ms> <dL> <dR> <vpkL> <vpkR> <angle>
```

| 字段 | 含义 |
|---|---|
| `exp` | 实验号 |
| `REASON` | `DONE`（剖面走完）/ `TIME`（时间护栏）/ `DIST`（到里程）/ `ANGLE`（到角度）/ `IR`（前向撞墙）/ `ESTOP` / `STOP` |
| `ms` | 实际运行时长 |
| `dL` `dR` | 左右轮脉冲计数（**已按当前 `TRACKL/TRACKR` 换算**，是算参直接输入） |
| `vpkL` `vpkR` | 实测速度峰值（"电机真的转了"的证据） |
| `angle` | 结束时航向角读数（实验六回传的"固件自认角度"就在这里） |

**全部为整数**，不含浮点格式化 —— 既避开 C90 的 `snprintf`，也避开中断里的软浮点。

### 3.4 各实验的剖面（`LESSONLAB_Tick`，1 ms 周期）

| exp | 剖面 | 停止判据 | 预期 REASON |
|---|---|---|---|
| 2 | 匀速直行 | 固件**自认**里程 ≥ `dist` | `DIST` |
| 3 | 加速 `t_acc` → 匀速 `t_cruise` → 减速 `t_dec` → 停 | 剖面走完 | `DONE` |
| 5 | 原地转（左右轮反向） | `\|gyroStr.angle\|` ≥ `\|angle\|` | `ANGLE` |
| 6 | 匀速直行 + 红外/陀螺纠偏 | 里程 ≥ `dist` 或前向红外触发 | `DONE` / `IR` |

**通用时间护栏**放在最后统一判定：任何实验 `elapsed ≥ limit` 即停 —— 剖面写错、上位机失联都不会失控。

### 3.5 双流复用

课程实验**直接复用**电机远程控制实验的 1 kHz 环形缓冲与 `SCOPE DUMP` 整块回传：

- 实验一开始就打开本地 1 kHz 采集（**零带宽**）；
- 结束时冻结环并置 `LINK_FLAG_RUNLOG`（快帧 bit7）；
- 之后上位机 `SCOPE DUMP` 整块拉走（固定 20 块 ≈ 9.8 KB，真机约 7 s）。

**运动期间只跑实时流**（≈152 B/s，看"有没有在动"），**停车后整块回传**（看"动得怎么样"）——
与电机实验同一条分时策略，原因见 `docs/电机远程控制与双流传输.md` §4.1 的带宽账。

## 4. 上位机侧

### 4.1 门面 API（`mc.lesson`）

| 方法 | 作用 |
|---|---|
| `params(refresh=True)` | 读 14 个课程参量的当前值 |
| `param_meta()` | 读它们的单位/小数位/说明 |
| `set_params(mapping, readback=True, save=False)` | 批量设参（默认逐项回读校验；`save=True` 再落 Flash） |
| `read_param(name)` | 读单个课程参数 |
| `status()` | 课程实验视角的状态（可否开跑、急停、日志就绪） |
| `start(exp, a, b, c, d)` | **只启动**，不等结果（配合 `stop()` 用） |
| `stop()` | **中止**当前实验 |
| `run(exp, fetch_log=True, realtime_hz=5.0, ..., **kwargs)` | **阻塞**跑完一次完整闭环：开采集 → 启动 → 等 `LESSON DONE` → 冻结 → 回传 → 自动算参 |
| `fetch_log()` | 只回传当前冻结的 1 kHz 日志 |
| `explain(res)` | 把结果整理成人能读的结论 |

`run()` 的 `**kwargs` 按 `LESSON_EXPS[exp].arg_names` 取值，例如 `run(3, v=50, t_acc=200, t_cruise=800, t_dec=200)`。

### 4.2 算参纯函数（可脱离硬件单测）

`host/host/api/lesson.py` 里的"算参"部分**全是纯函数**：

| 函数 | 用途 |
|---|---|
| `theory_track_ratio(线数=256, 轮齿=42, 编码齿=10, 轮径=22)` | 实验三 里程系数**理论值** = 62.2267（课件示例 62.24） |
| `theory_gyro_ratio(灵敏度=0.67, 位数=11, Vref=3300)` | 实验六 角度系数**理论值** = 415.8061（课件示例 415.8） |
| `solve_ratio(current, reading, truth)` | **实验三/六共用**：`新系数 = 旧系数 × 固件读数 / 真实值` |
| `error_ratio(reading, truth)` | 相对误差（%），用于"测距/测角误差 ≤ 3%"验收线 |
| `step_metrics(t, values, steady_frac=0.3, band_pct=5)` | 实验四：σ% / ts / tp / 上升时间 |
| `straightness_metrics(t, spL, spR, gangle)` | 实验七：航向漂移 + 左右轮速度不对称度 |
| `ir_error_stats(measured, truth)` / `pick_best_position` | 实验五：误差统计 + 最优摆位选择 |

**`solve_ratio` 为什么两个实验共用一条公式？** 两个实验方向看起来相反，其实是同一条：

```
实验三(里程): 固件按"它自己算出的"里程停车 → "读数"就是目标值
    solve_ratio(62.24, reading=100, truth=110) -> 56.58     # 读得偏小 => 系数调小
实验六(角度): 命令转 1080 度, 固件报 1091 度, 实际 1080 度
    solve_ratio(415.8, reading=1091, truth=1080) -> 420.03  # 读得偏大 => 系数调大
```

统一规则：**读得偏大就把系数调小，读得偏小就把系数调大**，一步到位（线性标定）。

### 4.3 六个实验怎么落到代码上

| 课件 | 物理量 | 固件参数 | 上位机算参 |
|---|---|---|---|
| 实验三 编码器测距 | 里程系数 `trackRatio` | `TRACKL`/`TRACKR`（生产表，已有） | `theory_track_ratio` + `solve_ratio` |
| 实验四 匀变速直线 | 速度环 PID | `KPL/KIL/KDL`、`KPR/KIR/KDR` | `step_metrics` → σ% / ts / tp |
| 实验五 红外标定 | 红外距离表 | 走既有 `CAL IRDATA` 四步 | `ir_error_stats` + `pick_best_position` |
| 实验六 陀螺标定 | 角度系数 `gyroRatio` | `GYRORATIO`（生产表，已有） | `theory_gyro_ratio` + `solve_ratio` |
| 实验七 多传感器直行 | 红外 P / 陀螺 PD | `IRPL/IRPR`、`GYROP/GYROD`、`SENSORMODE` | `straightness_metrics` |
| 实验八 转向控制 | 转向搜索数组 | —（数组是 `const`，未纳入） | — |

> **注意命名空间的边界**：`TRACKL/TRACKR/GYRORATIO` 是**生产标定参数**（在 page99），
> 不属于课程命名空间。所以算出的修正系数要用 `mc.params.set()` 写回，**不是** `mc.lesson.set_params()`。
> 终端入口 `--apply` 已按命名空间自动分流，学员无需关心。

### 5.4 安全护栏（上位机侧）

- **`mc.motor_disabled`**：安全固件（[1]）为真。`mc.lesson.run()` 会**立即**返回
  `MOTOR_DISABLED`（不空等），并提示改烧 [3]。
- **`mc.estop_locked`**：急停锁存时 `run()` 立即返回 `ESTOP_LOCKED`，提示先 `mc.lab.resume()`。
- **`LESSON` 与 `MOVE` 互斥**：实验在跑时发 `MOVE RUN` 会被拒（`ERR_BUSY`）；反之，`MOVE RUN` 在跑时启动实验也会被拒。
  两者都在写速度目标，必须互斥。
- **`--apply` 按命名空间分流**：课程参量 → `mc.lesson.set_params()`；生产标定 → `mc.params.set()`。
  两套参数在**不同的 Flash 页**（100 / 99），不能混用一个 API。

## 6. 实验五（红外标定）怎么走

红外数据采集**不用** LESSON 引擎，而是复用既有的 `CAL IRDATA` 四步标定
（逐点摆位 → 采样 → 重算表），因为它需要**人工摆位**，不适合"一键跑完"：

```bash
python -m host.cli calib irdata --target COM7        # 4 个摆位逐点采(交互)
python -m host.cli calib irdata --yes                # 不等回车, 连续采 4 点(自动化用)
python -m host.cli save --target COM7                # 落 Flash
```

上位机侧的算参工具（`ir_error_stats` / `pick_best_position`）用于把"测量值 vs 真实值"比出
最大/平均/RMS 误差，并在若干候选摆位里挑综合误差最小的那个 —— 课件强调"不同最优方案可能不同"，
所以本工具**按红外通道分别比**。

## 8. 边界与注意

- **实验四的 σ%/ts/tp 要取末段当稳态**：`step_metrics` 默认取后 30% 为稳态。
  若整段平均，加速段会把"稳态"拉低、超调量虚高。
- **短动作的红外显示为 `—`**：红外只在 0.5 Hz 慢帧上，短于 ~2 s 的动作实时流里可能整轮没刷新到；
  真实最小红外由固件 1 kHz 统计随 `LESSON DONE` 给出。
- **`dump` 耗时与采集点数无关**：固件恒发满 20 块，上位机按 `filled` 截断 —— 0.6 s 与 2 s 的动作
  回传耗时都是 ~7.1 s。
- **实验八（转向控制）未纳入在线调参**：转向搜索数组在源码里是 `const`，要改需改编译期常量。
  如确实需要，可另开一档 `MOUSE_LESSON_LAB` 的扩展项。
- **实验三/六的修正系数写回的是生产参数**（`TRACKL/TRACKR/GYRORATIO`，page99），
  改完若要掉电保持，需 `mc.params.save()`（`--apply --save`）。
