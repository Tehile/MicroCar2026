## 1. 固件：怎么禁用电机

### 1.1 一个开关（五档）

`code_stm32f1_mouse/USER/main.h` 顶部：

```c
#define MOUSE_TEST_NO_MOTOR 1       /* [1] 安全测试模式(电机物理禁用) —— 本文/标定阶段 ← 当前用这个 */
/* #define MOUSE_TEST_MOTOR_LAB 1 */ /* [2] 电机远程控制实验(电机可控 + 双护栏) —— 见另一份文档 */
/* #define MOUSE_LESSON_LAB 1 */    /* [3] 课程调参实验(电机可控 + 课件剖面引擎) —— 见另一份文档 */
/* #define MOUSE_DATA_LOG 1 */      /* [4] 数据收集档(无记忆迷宫 + 运动控制 + 远程发车) —— 见另一份文档 */
/* 四个都注释掉 */                  /* [5] 原比赛固件(自走 / 按键菜单 / 课程实验) */
```

- **[1] 定义** = 安全测试模式（电机不可能转）；**[5] 都不定义** = 原比赛固件；
  > ✅ **五档现均可编译**（2026-10-04 修复）：程序区上限由 88 KB 扩到 **101 KB**，[5] 余 **6696 B**。
  > 做法是把**运行数据录制区**由 page 89 上移到 page 102（它原预留 29 页、实际只用 13 页，
  > 虚设的 16 页还给了程序区），顺带修掉一处真实冲突：链路模块的标定页原先取 page 99，
  > **正落在录制区的擦除范围(89..101)内**，触发一次 `FLASH_EraseRunData()` 就会连标定一起擦掉
  > （已上移到 page 115/116）。**运动/比赛逻辑一行未改**，迷宫/路径/红外/陀螺页地址不变，
  > 故**不需要重新标定**。详见 `docs/比赛固件空间不足诊断与瘦身方案.md` 与 `CHANGELOG [1.5.4]`。
  > 各档 ROM（含迷宫状态机回传后）：[1] 33576 / [2] 34128 / [3] 38640 / [4] 81704 / **[5] 96728 B**。
- **[2] 电机可控**，但驱动它的只有显式命令（`MOVE RUN/FWD/ROT`），且带时间/红外/急停三重护栏。
  用途与文档见 **`docs/电机远程控制与双流传输.md`**。
- **[3] 电机可控**，多一层"按课件剖面自动跑"的引擎（实验三~八的调参），
  且电机六增益变成运行时变量。用途与文档见 **`docs/课程调参实验与参数设定.md`**。
- **[4] 与前三档相反**：它**要跑自走策略**（`MOUSE_DATA_LOG` 独自**不**派生 `MOUSE_TEST_MODE`），
  用途与文档见 **`docs/数据收集与时间同步.md`**。
- **四个宏互斥**，同时定义两个以上会 `#error`；[1][2][3] 任一被定义即派生 `MOUSE_TEST_MODE`，
  用来包住"无自走策略"的测试分支。**本文只讲 [1]。**
- 其余代码一行都不用动，也不影响原有逻辑。

### 1.2 被停用的东西（4 处）

| 位置 | 改动 | 效果 |
|---|---|---|
| `motor.c` `MOTOR_PwmInit()` | 不配置 TIM4 的 CCMR/CCER/CR1，只把 **PB6…PB9 配成普通推挽输出并拉低** | 引脚不再是 PWM 复用功能，硬件上不可能输出 PWM 波形 |
| `motor.c` `MOTOR_LoopControl()` | 直接 `pwmMotorL/R = 0` 并输出 0 后 `return` | 任何路径算出的 PWM 都到不了电机（双保险） |
| `isr.c` `SysTick_Handler()` | `switch (motionCtrl.task)` 整块 + `LESSON_ISR()` 用 `#ifndef` 包住 | 运动状态机与课程实验不执行，速度目标永远是 0 |
| `main.c` `main()` | 跳过 `MENU_Run()`、`STATE_MainLoop()`，进入 `STATE_TestLoop()`（LED 1Hz 心跳） | 不按键等待、不载地图、不跑冲刺；板子安静地只做采集与通信 |

另外还顺手关掉了三个"副作用源"：`speedSt.freemode = 1`（自由模式，电机输出 0）、
`flashSt.flashenable = 0`（不写 Flash，避免覆盖比赛运行数据）、`emergMon.enabled = 0`（无电机，急停无意义）。

> 这三项里只有 `emergMon.enabled` 在 [2] 电机实验模式下**反过来**：那里 `emergMon.enabled = 1`
> —— 有了可动的电机，急停监视才重新有意义。

### 1.3 仍然保留的东西

- 采集：陀螺 `GYRO_Sample` / 里程 `ODOM_Sample` / 墙检测 `doWallDetect` / ADC 电池电压
- 通信：蓝牙遥测上行（快/中/慢帧）、下行命令、远程标定服务 `LINK_Tick()`
- 标定：`CALIB_InitIr()`、红外标定、`CAL` 标定状态机

上位机因此可以照常 `GET/SET/CAL/SCOPE/MAP`，只是没东西会动。

### 1.4 编译验证（Keil 实编，已通过）

```
Program Size: Code=24512  RO-data=456  RW-data=2124  ZI-data=14172
".\Object\Mouse.axf" - 0 Error(s), 77 Warning(s)
ER_IROM1 (ROM) = 24968 B
```

> 77 条告警全部为**既有、与本开关无关**：54 条是 `FLASH_KEY1/2` 宏重定义
> （每编译一个 `.c` 报一次），其余是测试模式下 `doTask*` 系列"声明未引用"
> （策略函数不进固件，正是期望结果）。无新增告警。

安全模式下 ROM 从约 **88 kB 降到 24.4 kB**，原因是链接器把不可达代码整块删掉了 ——
用 `fromelf -s` 核对符号可见：

| 符号 | 安全模式 | 说明 |
|---|---|---|
| `STATE_TestLoop` | ✅ 在 | 测试分支确实被编进去了 |
| `MOTOR_LoopControl` | **0x20 B（32 字节）** | 只有"清零+返回"这么大（原闭环逻辑远大于此） |
| `STATE_MainLoop` / `MENU_Run` / `LESSON_ISR` / `doTaskTurn` / `STATE_LoadMapAndSelectSpeed` | ❌ 已消失 | 策略与运动状态机确实没进固件 |
| `LINK_Tick` / `GYRO_Sample` / `ODOM_Sample` / `doWallDetect` / `CALIB_InitIr` | ✅ 在 | 采集与链路完整保留 |

也就是说，"不会意外启动"不只是运行期的判断，而是**固件里压根没有驱动电机的路径**。

## 2. 上位机：实时数据显示

### 2.1 用法

```bash
cd host

python -m host.monitor                       # 自动挑串口；找不到串口则连模拟器 TCP
python -m host.monitor COM7 --expect-safe    # 指定串口，并核对"电机已禁用"标志
python -m host.monitor tcp://127.0.0.1:5555  # 连模拟器(没有硬件时先验证上位机)
python -m host.monitor replay://sessions/2026-09-27_0151     # 回放历史会话
python -m host.monitor COM7 --record         # 同时把会话落盘到 sessions/
python -m host.monitor COM7 --json --seconds 10              # 每行一条 JSON，给脚本/管道
```

等价写法：`python -m host.cli monitor COM7 --expect-safe`。

**只依赖 `host` 包，不需要 PySide6** —— 没有显示器、走 SSH 也能跑（Qt 界面那套保持不变，装了 PySide6 才用）。

- **链路**：实测吞吐 / 三路帧率 / CRC 丢帧 / 连接状态。这条蓝牙链路可持续吞吐约 152 B/s，

### 2.3 无硬件时的自测

```bash

```

`--safe` 让模拟器置"电机已禁用"位且速度恒 0；`--realistic` 让它按真机的 5/1/0.5 Hz 发帧。

## 3. 标定：安全模式下能做什么、不能做什么

### 3.1 能力边界（重要）

安全模式只切掉了**电机输出**，所以标定被劈成两半：

| 标定项 | 命令 | 安全模式 | 需要什么 | 写哪里 |
|---|---|---|---|---|
| `GYRO` | `CAL GYRO START` | ✅ **可做** | 车**静止** | 直接写 Flash page 127 |
| `WALLDIST` | `CAL WALLDIST START` | ✅ **可做** | 左侧**平行贴墙** | 只进 RAM（`SAVE` 才落 page 115） |
| `IRDATA` | `CAL IRDATA START` + 4×`SAMPLE` | ✅ **可做** | 按 4 个摆位逐点采 | 第 4 点后写 Flash page 123 |
| `GYRORATIO` / `ENCANGLE` | `CAL GYRORATIO START` | ❌ **做不了** | 车要**原地往复转** 0°↔90° 共 900° | RAM（`SAVE` 落 page 115） |
| 里程系数 | `MOVE FWD` 跑直线 | ❌ **做不了** | 车要**跑一段直线** | RAM（`SAVE` 落 page 115） |

后两项失败**不是 bug，是安全模式的定义**：它们的固件侧流程会给速度目标 `±25 cm/s`，
而电机被物理禁用 —— 车不会动，只会在原地等到超时。

### 3.2 所以上位机加了一道前置拦截

以前这种情况会**傻等 90 秒**（角度标定默认超时）然后报 `TIMEOUT`，看起来像"设备没反应"。
现在门面会先读快帧的编译期标志位，**立刻**返回原因：

```python
r = mc.calib.angle()
r.ok      # False
r.status  # "MOTOR_DISABLED"
r.data["hint"]  # "设备运行的是安全测试固件(主开关 MOUSE_TEST_NO_MOTOR=1)……"
```

- 生效范围：`mc.move.forward()` / `mc.move.rotate()` / `mc.calib.angle()` / `mc.move.servo()` / `mc.calib.track()`
- 判断依据：快帧状态位 `LINK_FLAG_MOTOR_OFF`（**编译期**事实的镜像，不是"当前速度恰好为 0"）
- **底层不受限**：`mc.send_cmd(...)` / `mc.calib.step(...)` 照常下发 —— 要单纯验证命令通路时用它们
- 相关属性：`mc.motor_disabled`（`True`/`False`/`None`）、
  `mc.calib.STATIC_ITEMS`、`mc.calib.MOTION_ITEMS`

### 3.3 实机操作（静态三项）

**陀螺零偏**（车放平、静止不动）：

```bash
python -m host.cli calib gyro --target COM7     # 约 1.5s 完成，写 page 127
```

**车心到墙距离**（车左侧平行贴墙）：

```bash
python -m host.cli calib walldist --target COM7
python -m host.cli save --target COM7           # 需要持久化时才写 page 115
```

**红外 8 值**（4 个摆位逐点采，摆好后回车）：

```bash
python -m host.cli calib ir --target COM7
```

> 逐点路径**不会**擦除已探索的迷宫 —— 它只重建红外查表（`link_IrRebuild()`），
> 与教学用的 `CALIB_InitIr()` 是两回事。

**做每一项时都开着一个实时面板**，这是本阶段实时显示的主要用途：

```bash
# 终端 A：盯读数（红外 mm / 电压 / 陀螺角 / 墙位）
python -m host.monitor COM7 --expect-safe
# 终端 B：下命令
python -m host.cli calib ir --target COM7
```

红外标定摆位时，盯 `monitor` 面板的 `左/右/前 f1/f2` 四项读数稳定下来再敲回车，
比"凭手感贴墙"可靠得多。

### 3.4 要标角度/里程系数时

这两项必须让车动。**首选做法是切到 [2] 电机实验模式**（而不是整个切回比赛固件）——
它让电机可控，但**不会引入自走策略**，且保留了时间/红外/急停三重护栏：

1. `main.h` 里把 `#define MOUSE_TEST_NO_MOTOR 1` 注释掉、打开 `#define MOUSE_TEST_MOTOR_LAB 1`
2. Keil 重新编译下载（ROM 约 25 kB；对比 [4] 数据收集档 79 kB、程序区上限 101 kB —— 见上文 [5] 的容量提示）
3. 在**足够长的直线 / 角格**里跑：

   ```bash
   python -m host.cli calib angle --target COM7     # GYRORATIO/ENCANGLE: 往复转, 约 30–90s
   move.forward() 跑直线                            # 里程系数
   ```

   结束后用 `python -m host.cli save --target COM7` 把参数落 Flash page 115。
4. 标完把开关打回 `MOUSE_TEST_NO_MOTOR 1`、重新编译下载。

> 只有当你**确实需要比赛自走逻辑**（按键菜单 / `MENU_Run` / 课程实验）时，才把两个宏都注释掉
> 切到 [3] 比赛固件。
>
> 第 2 步之后电机是**真的会转**的：请确认场地周围无人、车在足够长的直线/角格里。
> 此时也仍可随时用 `python -m host.motor_test COM7 --estop` 急停。

## 4. 建议的现场流程

1. `#define MOUSE_TEST_NO_MOTOR 1` 保持打开，编译下载（电机此时不可能转）。
2. 上位机 `python -m host.monitor COM7 --expect-safe`：
   - 看到 `电机已禁用(安全模式)` → 确认刷的是安全固件；
   - 看到红外/电压/陀螺在刷新 → 传感器正常。
3. 做**静态标定**（`calib gyro` / `calib walldist` / `calib ir`），全程实时面板盯着读数。
   要动的两项（角度/里程系数）见 [3.4](#34-要标角度里程系数时)。
4. 标定结束、要整车跑时：**先确认要哪一档**——
   - 要"能远程发车 + 完整采集"→ 切 **[4] `MOUSE_DATA_LOG`**（推荐，见 `docs/数据收集与时间同步.md`）；
