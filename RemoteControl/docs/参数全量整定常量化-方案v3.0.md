## 1. 「全量整定常量」的边界与枚举

### 1.1 纳入 / 排除规则

**纳入（T = Tunable）** — 同时满足：
1. 文件作用域、**标量**（不是数组/结构体）；
2. 有**字面量或常量表达式**初值，**或**存在 `= 字面量` 形式的整定赋值点；
3. 属于**运动控制 / 感知滤波 / 路径速度**整定域；
4. 值的变化会改变车的实际行为。

**排除（N = Not-a-parameter）**：

| 类别 | 例 | 理由 |
|---|---|---|
| 运行状态 / 计数 / 标志 | `tick/task/step/trackl/freemode/irswitch/gyroinit` | 值随运行变化，不是「设定」 |
| 查表 / 数组 | `queue[50]`、`anglehis[50]`、`InfCorrect[]`、`vouter_search[170]` | 表，另立议题 |
| 任务目标 | `GoalX=7` / `GoalY=7`（`stratagy.c:34-35`；运行期被 Flash/鼠标坐标覆盖） | 每局任务输入，不是整定量 |
| 纯运行时派生 | `InitialSpeed=speed`、`TopSpeed/BottomSpeed`（无初值，由分支选） | 无独立值 |
| 硬件 / 协议常量 | 寄存器值、`FLASH_ADDR_*`、Q16 缩放因子 | 非整定域 |
| 死变量 | `kiturn`（`timer.c:63`，仅定义无任何读写） | 无消费者 |
| 开关型（**待定**） | `kalmanswitch=1`、`EMERGENCYON=1`、`irswitch=1`、`gyroswitch` | 见 §6-Q3 |

### 1.3 赋值点的**三种形态**（决定写回怎么锚）

| 形态 | 含义 | 例 |
|---|---|---|
| `init` | 定义处的编译期初值 | `timer.c:75 double kpl=3,...` |
| `phase` | 某整定函数里按时期设定 | `user.c:80 kpl=13;kil=0.74;kdl=0.9;` |
| `override` | **save → set → restore** 的临时覆盖 | `test.c:847-852`（`LTopSpeed` 存旧值→设 70→还原）；`user.c:847` 同类 |
| （`derived`） | 右值是**表达式**而非常量（`speed_ss=(SpurtAccRatio+0.2)*track;`） | **不算「套」**，登记为「公式消费者」 |

> `override` 是 v2 没有的新形态：它的值**不是参数值**，是调用点临时量。方案里登记为 `kind:"override"`，
> **默认不回写、不参与 1:1 对账**，只用于解释「为什么这个全局量会跳变」。

## 2. 多套建模与命名规范（B2 / B4）

### 2.1 命名：`<参数名>@<时期>`

```
kpl                        # 逻辑参数（基名 = 固件符号名，保大小写）
kpl@init                   # 上电初值            timer.c:75   = 3
kpl@search                 # 搜索期 parameter_search()   user.c:80  = 13
kpl@spurt                  # 冲刺期 parameter_spurt()    user.c:91  = 13
kpl@mirror                 # 远程档镜像          link.c:124   = 10.75   （本轮只登记）
```

> 分隔符待定（§6-Q2）：`@`（可读）/ `__`（C 标识符安全，便于将来生成宏）。

**不变式（写进 `check`）**：
1. 同一 `基名` 的所有套**必须来自同一物理符号**（同名同类型）——`check` 比对 `decl` 类型；
2. 套的**存档集必须覆盖该符号的全部 `phase/init` 赋值点**，缺一个即 `error`（防漏抄，对应 I8/I9）；
3. `derived` 赋值点（右值含变量）**必须**被显式标为 `derived`，否则 `error`。

### 2.2 时期词表（封闭枚举，共 11 项）

| phase id | 含义 | 触发点 |
|---|---|---|
| `init` | 上电初值（编译期初始化式） | `timer.c:45-85`、`utility.c:21/513/524/1229-1268`、`adc.c:144-151` |
| `search` | 搜索期 | `user.c:78-86` `parameter_search()` |
| `spurt` | 冲刺/回程期 | `user.c:89-97` `parameter_spurt()` |

| `spurt.medium` | `spurt(MEDIUM)` | `utility.c:1163-1177` |

## 3. 数据模型 v3

### 3.1 `tools/params/params.competition.json` → `schema_version: 3`

```jsonc
{
  "schema_version": 3,
  "profile": "competition",
  "generated": "2026-10-16T…",
  "firmware": { "redline_sha256": "68ad6be2…", "link_p_num": {"remote":41,"competition":24} },
  "phases": [ {"id":"init","desc":"上电初值（编译期初始化式）"}, … ],
  "groups": [ … ],
  "params": [
    {
      "name": "kpl",
      "group": "motor_pid",
      "ctype": "double",
      "default_phase": "search",          // B5：默认值取 L2（比赛期运行值）
      "sets": [
        {"phase":"init",   "value":"3",     "expr":"3",     "kind":"decl",
         "anchor":{"file":"HARDWARE/TIMER/timer.c","line":75,"sha16":"…"}},
        {"phase":"search", "value":"13",    "expr":"13",    "kind":"assign",
         "anchor":{"file":"USER/user.c","line":80,"sha16":"…"}},
        {"phase":"mirror", "value":"10.75", "expr":"10.75", "kind":"decl",
         "anchor":{"file":"REMOTE/link.c","line":124,"sha16":"…","symbol":"linkMtrKpL"}}
      ],
      "derived":  [ {"file":"…","line":…,"expr":"…"} ],   // 公式赋值点（不写回）
      "overrides":[ {"file":"USER/test.c","line":848,"expr":"70"} ],
      "consumers": [ … ], "doc": …, "notes": […]
    }
  ],
  "gaps": […]
}
```

**与 v2 的差异**

| v2 | v3 |
|---|---|
| 41 项 = 有链路 id 的量 | **≈72 项** = 全量整定常量（**不再要求有 id**） |
| 单值 `fw:{value,anchors}` | **多套** `sets:[{phase,value,expr,anchor}]` |
| 三层不成模型（B 类只是「镜像赢」） | 三层统一进 `sets`（`init`/`search`…/`mirror`），仲裁 A/B/C 降级为**每个套的属性**（§3.2） |
| `store` 单值 | `store` 仍单值，**作用于 `default_phase` 那一套** |
| `policy ∈ {pinned,apply,report}` | 不变；新增 `scope:"all-sets"`（改一处即改全套） |

### 3.2 仲裁的降级（重要）

v2 的 A/B/C 回答的是「**改固件常量会不会被远程层打回**」——那是**远程档**问题（B6 已说本轮不管）。
v3 改为按**每个套**记录两个正交属性：

| 属性 | 取值 | 含义 |
|---|---|---|
| `writable` | `true` | 该点可被工具写回（有稳定锚点 + 唯一值域） |
| `runtime_overwritten_by` | `[]` / `["parameter_search"]` / `["LP_SyncOut"]` … | 运行期会不会被别的写者覆盖（**I12** 的回答） |

A/B/C 三分类**保留在 JSON 里做参考**（自动算），但不再是主模型。

## 4. 写回语义与 B5 验收

### 4.1 「同时修改」= 一个参数的全部套**一次写回**

写回单元 = **参数**（不是一个套）。`apply` 对某参数执行时：
1. 遍历它的 `sets`，逐个用 `patch.set_value(line, symbol, value)` 只切值域；
2. 任一锚点指纹不符 / 单行不唯一 / 形态校验失败 ⇒ **整体放弃该参数**（不半途改一半）；
3. `derived` / `overrides` **永不写回**。

### 4.2 默认值规则（B5）

- 顶层 `value` / `store` 作用于 `default_phase`；
- **`default_phase` 默认 = `search`**（即 L2，比赛档真实运行值）；
- 若某参数无 `search` 套（如 `keep_dis` 只有 `init`/`search`… 均有），退化为 `init`；
- **不统一各套的值**（见 §6-Q1）。

### 4.3 B5 验收流程（**冻结-回写-重编**，可重复执行）

```
0) 冻结比赛固件      git tag  +  记录 USER/TEST.hex 的 sha256
1) 抽取              paramgen.py extract --accept        # JSON ← 源码
2) 回写（零变更）    paramgen.py apply --commit          # 期望：0 行 / 0 文件
3) 核对工作区        git status --porcelain -- code_competition   # 期望：空
4) 双档重编          python build_competition_modes.py   # 比赛档红线必须 PASS
5) 判据              TEST.hex sha256 == 68ad6be2…8141
```

**全部通过 ⇒ 「源码固定 ⇒ 重编二进制不变 ⇒ 行为可重复」被证明。**
任何一步失败 ⇒ 立即 `git checkout -- code_competition` 还原（tag 是二重保险）。

## 6. 待你确认（4 项，确认后即开工）

### Q1〔最关键〕「L1 L2 L3 同时修改」的确切语义

你的原话：「L1 L2 L3 **同时修改**，但是**默认值是 L2**（或 L1，保证比赛固件不动）」

- **读法甲（我推荐）**：多套 = **同一参数在不同时期的值，各自保留**。
  「同时修改」= 工具对某参数执行写回时，**一次写它全部的套**（不遗漏任一层）。
  「默认值 = L2」= JSON 里该参数的**主值**取 `search` 期那套。
  ⇒ 比赛档红线**不动**，多套语义完整。
- **读法乙**：多套 = 同一参数的三个副本，**强制统一成同一值**（`kpl` 变 13 写进 `timer.c:75`）。
  ⇒ **会改比赛档红线**（`timer.c:75` 在 `Target 1` 里），与 B5「比赛固件不动」直接冲突；
  若确要走乙，需要你接受**新基线**（`--no-redline` + 重定 `REDLINE_SHA256`）。

> 请回 **甲 / 乙**。（我按甲起草了全文；若选乙，§3/§4 需重写。）

### Q2 命名分隔符

`kpl@init`（推荐，可读）/ `kpl__init`（C 标识符安全）/ `kpl.init`（点号，与 JSON 路径易混）。

### Q3 「开关型」量算不算整定常量？

`kalmanswitch=1`（`adc.c:151`）、`EMERGENCYON=1`（`timer.c:30`）、`irswitch=1`（`timer.c:96`）、
`gyroswitch`（`timer.c:80`）。它们**改值会改行为**，但语义是「开关」而非「整定值」。
建议：**纳入**，单列 `group: "switch"`，值为布尔。

### Q4 卡尔曼「辅助量」是否纳入？

`adc.c` 的 `f1/covf1`、`f2/covf2`、`l/covl`、`r/covr`（初值 2000.0 / 1.0，4 路共 12 个值位）与
`timer.c:85` 的 `g/covg`。它们是滤波器的**测量/过程方差**，值得固定（可重复性），但现行代码里
`cov` 每 tick 被重写。建议：**纳入**，标记 `runtime_overwritten_by: ["kalman_step"]`。
