### ★ C 档清零——唯一实际行为冲突，已按 3.x 优先落实（甲修法）

- **原病灶**：`link.c:123-126` 镜像静态初值是旧课程值（`10.75/0.55/0.55`、`10.20/0.5/0.5`），
  `LP_SyncIn` 不读 kpl 家族 ⇒ `LP_SyncOut`（原 253–258）每 tick 把旧值写回固件全局 ⇒
  比赛档 `user.c:80-81`（搜索 13/0.74/0.9）、`user.c:91-92`（冲刺 13/0.7/0.8）的阶段调度
  在远程档**全程失效**，`GET` 还返回陈旧静态值。
- **已实施（甲）**：`LP_SyncIn` 增 6 行回显（`linkMtrKpL=kpl; … linkMtrKdR=kdr;`，
  见 `link_port.c:200-212`）⇒ 每 tick 镜像=固件真值，`LP_SyncOut` 原样写回 = 空操作，
  **比赛档阶段调度生效**（与 v3.0 Q1 甲"冲突留比赛档"一致）。
- **新语义**：`GET` 返回固件当前阶段真值；`SETQ` 经同 tick `SyncOut` 落盘生效，
  直到下一次 `parameter_search/parameter_spurt` 调用（阶段切换收回）。
  远程档开机缺省 = 固件启动值 `timer.c:75`（3/2/0.1），不再是旧课程值。
- **工具链联动**：v2 JSON 仲裁自动重算，MKPL 家族 **B→A**（14→20 / 9→3，`check` 恢复 0 error）；
  v3 JSON 仅行号位移（+14），sha16 锚点零变化，`check3` 0/0/0、`apply3` dry-run 0 行/0 文件。
- **乙修法（镜像初值改比赛档搜索值）未采用**：远程锁定一套拿不到冲刺段 13/0.7/0.8，
  且与 Q1 甲"留比赛档"相悖。
