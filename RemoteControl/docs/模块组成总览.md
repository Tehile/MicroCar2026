# RemoteControl · 模块组成总览

> 2026-10-25。回答"这套东西由哪些模块组成、各自负责什么"。
> 对外接口（帧/命令/参数）的权威定义不在这里，看 [`通信协议规格.md`](通信协议规格.md)；
> 历史决策看 [`已落地方案与决策记录.md`](已落地方案与决策记录.md)。

## 1. 一句话定位

给 STM32F103 电脑鼠加一条**双向蓝牙链路**与一整套 PC 工具链，把"调参、标定、监视、复现"
从"串口 printf 肉眼观察"搬到电脑上 —— **不改比赛行为**。

**当前版本**：远程档 `PROTO 10` / `FW 314`，比赛档 `PROTO 5` / `FW 216`，host API 2.14.0。

## 2. 与外部系统的关系

```
    上位机整合层 Control/  (HTTP + 浏览器前端, 独立进程)
              │  依赖 host 的 MouseClient 门面
              ▼
    RemoteControl/host/   (Python 包 + 30 个脚本)
              │  蓝牙 SPP / 串口, 460800, 命令严格停等
              ▼
    code_competition/REMOTE/  (链路层, 只编译进远程档)
              │  读写裸全局量
              ▼
    code_competition/ 比赛代码  (单体 main, 迷宫搜索/冲刺)
```

**底线约束**：两档共用同一份源码，**比赛档产物必须逐字节不变**。
判据是 hex 哈希（比赛档 `68ad6be2…8141`），**不是看代码**。

## 3. 分层拓扑

| 层 | 位置 | 编译条件 | 职责 |
|---|---|---|---|
| 比赛代码 | `code_competition/{USER,STRATAGY,UTILITY,HARDWARE,SYSTEM}` | 两档都编译 | 迷宫搜索/冲刺/控制，本项目**只加可见性不改行为** |
| 链路层 | `code_competition/REMOTE/` | **仅远程档**（整文件 `#ifdef MOUSE_REMOTE`） | 协议引擎 + 平台适配 |
| 上位机 | `host/host/` | — | protocol / transport / model / api / ui / sim |
| 工具链 | `tools/paramgen.py` + `tools/paramkit/` | — | 参数 JSON ⇄ 固件源码双向转换 |
| 构建/归档 | `build_competition_modes.py`、`release/` | — | 双 Target 编译 + 红线校验 + 打包 |

## 4. 固件模块

### 4.1 单工程双 Target

`USER/TEST.uvprojx` 里 Target 1 = 比赛档，Target_Remote = 远程档。
`MOUSE_REMOTE` 由 Keil `-D` 注入，**源码里只有 `#ifdef`**，没有任何 `#define`。
当前档位看 `TEST.uvoptx` 的 `<IsCurrentTarget>`；Target 顺序不可调换（契约测试正则依赖）。

### 4.2 `REMOTE/link.c`（3891 行）—— 协议引擎

与平台无关的那一层：命令解析（token 化 + `link_TokNum`）、CRC16、ACK/幂等重放、
统一帧组帧、建图增量队列 `LinkMapD`、参数表镜像 `linkParam[]`、
`LINK_Tick()`（挂在 SysTick 末尾）、发车复合命令 `MAZE RUN ... PULL n t`。

- **命令在 SysTick ISR 里处理** ⇒ 严禁 `DELAY` / `while` 等待。
- **幂等重放**：同 seq + 同 CRC 只回 ACK、不重复执行 ⇒ 重发安全。
- **建图增量**（v10）：`linkMapD[32]` 环形缓冲，每 tick 采样坐标变化，
  每帧带 3 条 × 2 B（自带绝对坐标，无方向字段）。

### 4.3 `REMOTE/link_port.c`（378 行）—— 平台适配层

把"比赛代码的裸全局量"映射到"链路层的镜像结构体"：

| 函数 | 方向 | 时机 |
|---|---|---|
| `LP_SyncIn()` | 固件全局量 → 镜像（`mazeState` / `irCalib` / `sysCfg` …） | **每 tick** |
| `LP_SyncOut()` | 镜像 → 固件全局量（参数） | 命令处理后按需 |
| `LP_SyncMap()` | `GucMapBlock/GucMapGet` → `mazeState.mapWall/mapVisited` | ⚠️ **无调用点**（见下） |

镜像实例定义在 `link_port.c:36` 起（`MazeState mazeState` 等，**不加 static**，
因为 `link.c` 直接引用这些全局名）。

### 4.4 应用层门控插入

约 10 处 `#ifdef MOUSE_REMOTE` 的 1~3 行插入，分布在 `test.c` / `timer.c` / `led.c` 等，
用于：遥测采样点、LED 语义、发车/收车握手、Flash 写入门控。

## 5. 上位机模块（`host/host/`）

| 子模块 | 文件 | 职责 |
|---|---|---|
| `protocol/` | `codec.py`、`commands.py` | 帧编解码、命令构造（单一登记点） |
| `transport/` | `link.py`、`ports.py` | 串口/蓝牙/模拟器三种传输，字节流收发 |
| `model/` | `ring.py`、`session.py` | 环形缓冲与快照、会话落盘 |
| `api/` | `client.py`（门面）、`maze.py`、`params.py`、`move.py`、`calib.py`、`analyze.py`、`mapd.py`、`lab.py`、`conn.py`、`events.py`、`errors.py`、`calc.py` | 对外能力，`MouseClient` 是唯一门面 |
| `ui/` | `main_window.py`、`maze_view.py`、`status_panel.py`、`param_panel.py`、`calib_wizard.py`、`console.py`、`fetch_panel.py` | PySide6 图形界面 |
| `sim/` | `mouse_sim.py` | 设备模拟器（协议逐字节一致，自带仿真物理） |
| `analysis/` | `metrics.py` | 离线分析指标 |
| 顶层 | `registry.py`（命令/帧/参数**单一登记点**）、`monitor.py`、`cli.py`、`replay.py`、`motor_test.py`、`clock.py`、`datalog.py`、`fwprofile.py` | 登记、终端仪表盘、CLI、回放 |

**关键约定**：新增帧/命令/参数**只改 `registry.py`**，
`contract_test.py` 会机器强制"接口有没有自动覆盖"（当前 278 项全绿）。

## 6. 运行时模型

- **命令严格停等**：在途 ≤1。链路半双工，命令只能在静默期发。
- **host 三态状态机**：`IDLE`（唯一允许发命令）/ `PENDING`（禁发任何字节）/
  `RESETTING`（发 `RATE OFF` 重建静默）。安全命令（`MAZE STOP` / `ESTOP` / `RESET`）**不受三态约束**。
- **收车分级**：`MAZE STOP` → 拉帧验证 `mazeTask/motionTask` 归零 → `ESTOP` → `MCU RESET`。
  **只看 `ACK OK` 不算停住**，必须验证任务真的归零。
- **容量顶**：RTT 恒 300~310 ms（瓶颈在 PC 侧 CH340），帧率 ≈ N/RTT。
  N=5（17 Hz）是安全顶；**N≥6 会把透传模块灌死，须物理断电**。
- **`RATE FIX <hz>` 连续发流是禁手**：十来秒就灌死模块，且取流期间下行命令会被打坏。
  一律用批量下拉 `RATE PULL <n> <t>`。

## 8. 已知接线缺口

**`LP_SyncMap()` 从未被调用。** 它负责把实时墙图 `GucMapBlock` 拷进回传镜像
`mazeState.mapWall`，全仓只有定义、声明和注释，**没有任何调用点**。
⇒ `MAP DUMP` 实际是"Flash 存档快照通道"，拿不到本轮实时探索结果
（详见 [`迷宫数据回传与重建.md`](迷宫数据回传与重建.md)）。
v10 没有去修它，而是**另开建图增量通道**绕开；`MAP LIVE` 至今未实现。
