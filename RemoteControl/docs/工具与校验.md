```bash
python tools/paramgen.py {extract|apply|check|audit|render}{3}
```

## 5. 真机四条铁律

1. **上电前车必须绝对静止。** `hardware_init()` 的陀螺零偏标定是**阻塞死循环**
   （`gyro0==-1` 等 `angle_counter>1000`，一见 `gangle` 变化就清零）。车一动 ⇒ 永久自旋 ⇒
   标定完成前串口全程 0 字节。**症状与 NVIC 故障完全相同，极易误判。**
2. **判状态必须用新鲜帧。** `telemetry.latest()` 是缓存，链路一停就永远停在旧值。
   必须记帧计数 → 发 `TELEM` → 等计数真变。**空帧 ≠ 待命**（空帧意味着链路不通，
   必须按"可能在跑"处理）。刚发过车一律 `assume_busy=True`。
3. **安全出口宁可报失败，绝不谎报成功。** 收车判据 `rst=SW`；
   `force_idle()` 停不住时必须报"未确认待命，请人工断电"。低电闸 `LAUNCH_MIN_MV=7000`。
4. ⚠️ **链路断死时软件收车网完全无效。** 透传模块被灌满时（COM7 能打开但 0 字节），
   `halt()` 的 STOP→ESTOP→RESET 三级**全部 ACK 超时，一条都进不去**，只能人手动停车 + 断电。
   不要写"脚本会兜住"这类假设。

## 6. 判档与排障速查

| 症状 | 先怀疑 |
|---|---|
| `PING` 无 `PONG` | **烧错档**（比赛档无 `LINK_Init`）。判档看 `TEST.uvoptx` `<IsCurrentTarget>`；J-Link 读 Flash 首字：远程档 `0x200034F8` / 比赛档 `0x20005000` |
| 烧录成功但串口全静默 | ① USART1 NVIC 漏配（已修：`LINK_Init` 显式写 ISER）② 上电陀螺标定阻塞 ③ 透传模块被灌满 |
| 有 ACK 无 PONG | **主机侧 USB 首包截断**，不是固件。PONG 与 ACK 同环同一次 DMA，环满只逐字节丢**尾部** ⇒ 只丢前 30 B 必属主机接收侧 |
| 连测后掉线 | 模块灌满（0 字节 + 断电自愈）。**发车批次 `PULL 8 40` 是全程最密突发**（瞬时 200 帧/s），复测一律 `--mark-n 2` |
| 取流期间下发命令被打坏 | 按"**同 seq + 同正文**"重发。固件幂等分支保证同 seq+CRC 只回 ACK、不重复执行 ⇒ 重发安全 |
