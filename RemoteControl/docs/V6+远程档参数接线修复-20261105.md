## 2. 真机证据（修复前）

```
=== 基线 ===
  [base] irL=249 irR=249 irF1=249 irF2=249  wallL=0 wallR=0 wallF=0

=== SETQ IRTHRWALL = 255 ===            ← 真参数
  [THRWALL=255] irL=249 irR=249 ...      wallL=1 wallR=1     ✅ 立刻变
=== 恢复 IRTHRWALL = 130 ===
  [THRWALL=130] ...                      wallL=0 wallR=0     ✅ 立刻变回

=== SETQ IRTHR45 = 255 ===              ← 死参数
  [THR45=255]   ...                      wallL=0 wallR=0     ❌ 毫无变化
   IRTHR45 回读 = 16711680 (=255.0)      ← 存住了、能读回，就是没人用
```

`IRTHR45` 的 `wallL/wallR/wallF` 三个判据一个都不动，即可判定它是纯影子量。

## 3. 根因

`link.c` 的参数表从"镜像结构"取初值：

| 参数 ID | 初值来源 | 镜像结构里的写入者 | 固件里的消费者 |
|---|---|---|---|
| 22 | `wallSns.wallThresh` ← `sidewall_threshold` | `LP_SyncIn`/`LP_SyncOut` | `timer.c:502/504` ✅ |
| 23–28 | `irCfg.thr45` … | **无** | **无** ❌ |
| 29–31 | `irCfg.kalQ/kalP/kalOn` | `LP_SyncOut` 推 `Qf1/Pf1/kalmanswitch` | `timer.c` 卡尔曼 ✅ |
| 32 | `irCfg.frontMode` | 无 | 无 ❌ |
| 33–38 | `powerCfg.*` | 无 | 无（电池走另一套公式）❌ |
| 39 | `sysCfg.trackCoord` | 无 | `trackcoor`（`const`，写不进）❌ |
| 43 | `linkDisF60` | 无 | 无 ❌ |
| 47–49 | `linkPtKp/Ki/Kd` | 无 | 硬编码字面量 `2.5/0.01/0.1` ❌ |

即：`irCfg` / `powerCfg` / `linkPtKp` 这几组是**只写不读的影子参数**，是早期"core.h/safety.c 单真源"架构留下的接口，本工程（V6+，老式固件）根本没有对应实现。

> ⚠️ 顺带排除一个错误怀疑：`LP_SyncOut` 每 1 ms 把镜像写回固件，看似会打回 V6 算法自己的赋值（`sidewall_threshold=160`、`turn_kp=10` 等）。
> 实际不会 —— `LP_SyncIn` 在每个 tick **开头**先把固件值读进镜像，`LP_SyncOut` 在 tick **末尾**写回同值，中间只跑同一 ISR，主循环插不进来，所以是恒等回声。设计是对的。

## 4. 本次修复

### 4.1 手法：`#ifdef MOUSE_REMOTE` 变量 + `#else` 宏

比赛档必须逐字节不变（红线），所以新宿主量只在远程档存在：

```c
#ifdef MOUSE_REMOTE
u16 irThr45 = 150;      /* 可被 SETQ 改写 */
...
#else
#define irThr45 150     /* 比赛档：与改前的字面量 150 完全等价 */
#endif
```

判据处 `if(disl<150)` → `if(disl<irThr45)`：
比赛档预处理后展开回 `150`，**指令逐字节一致**（已用四个 hex 哈希验证）。

### 4.3 前墙 4 个参数怎么映射

原判据有 5 个字面量、4 个参数，映射按语义对齐：

```
(disf1<230 && disf2<245)   ->  (disf1<FLO  && disf2<FMID)
(disf2<240 && disf1<245)   ->  (disf2<FHI  && disf1<FMID)
(disf1<65) || (disf2<65)   ->  (disf1<FNEAR) || (disf2<FNEAR)
```

默认值取原字面量，**行为零变化**。

## 7. 方法论备忘

**"设了没反应"的三段定位法**（本轮验证有效，可复用）：

1. `SETQ` → `GET` **回读一致** ⇒ 存储层没问题（排除协议/CRC/落盘）
2. 挑一个**可观测的输出**（这里是统一帧的 `wallLeft/wallRight/wallFront`），把参数推到极端值看输出翻不翻 ⇒ 判断"有没有消费者"
3. 没有消费者就去固件里找**字面量**：`grep 'disl<150'` 一类，往往能直接定位硬编码判据

不要从 `SETQ` 分支往里查 —— 分支写镜像结构是"看起来完全正确"的代码，问题在镜像**有没有人读**。
