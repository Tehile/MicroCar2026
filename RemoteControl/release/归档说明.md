- **被实机推翻的静态推断**：远程档卡尔曼 Q/P「被清零」不成立（`GET IRKALQ=100/IRKALP=2000`，滤波正常）——
  教训已写进 v2 设计稿与 v3 方案：BSS 裸定义的运行时值必须实测。

## 6. 归档纪律（下次照这个来）

### 6.1 顺序（**别搞反**）

1. **先全绿 + 重编译**（跑十套件、双档编译，记录**真实数字**）；
2. **接口一致性审计**（清点 API/命令/帧/参数；核对 `API_VERSION` 与文档一致）；
3. **修正过期文档**（尤其"当前状态陈述"里的数字；**历史记录不动**）；
4. **写工作记忆**（必须在打包**之前** —— 否则包里的记忆是旧的，v1.4.0 踩过）；
5. **写归档说明**（必须在打包之前）；
6. **打包**（`make_archive.py`）→ **抽查**（`verify_archive.py`：关键文件在、运行现场不在）；
7. **生成 `SHA256SUMS.txt`** → 真的跑一次 `sha256sum -c`，确认**零告警**；
8. **提交**（只 commit 不 push；消息 `[feat] RemoteControl: …`）。

### 6.2 踩过的坑（下次直接避）

| 现象 | 真因 / 对策 |
|---|---|
| 归档脚本自检清单写死已删文件 | 删功能时只改源码，忘了 `make_archive.py`/`verify_archive.py` 的 `must_have` ⇒ 归档必然失败。**删文件要顺手 grep 一遍 `release/`**（本轮 v3.0.0 就踩到：旧清单全是 `code_stm32f1_mouse` 路径） |
| 排除规则误杀交付物 | v3.0.0 打包时「host 顶层 `*.txt` 排除」把 `host/requirements.txt`（依赖清单，交付物）一起误杀——**靠 make_archive 自检的 `must_have` 抓住**（FAIL 退出）。教训：排除规则要配「白名单例外」，且自检必须真跑 |
| 先打包后写记忆 | zip 内记忆是旧的，只能重打（v1.4.0） |
| 文档里一堆旧快照数字 | 归档前必须全局 grep 当前状态陈述；本包所有数字均为 2026-10-16 本轮真跑/机械清点 |
