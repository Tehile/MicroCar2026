## 实际行为

| 搜索动作顺序 | 使用的转弯曲线 |
|---|---|
| 左→右→左 | 原速→90%→90% |
| 右→左→右 | 原速→90%→90% |
| 左→左→左，或右→右→右 | 原速→90%→90% |
| 左→正常直行→右→左 | 原速→原速→90% |
| 掉头后第一次90°转弯 | 原速；终点4mm起步保留 |
| 冲刺，包括V字路局部搜索绕行 | 保留V5原曲线，不启用此次减速 |

“连续”按实际动作衔接判断：上一实际动作是普通搜索90°转弯，期间未执行正常直行或掉头，本次又是90°转弯。弯后仅补足位置或提交坐标，不视为一段正常直行。第一弯仍按V5原速执行。

原代码无墙直行会写入与左转相同的 `LastSearchAction` 数值。V6保留该旧变量的取值及所有距离衔接，另外使用 `v5_diag.reserved` 这一既有保留字节记录是否仍处于连续弯。这样既避免把“直行后再转弯”误判成连续弯，也不会因修正旧动作值而改变原来的转弯时机。

## 速度与角度如何配套

V5实际搜索转弯由195点查表曲线执行，标称中心速度70、外轮峰值109。V6新增只读慢曲线，左右轮速度缩放到90%，角度参考沿原曲线以90%速率推进，起止角度参考保持对应原有执行窗口。

| 项目 | V5原曲线 | V6连续弯慢曲线 |
|---|---:|---:|
| 标称中心速度 | 70 | 63 |
| 外轮前馈峰值 | 109 | 98 |
| 内轮前馈最低值 | 31 | 28 |
| 搜索左转执行周期数 | 189 | 210 |
| 搜索右转执行周期数 | 193 | 215 |

每个受影响的弯名义增加约21～22ms。表中是指令曲线数值；实际轮速会受到闭环纠偏和机械状态影响。

离散重采样模型中，左/右出口位置与原参考曲线的差异分别约0.005mm、0.355mm；这只是按参考角度和标称中心速度积分的结果，没有模拟打滑或控制误差，不能作为实车出口精度保证。

原 `before90turn()`、转弯延迟、距离补偿、坐标更新、普通 `taskturn()`、内外轮原始表和原控制中断均保留。终点4mm起步、无45°冲刺、V字路搜索走法、V5停车快照/停轮复核/掉头前限幅也保留。

慢曲线已预先生成，不在控制中断中进行插值或重采样。`V6_CONTINUOUS_TURN_PERCENT=90`用于标识当前生成表的比例；将来若要改比例，需要配套重新生成轮速与角度表，不能只改这个数字。

## 修改范围与内存

- 现有生产文件只修改 `UTILITY/utility.c`：增加内部曲线选择与执行辅助函数，直行/掉头时结束连续弯状态，左右转弯入口选择原曲线或慢曲线。
- 新增 `UTILITY/search_turn_v6.h`：6份只读表和执行周期常量，表数据共2574字节，放在Flash。
- 原有公共函数、动作编号、路径Flash格式、全局速度/PID/红外标定和所有距离参数保持一致。
- 未新增全局RAM。沿用V5的256字节诊断块、768字节栈和1136条旧行车记录，总RAM仍为20480字节。
- 当前固件最后占用地址0x0801521B，未进入0x08016000起的原数据区。

## 实车验收顺序

1. 先使用默认V6_4mm，与V5使用同一套标定、轮胎清洁状态和地图。确认单独左/右转、到终点后的4mm起步及第一次左转与V5一致。
2. 分别重复左右左、右左右、连续左、连续右，重点观察第二弯及后续弯是否更稳、擦墙是否减少；建议每种结构测试10次。
3. 检查“左→直行→右”和“右→直行→左”：直行后的第一个弯应恢复原速，其后若再次紧接转弯才减速。也检查短位置补偿后的连续弯没有误恢复原速。
4. 复测上次V5已改善的蓝叉/绿叉位置，确认停车复核与原有保护仍正常。若再次保护停车，按V5方法保留 `V5_TRIGGER` / `V5_RECHECK` 文本或读取 `v5_diag`。
5. 搜索稳定后再验证无45°冲刺及V字路绕行，确认本次减速没有进入冲刺阶段。

V6增加了过弯余量，仍应维持轮胎和赛道的日常清洁。若第一弯本身也擦墙，该版本不会降低第一弯速度，应另行讨论普通搜索90°的统一小幅降速。
