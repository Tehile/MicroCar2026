# 会话级接口规范 —— 视频文件处理（v1.2.0 拟）

> 本文档是**对外调用规范**，不是实现文档。
> 对象：**整个视频文件为一次"会话"** 的调用方（PC 上位机 / 手机端离线处理 / 其他程序）。
> 单帧/逐帧的 v1.x 帧级契约见 [docs/API.md](API.md)，**保持不变**；本文档只规范它之上的
> **会话级**输入输出。
>
> 定位：**接口草案（v0）**，供实现与联调用。等测试视频到位后，本规范的字段随实现一起定稿，
> 不另行征求意见（字段只增不减，增补走 CHANGELOG）。

---

## 0. 调用模型（一句话）

调用方传一个**视频文件路径**（+ 可选配置），**阻塞式**拿到三样产物：

```
run_session(video_path, config) →
    1. session.json      ← 会话级结构化结果（唯一权威）
    2. trajectory.csv    ← 逐帧轨迹表（时间轴以发车 t0 为 0）
    3. 图（可选）        ← trajectory.png / maze_structure.png / overlay.mp4
```

**不再承诺实时**：本接口按"离线批处理"设计，调用方不依赖帧率、不依赖流式回调；
全部结果在函数返回时已经落盘。逐帧回调式（`iter_locations`）仍是 v1.x 的帧级接口，两者并存。

## 1. 调用方式

### 1.1 Python 接口（主）

> **当前实现状态（S1+S2 已完成）**：`run_session` 已可用，但以**模块路径**导入：
> `from aruco_locator.session import run_session`。
> 顶层导出（`from aruco_locator import run_session`）随 **v1.2.0** 提供（`__init__.__all__`
> 只增不减地追加），在此之前顶层导入不可用，避免改动 v1.1.0 冻结的 `__all__`。

```python
from aruco_locator import run_session  # v1.2.0 起；当前用 from aruco_locator.session import run_session

result = run_session(
    video_path="run01.mp4",            # 必需：视频文件
    config=None,                       # 可选：None=内置默认；str=YAML 路径；LocatorConfig
    out_dir="output/run01",            # 可选：None=不落盘（只返回对象）
    # —— 以下为"可选覆盖"，全部不传则用 config 里的值 ——
    start_frame=None, end_frame=None,
    start_s=None, end_s=None,          # 时间窗口（与帧窗口二选一）
    stride=1,
    sync_led=None,                     # None=用配置；True/False 强制开关
    max_frames=None,
)

# 返回 SessionResult（见 §2），主要字段：
result.video        # 视频元数据（见 §3.1）
result.sync         # 发车对轴结果（见 §3.2）
result.frames       # 逐帧统计（见 §3.3）
result.trajectory   # 轨迹 DataFrame/表（"t_rel" 见 §3.4）
result.maze         # 迷宫融合结果（见 §3.5）
result.flags        # 会话级标志（见 §6）
```

### 1.2 CLI（批处理入口）

> **当前实现状态**：统一 CLI 参数（`--sync-led` / `--trajectory` / `--session` /
> `--save-maze`）随 v1.2.0 落地；现阶段可用模块入口代替：
> `python -m aruco_locator.session --source run01.mp4 --out output/run01 [--start-s 0 --end-s 60] [--stride 1]`。

```bash
python -m aruco_locator.cli \
  --source run01.mp4 \
  --out output/run01 \
  --sync-led \
  --start-s 0 --end-s 60 \
  --trajectory output/run01/trajectory.csv \
  --session output/run01/session.json \
  [--save-overlay output/run01/overlay.mp4] \
  [--save-maze output/run01/maze_structure.png]
```

CLI 的**逐帧产物**（`results.jsonl` / `results.csv` / `--save-annotated`）保持 v1.x 不变，
是**调试用**；对外消费请用 `session.json` + `trajectory.csv`。

### 1.3 输入约束

| 项 | 约束 |
|---|---|
| 视频路径 | 存在、可解码；`mp4/mov/mkv/avi` 等（与 `VIDEO_EXTS` 一致） |
| 编码 | 任何 OpenCV 能解码的即可；**手机 H.264** 预期可用。若打不开 → `RuntimeError`，`session.json` 不产生 |
| 尺寸 | 不限；性能建议见 §8 |
| 窗口 | `start/end` 用**帧号**或**秒**（二选一，互斥）；默认全片 |
| 配置 | 缺省全部用内置默认（与 `v1.1.0` 行为一致）；`sync.enable` 默认 `false` |

**实时性**：本接口不承诺处理帧率上限；性能目标只是"参考"（见 §8），无硬性 SLA。

> ⚠ **实测必要配置（720p 手机视频）**：1280×720 下角标记仅 10~34px，默认
> `detection.scales=[1.0]` 几乎全灭。需 `config.detection.scales = [1.0, 2.0, 3.0]`
> （多尺度检测，包内已有机制）。三段实测视频均验证有效。

## 2. 返回对象 `SessionResult`

```python
@dataclass
class SessionResult:
    video:      VideoMeta            # §3.1
    sync:       SyncResult | None    # §3.2（sync.enable=false 时为 None）
    frames:     FrameStats           # §3.3
    trajectory: Trajectory           # §3.4（含 .rows / .to_csv() / .to_dicts()）
    maze:       Maze | None          # §3.5（迷宫融合；未开启/无有效帧时为 None）
    flags:      list[str]            # §6

    def to_dict(self) -> dict: ...   # 与 session.json 结构一致
    def save(self, out_dir: str) -> list[str]:
        """落盘 session.json + trajectory.csv（+ 图，按配置），返回写出的路径列表。"""
```

## 3. 数据结构与字段契约

### 3.1 视频元数据 `video`（来自 `preflight`，写进 session.json 的 `video` 键）

| 字段 | 类型 | 说明 |
|---|---|---|
| `path` | str | 输入视频绝对/相对路径 |
| `frames` | int | 容器声明的帧数 |
| `fps_declared` | float | 容器声明的帧率 |
| `duration_s` | float | 帧数 / fps（容器声明） |
| `width` / `height` | int | 帧尺寸 |
| `fourcc` / `backend` | str | 编码 / 解码后端 |
| `size_bytes` | int | 文件字节数 |
| `timestamp_source` | str | `container_pts` \| `frame_index_over_fps`（时基来源，见 §4） |
| `vfr_suspected` | bool | 帧间隔标准差超阈值 → True（见 §4） |
| `orientation` | str | `landscape` \| `portrait` \| `unknown`（旋转元数据判定） |

### 3.2 发车对轴 `sync`（`sync.enable=true` 时，写进 `sync` 键）

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | bool | 本次是否实际启用 |
| `onset_frame` | int | 检出的点亮起始帧号 |
| `onset_time_video_s` | float | 该帧的视频绝对时间（时基来源见 §4） |
| `subframe_offset_s` | float | 亚帧插值偏移（0 表示未启用/无法插值） |
| `confidence` | float | 0..1，判定置信度（几何+能量联合） |
| `n_led` | int | 确认到的 LED 颗数（预期 4） |
| `t0_mode` | str | `first_lit` \| `all_lit` \| `stable`（配置决定） |
| `t0_abs_s` | float | **发车时刻（绝对）** = onset_time + subframe_offset |
| `flags` | list[str] | `led_partial` / `led_subframe_estimate` / `led_ambiguous` … |

> **对调用方最重要的一个数**：`t0_abs_s`。轨迹时间轴 `t_rel = t_video − t0_abs_s`。

### 3.3 逐帧统计 `frames`

| 字段 | 类型 | 说明 |
|---|---|---|
| `n_total` | int | 处理帧数（受窗口限制） |
| `n_valid` | int | 有效帧数 |
| `valid_ratio` | float | n_valid / n_total |
| `n_invalid` | int | 无效帧数 |
| `invalid_reasons` | dict[str,int] | reason 计数（如 `corner_markers_missing`） |
| `rms_field` | dict | `{"mean","median","p95","max"}`（场地单位） |
| `pos_noise_est` | dict | 轨迹抖动估计（差分中位绝对值，见 §3.4） |

### 3.4 轨迹 `trajectory`（`trajectory.csv` 的列契约）

| 列 | 类型 | 说明 |
|---|---|---|
| `frame` | int | 视频帧号（容器序） |
| `t_video_s` | float | 视频绝对时间（时基来源见 §4） |
| `t_rel_s` | float | **相对发车时间** = t_video − t0_abs_s（无 sync 时为 t_video） |
| `valid` | bool | 该帧是否有效 |
| `x` / `y` | float | 场地坐标 **[0,1]²**（归一化，见 API.md §1） |
| `theta_deg` | float | 朝向角（°），逆时针为正 |
| `dir_x` / `dir_y` | float | 方向单位向量（场地系） |
| `rms_field` | float | 定位质量（越小越好） |
| `origin_id` | int | 本次用哪个角标记当原点 |
| `corner_ids` | str | 命中的角标记 ID，分号连接（如 `"1;2;3;4"`） |
| `flags` | str | 帧级标志，分号连接 |
| `reason` | str | 无效原因（valid=false 时） |

> 列集 = v1.x `CSV_FIELDS` **减去** `x_raw/y_raw/theta_deg_raw/missing_corner_ids/target_rms/marker_scale/scale_cv`，
> **加上** `t_video_s`/`t_rel_s`。理由：
> * 会话级不再需要"滤波前"raw 列（时序滤波在会话模式下**强制关**，见 API.md §10 与本文档 §6）；
> * 减掉的是帧级诊断量，需要时从 `session.json` 的 `frames.diagnostics` 拿；
> * **既有 v1.x `results.csv` 列集保持不变**，本文档只定义**新增的** `trajectory.csv`。

轨迹还提供 `pos_noise_est`（有效帧差分的中位绝对值，mm 或场地单位）→ 一次失败检测：
抖动远大于预期 → 可能是运动模糊过大 / 角标记太远，是**外部绝对参照之外**的补充信号。

### 3.5 迷宫 `maze`（多帧融合，写进 `maze` 键）

> **当前实现状态（S4 已完成）**：融合的选帧标准是**"四角齐全"的帧，不是"定位有效"的帧**——
> 0 号目标缺失只影响轨迹，不影响迷宫结构（实测 720p 手持视频里四角齐全帧远多于有效帧）。
> `ambiguous_axis` 帧被排除（轴向存疑 → 迷宫可能被转 90°，会污染融合）。
> 融合结果的 `frame = -1`、`origin_id = null`（不属于任何单帧）。

沿用 `maze_extract.Maze` 的 `to_dict()` 结构（见 `maze_extract.py`），**在原结构上增加**：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `n_frames_used` | int | 参与融合的有效帧数 |
| `per_segment` | dict | 每段 `{"n_wall","n_open","n_unknown","n_frames"}` 投票统计 |
| `consistency` | dict | 各段一致率分布：`{"n","median","p25","min"}`（"不同机位解出同一迷宫"的量化） |

`consistency` 低 → 打 `maze_inconsistent` 标志（见 §6）。**这就是 v1.0.1 教训要的"系统性错误检测器"。**

融合语义（实现定稿）：

* 每段取 `conf ≥ conf_min` 的帧的**平均覆盖率**定态（判定顺序与单帧一致：先可判性、再覆盖率）；
* 一致率 = 该段"与融合态一致的帧"占可判帧的比例；统计量为全部段的分布（n/median/p25/min）；
* 外圈恒为墙（`boundary_is_wall`，与单帧解算同约定）；
* 会话级参数：`maze`（开关，默认开）、`maze_cfg`（`MazeConfig` 覆盖）、`maze_stride`、
  `maze_min_consistency`（默认 0.7）。

## 4. 时基（时间戳来源，规范要求）

**不再默认信任容器时间戳**。`preflight` 检测帧间隔：

- 若 `std(Δt) / mean(Δt) < 0.005` → 判定 CFR，时基可信，`timestamp_source = container_pts`（或 `frame_index_over_fps`，两者等价，见设计文档 §6 探针事实 1）；
- 否则 → 判为 **VFR 疑似**，`vfr_suspected=true`，**时基不可信**，打 `timebase_unreliable` 标志；
  → 该视频下 `t_video_s` 仍输出（按帧号÷标称 fps），但调用方**不得**把它当精确物理时间；
  → 发车对轴在 VFR 下只给 `onset_frame`，**不给**精确 `t0_abs_s`（亚帧插值禁用）；
  → 若 **EIS/防抖开启**（检测或用户声明），额外打 `eis_enabled` 标志 → 逐帧内参会漂移，
     `per_frame_from_homography` 自动回退为常量路径并打 `parallax_fallback_const`。

**为什么**：探针实测 CFR 下 `max|POS_MSEC − index/fps| = 1.1e-16`，容器时间戳没有独立信息；
手机 VFR 是否可信**未经验证** → 规范一律按"可疑"处理，宁可打标志也不给错时间（§6 的原则）。

## 5. 错误处理

| 情况 | 行为 |
|---|---|
| 视频打不开 / 无解码器 | `RuntimeError`（不产生 session.json）；CLI 直接失败退出码 1 |
| 视频读到了但 0 帧 | `runtime_error`（不产生 session） |
| `sync.enable=true` 但检不到 LED | **不报错**；`sync=None`，打 `sync_not_found` 标志，轨迹按无对轴输出（t_rel=t_video），继续完成会话。**S3 实现前**：显式开启（`sync_led=True` 或配置 `sync.enable=true`）→ `NotImplementedError`（明确失败，不静默假装成功） |
| 全部帧无效（无定位） | 不报错；`frames.n_valid=0`，打 `no_valid_frames`，maze=None，轨迹只有 0 行有效 |
| 中途单帧解码失败 | 跳过该帧，帧数照常累计，打 `frame_decode_errors` 标志（计数） |
| 配置非法（如 `start_s` 与 `start_frame` 同时给） | `ValueError`（执行前抛，不产生 session） |
| 输出目录不可写 | `OSError`（CLI 退出码 2） |

原则：**能完成的会话绝不因为部分数据缺失而整段失败** —— 缺失信息一律用标志表达，
保证"供其他程序调用"时，调用方只需处理**成功**与**少数明确异常**两种路径。

## 6. 标志（`flags`）全集

会话级：

| 标志 | 含义 |
|---|---|
| `timebase_unreliable` | 帧间隔非均匀（VFR 疑似），时间不可精确信任 |
| `eis_enabled` | 防抖开启或疑似开启 → 逐帧内参可能漂移 |
| `sync_not_found` | 开启了 LED 对轴但没检出（结果按无对轴输出） |
| `sync_subframe_estimate` | t0 是亚帧插值估计（精度受曝光时间限制） |
| `frame_decode_errors` | 有帧解码失败被跳过（含计数） |
| `no_valid_frames` | 没有一帧定位成功 |
| `maze_not_enabled` | 迷宫融合未启用（缺配置） |
| `maze_inconsistent` | 迷宫各段投票一致率低于阈值（低质量） |
| `parallax_fallback_const` | 视差修正从逐帧回退到常量路径 |
| `smoothed_in_video` | 用户显式要求平滑时提示（会话模式默认强制关） |

帧级 `flags`（`Localization.flags`）沿用 v1.x，不变（`ambiguous_axis` 等）。

## 8. 性能（已降级为参考，非 SLA）

| 项 | 值 | 说明 |
|---|---|---|
| 目标帧率 | **无硬性要求** | 离线批处理；调用方等待最终文件 |

> "离线批处理参考"，不再承诺帧率上限。

## 9. 最小集成示例（给调用方）

> 现阶段（S3 前）：去掉 `sync_led=True`、从 `aruco_locator.session` 导入，即可直接运行；
> `res.sync` 恒为 `None`（LED 对轴落地后该分支生效）。

```python
import aruco_locator as al

res = al.run_session("run01.mp4", out_dir="output/run01", sync_led=True)  # sync_led 待 S3

print(res.video.frames, "帧,", res.video.fps_declared, "fps, 时基来源:", res.video.timestamp_source)
if res.sync:
    print("发车 t0 =", res.sync.t0_abs_s, "s (onset 帧", res.sync.onset_frame, ")")
    # 取发车后 0.2s 那一帧附近的位置
    rows = [r for r in res.trajectory.rows if 0.18 <= r["t_rel_s"] <= 0.22]
    for r in rows[:5]:
        print(f"  t={r['t_rel_s']:.3f}s  x={r['x']:.4f} y={r['y']:.4f} θ={r['theta_deg']:.1f}°")
if res.maze:
    print("迷宫: wall", res.maze.n_wall, "/", res.maze.n_segment,
          "unknown", res.maze.n_unknown, "连通", res.maze.diagnostics["sanity"]["connected"])
print("会话标志:", ",".join(res.flags) or "-")
```

CLI 等价：

```bash
python -m aruco_locator.cli --source run01.mp4 --out output/run01 --sync-led \
  --trajectory output/run01/trajectory.csv --session output/run01/session.json --save-maze output/run01/maze.png
```

## 10. 与设计文档的关系

本规范把 [视频输入与手持拍摄改造-设计方案.md](视频输入与手持拍摄改造-设计方案.md) 的第 4/5 章
从"拟新增"落实为**可验收的契约**：
* §3 对应设计文档 §5 的输入/输出与序列化；
* §4 落实设计文档 §6 探针事实 1（时间戳无独立信息）与存疑 U4；
* §6 落实存疑 U1（t0 语义 → `t0_mode`）与"实时性降级"；
* 存疑项（LED 时序、亚帧、EIS、内参有无）**仍未定** —— 本规范只冻结"字段形状"，
  **不冻结具体阈值与判据**，阈值随测试视频定稿后进 `config.yaml`。
