# 修改方案：运动模糊下的标记检出

> 起因：2026-10-27 最终 4K 视频验证显示有效定位帧只有 2.6%~7.4%。
> 用户澄清两条前提：**① id2 固定在迷宫上、与场地共面、背景是暖气片（合规）；
> ② 标记绝大多数时间可见，问题只在运动时的动态模糊。**
> 本方案据此重做根因分析，并给出已实施部分与后续阶段。
>
> **结论速览**
> * **角标记**：四边形已找到、只是位判决失败 → **已修复**（白名单重解码，四角齐全 52%→64%）。
> * **目标标记**：两条路都做了——
>   ① **场地平面重投影**（用户提出）**有效**：目标检出 8%→12%、有效定位 4%→7%
>   （严格超集，无回归，+312ms/帧）；
>   ② 模糊超过 1~2 个模块时（位移 10~17mm / 模块 8mm）单帧信息已丢，
>   这部分只能靠跟踪补洞（漂移 ~10mm，须打 `tracked` 标志）或改采集。

---

## 0. 前提更正（撤回之前的错误判断）

| 之前的说法 | 更正 |
|---|---|
| "id2 斜靠、离面，破坏共面假设" | **错**。id2 固定于迷宫、共面；背景是暖气片，不构成违规。共面假设成立。 |
| "远端标记太小 → 物理上不可见" | **不准确**。标记在绝大多数帧可见；25px 是透视造成的正常尺寸。 |

因此不能把问题归给采集，必须由算法解决。

## 1. 失效机理（有证据，分两类）

在 121 帧抽样里逐帧解剖，失败分成两个互不相同的阶段：

### A 类：四边形找到了，**4×4 位判决失败**（角标记为主）

帧 200 的 14 个 `rejectedImgPoints` 中：

| 拒绝四边形 | 边长 | 实际身份 |
|---|---|---|
| (243, 1873) | 132.8 px | **id4**（正确位置 (200,1900)） |
| (2743, 222) | 45.3 px | **id2**（正确位置 (2700,215)） |
| (1164, 179) | 26.8 px | **id1**（正确位置 (1100,190)） |

对这三个四边形做白名单重解码，**Hamming 距离 0**（完全正确）。
另一类表现是**解成错误 ID**：同一帧 `id2 → 998`，被白名单当"缺失"丢弃。

机理：运动模糊把模块边界抹成斜坡，OpenCV 用 `perspectiveRemovePixelPerCell`
取每格均值时被邻域污染 → 位翻转 → 该候选被判无效。

> 实测附带结论：`errorCorrectionRate`（0.6 / 0.8 / 1.0）**完全无效**
> （四角 49%/49%/49%）——OpenCV 在进入这层校验之前就已经丢弃了。

### B 类：**四边形根本没形成**（目标标记为主）

帧 200 小车在 4K 坐标约 (1800, 830)，该处**没有任何候选四边形**
（14 个拒绝候选分别在墙面/桌沿/角标记处）。车顶标记在这种尺度 + 模糊下，
轮廓/多边形近似阶段就失败了。

所以：**角标记靠"重解码"能救；目标标记必须走"局部增强 + 重新检测"另一条路。**

## 2. 已实施（P0）：白名单四边形重解码

### 2.1 原理

```
候选四边形（含 OpenCV 丢弃的）
   → warp 成 6×6 模块网格（12 px/模块，对小标记是 3× 上采样）
   → 用「外圈边框（恒黑）中位 vs 数据区中位」自适应阈值取 4×4 位
   → 只与白名单 {0,1,2,3,4} 的模板比 Hamming（4 旋转取最小）
   → 接受：dist ≤ 2（16 位）、margin ≥ 3、contrast ≥ 25、最短边 ≥ 10px
```

关键点：**白名单**把"1000 选 1"变成"5 选 1"，所以"差 3~4 位"的模糊图案
也能可靠归类；而错误 ID（998）会因为不在白名单里被清掉。

### 2.2 落点

* 新增 `aruco_locator/redecode.py`：`QuadDecoder`（模板缓存）、`quad_plausible`（形状闸门）。
* `detector.py`：`detect()` 现在**保留** `rejectedImgPoints`；
  多尺度合并后执行 `_redecode()`：先处理被丢弃的四边形，再处理"ID 不在白名单"的检出
  （重解码成功则替换掉错 ID）。
* `config.py` 新增 5 个参数（自动进参数目录）：
  `detection.redecode`（默认 **true**）、`redecode_max_dist=2`、`redecode_min_margin=3`、
  `redecode_min_contrast=25`、`redecode_min_side=10`。
* 误接受由既有几何检查兜底：`geometry.max_square_rms`（四角方正度）+ 重投影残差；
  实测帧 200 的 `998` 被正确替换为 `id2`，位置与其它帧一致。

### 2.3 实测效果（121 帧抽样，同一基准 CLAHE + `scales=[1.0,2.0]`）

| 指标 | 关闭 | 开启 | 变化 |
|---|---|---|---|
| **四角齐全** | 63/121（52%） | **77/121（64%）** | **+12 pp** |
| 目标标记检出 | 10/121（8%） | 10/121（8%） | 0（属 B 类，见 §3） |
| 有效定位 | 5/121（4%） | 5/121（4%） | 0 |
| 单帧耗时 | 745 ms | 803 ms | +58 ms（+7.8%） |

> 有效定位没涨，是因为它被**目标标记**卡住——四角补齐只解锁"迷宫融合"，
> 不解锁轨迹。这正好说明 P0 和 P1 解决的是两件事。

## 3. 目标标记：三条路线都试过了，先看清物理上限

### 3.1 物理上限（这一条决定后面所有方案的期望值）

标记 48mm / 6 模块 → **每模块 8mm**。按实测：车在 1/30s 内位移约 10~17mm
（≈1.2~2 个模块）时，4×4 位图案在单帧里**已经被抹平到不可判**。
这不是阈值/参数问题——信息在采样时就丢了。任何"提高分辨率/放大/换视角"都不能补回信息。

所以目标标记的可检出帧 = "车慢或静止"的帧；这类帧在视频里是少数（实测 3~8%）。

### 3.2 已实施：场地平面重投影（用户提出，**实测有效**）

**做法**：用四角解出的 `H_img2field` 把整幅 warp 到场地正方形（`rectified_side=4500`
≈1.9 px/mm，48mm 标记 ≈134px），在该视图里再找目标；找到后把角点映射回原图坐标，
走原有位姿链路。

**为什么有效**（视觉证据见 `experiments/_rect_view/compare_f5.png`）：
车顶标记是水平面内的正方形，倾斜视角下被**各向异性压缩**；重投影把长宽比恢复，
标记从 109px 的斜四边形变成 139px 的正四边形，黑白边界也更利于阈值判决。

**口径一：四角齐全帧内，原图 vs 重投影**（77 帧，stride=10 抽样）

| 指标 | 数量 |
|---|---|
| 原图检出目标 | 5 / 77（6%） |
| 重投影检出目标 | **9 / 77（12%）** |
| **并集** | **9 / 77**（严格超集：仅原图 0 帧，仅重投影 4 帧，都没有 68 帧） |

**口径二：端到端 A/B（121 帧）**

| 指标 | `rectified_target=false` | `=true` | 变化 |
|---|---|---|---|
| 四角齐全 | 64% | 64% | — |
| **目标检出** | 8% | **12%** | +4pp（相对 +50%） |
| **有效定位** | 4% | **7%** | +3pp（相对 +80%） |
| 单帧耗时 | 772 ms | 1084 ms | +312 ms |

**精度校验**：帧 5 由重投影找回目标后定位 (0.0728, 0.0168)，与相邻检测帧
(0.0727, 0.0175) 相差 **<1mm** —— 不是"随便找回一个位置"。

**边界**：重投影**救不了远端角标记**（id2 原图仅 25px，上采样后仍是一团灰，
见 `rect_..._id2_native.png`）——没有信息可恢复。它只对"本身够大、但被压扁/倾斜"的标记有效。

> ⚠ 更正：本文档最初写的"重投影无收益（5 vs 4）"来自 **stride=20 的 36 帧小样本**，
> 且当时的比例分母算错了。stride=10 的 77 帧样本给出稳定结论：**重投影是严格超集**。


### 3.3 已试：跨帧跟踪（相位相关）

**做法**：从检测成功的帧取标记模板，逐帧用 `cv2.phaseCorrelate` 求残差位移并更新模板。
**结果**（120407 帧 216→240，平均 15px/帧）：能跟上，但
**24 帧后漂移 22.9px ≈ 10mm**（中途 6 帧处 12.3px），且相关响应低（0.14~0.15）。

ECC 梯度下降版本直接失败（25 帧全不收敛），因为单帧位移已超出其收敛域。

**结论**：跟踪可以作为"**补洞**"，但精度只有 ~10mm 量级，
必须打 `tracked` 标志、不能与检测结果等同看待。

### 3.4 更正：**不能把失败归给遮挡**

> 本文档初稿写过"29% 的失败是人手遮挡"，**该结论作废**：
> 皮肤色判据在奶白木墙/桌面上同样触发（非遮挡帧的"肤色比"也有 0.10~0.17），
> 阈值 0.18 只是把一段手挡窗口单独圈了出来；而失败率是 85%+，遮挡解释不了。
>
> 正确认识：手遮挡确实存在（帧 20–48 那段），但**只占一小段**；
> 绝大多数失败是**车在跑 → 运动模糊**。抽样里"四角齐全但无目标"的帧
> 从帧 60 一直持续到 500+，期间车在迷宫各处移动。

### 3.5 已实施：帧间跟踪补洞（`aruco_locator/track.py`）

思路：模糊会抹平 4×4 位图案，但**不改变图像频谱相位** → 平移量仍可测。
每次检测成功即重置模板与位置（锚点），检测失败时用相位相关推进一步。

实测（`VID_20261027_120407`，stride=1）：

| 区间 | 帧数 | 有效 | 其中跟踪 | 备注 |
|---|---|---|---|---|
| 0–120（车静止在发车角） | 120 | **93（77.5%）** | 59 | 位置与检测值差 **<0.5mm**，`track_resp` 中位 0.67 |
| 300–520（车在迷宫内跑动） | 220 | **75（34%）** | 64 | 锚点只有 11 个；两端都有锚点的段内偏差 **1.3mm** |

**结论**：跟踪能把静止/慢速段的可用率抬到 77%，但**快速段只有 34%**——
因为锚点太稀（11/220），且相位相关响应低于门限就停（避免输出错位置）。

**下一步（按收益排序）**：
1. **ROI 局部重检**：跟踪给出预测位置后，在该处裁切 + 放大 + 重解码，
   把"跟踪"升级成"局部检测"（能拿到真实角点，精度回到检测级）；
2. **旋转感知模板**：当前模板只跟平移，车转弯后失配；改用 ECC 的
   `MOTION_EUCLIDEAN`（带初值）或按预测角度旋转模板；
3. **双向跟踪**：从后一个锚点反向补齐，能把开区间段也覆盖。

### 3.6 P1 的最终形态

| 失败类型 | 实测占比 | 处理 |
|---|---|---|
| 角标记位判决失败 | 四角 52%→64% | ✅ 白名单重解码 |
| 目标被透视压扁 | 目标 8%→12% | ✅ 场地平面重投影 |
| 目标运动模糊（慢速段） | — | ✅ 跟踪补洞，误差 <1mm |
| 目标运动模糊（快速段） | 约 2/3 的无目标帧 | ⚠ 跟踪覆盖 34%，需 ROI 重检 / 旋转模板 |
| 手遮挡 | 局部（约 1 秒） | ❌ 物理遮挡，拍摄时避免 |

```
每帧：能检出（含重解码 / 重投影兜底）→ 正常定位（flags 不含 tracked），并重置跟踪锚点
      检不出但四角齐全 → 相位相关推进一步 → 输出位置 + flags=tracked, track_age=N
      响应 < track_min_response（默认 0.08）或 track_age > 30 → 判定丢失，留空
```

* 实现：`aruco_locator/track.py::PatchTracker`；会话参数 `track` / `track_max_gap` /
  `track_min_response`；`trajectory.csv` 增加 `track_resp` 列，`session.json` 增加 `frames.n_tracked`。
* 精度：检测帧 ~0.4mm 级；跟踪帧在**慢速/静止段**实测 <1mm，
  **快速段**因锚点稀疏只能给到 mm 级且会丢失（见 §3.5 实测）。

> 若需要连续轨迹，跟踪是唯一软件手段；但要接受"分段覆盖 + `tracked` 标志"，
> 想让快速段也可靠，下一步必须做 ROI 局部重检（把跟踪升级成检测）。

## 4. 可选增强（P2，按需）

1. **多阈值位投票**：同一四边形用 3 个阈值各取一次位、多数表决。
   预计再降 1~2 位错误率；代价 <5ms/帧。适合在 P1 之后做精修。
2. **边缘精化的模糊鲁棒化**：`line_scatter` 大于阈值时**放弃边缘精化**、
   保留 OpenCV 亚像素角点（模糊会拉低直线拟合质量，宁可不用）。
3. **角点精度评估**：重解码得到的四边形，其角点来自 OpenCV 的轮廓拟合，
   与正常检出同源；但仍应统计其 `rms_field` 分布，确认不劣化。
4. **墙面证据（红顶 OR 亮侧墙）**：解决迷宫解算里 19/49 面内部墙判 UNKNOWN 的问题
   （UNKNOWN 段亮覆盖 15/19 ≥0.5，OPEN 段误报 12/57）。与目标标记无关，可独立做。

> 明确**不做**：3 角点降级解算。单应 8 DOF、3 点只有 6 个约束，
> 第 4 点位置在数学上完全不受约束，任何"补出来"的位置都是猜的。

## 5. 配置与回退

```yaml
detection:
  redecode: true            # 关闭即回到旧行为（默认已开启）
  redecode_max_dist: 2
  redecode_min_margin: 3
  redecode_min_contrast: 25
  redecode_min_side: 10
```

* 全部参数走 `config.yaml` / 参数 API（`set_param("detection.redecode", False)` 可运行时关）。
* 回退验证：`tools/check_api_surface.py` + `selftest_synthetic.py`（重解码开启下回归）。

## 6. 验证口径（下一步照此验收）

1. 121 帧抽样：四角齐全率、目标检出率、单帧耗时（本方案 §2.3 已给基线）；
2. 两段完整会话（`stride=2`）：有效帧率、`rms_field` 分位、`pos_noise_est`；
3. 外部参照：轨迹点与融合迷宫零穿墙；两段视频迷宫零分歧；
4. 合成真值：`selftest_synthetic.py` 位置/角度误差不劣化。
