## 0. 一句话结论

**用户的思路（算格点 → 判断相邻点之间有没有红）在几何上是正确的**，实测已证实红线确实落在
场地系 `k/8` 格线上。但它与"直接对 144 条候选墙段沿线采样"是**同一信息的两种编码**，
差别只在**测量方式**（点采样 vs 线采样）。推荐用线采样，因为它额外给出**置信度**与
**遮挡下的部分证据**，而点采样在遮挡/偏移时只有"是/否"。

**接口上真正需要小心的不是算法，而是三件事**：① 遮挡必须能表达成 `unknown`（不能静默当成"无墙"）；
② 输出必须带上解算它的那套场地系（否则迷宫结构无法与定位结果对齐）；
③ 外圈红线是免费的绝对参照，要当质量指标用起来，而不是扔掉。

**已拍板的四项接口决策（详见 §5）**：外墙 = 场地边界；**邻接图为主输出**；
`UNKNOWN` 默认当有墙（同时给出乐观视图）；**永久保持独立脚本**，不并入包。

## 1. 已确认的物理事实（本次用实拍 + 正射图量化）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 红色是**墙顶的边缘线**，不是地面上的画线 | 正射图（`out_maze/*_maze.png`）：红线压在米色木条的上沿 |
| 2 | 红线是**轴对齐的线段**，不是色块 | 竖墙像素的 y 相位中位 = **0.511**（= 均匀），说明竖墙跨整格高 |
| 3 | 红线**落在场地系 `k/8` 格线上**（本方法的核心前提） | 8 帧 691,893 个红像素：y 相位落在格线 ±22.5mm 内的占 **68%**（均匀分布只有 12.5%，即 **5.4×** 集中）；到最近 `k/8` 线中位 **3.60mm**（场地 1440mm，正射图 1px≈1mm） |
| 4 | 外圈红胶带**可靠** | 39 张样本：外圈 4×9=36 条格线，覆盖率 >50% 的 **116/116**，中位 **80.4%** |
| 5 | 内部红线**被遮挡严重** | 内部 406 条格线覆盖率中位仅 **44.5%**，>50% 的只有 147/406 |
| 6 | `H_img2field` 标定在**墙顶平面**（角标记 h_c=50mm），所以墙顶红线正好落格线；墙的**侧面与阴影**因视差被投到格线旁边 | 事实 3 的 3.60mm 残差 + 正射图里红线旁的米色带 |

**事实 6 的工程含义**：判据必须带一个**横向搜索带**（墙有厚度、红线不一定压在中线），
不能只取中心 1 像素。

## 2. 五个失效模式 —— 它们决定了接口必须长什么样

| 编号 | 失效模式 | 后果 | 接口上的对策 |
|---|---|---|---|
| **F1** | **遮挡 → 测不到红 → 被静默判成"无墙"** | 迷宫多出通路，寻路会撞墙。**最危险**：看不出来 | 三态输出（`wall`/`open`/**`unknown`**）+ 独立「可判性」量 |
| F2 | 内顶点选错 / 单应锚偏 → 整套格线整体错位 | 全盘错，但结果"看起来像迷宫" | 外圈红胶带四边贴合度 → `boundary_uneven` flag（v1.0.1 事故的外部参照，固化成在线自检） |
| F3 | 格相位/朝向错（外墙到底在 `k=0` 还是 `k=1`） | 全盘错，且错得很"整齐" | 红线相位直方图集中度 → `grid_misaligned` flag |
| F4 | 红棕色杂物被判成红 | 凭空多出墙 | 覆盖率阈值 + 形态学 + **结构自检**（见下） |
| F5 | 迷宫不连通 / 有环 | 说明有漏检或误检 | **结构自检**：连通性 + 环数（完美迷宫 8×8 内部墙应为 **49** 面） |

F5 的判据是免费的、极强的：8×8 完美迷宫（生成树）必须**全连通**且**恰好 49 面内部墙**
（内部边 112 条 − (64 格 − 1)）。本次原型跑实拍，立刻抓出 `reachable 44/64, connected=False`
—— 数据不该用，代码自己报了警，没有静默给出一个错迷宫。

## 3. 方案比选

### 方案 A —— 格点-邻接法（用户原始思路）

算出 64 个格心（或 81 个交叉点）的场地坐标 → 对每对相邻格心，看连线中点附近有没有红。

* **优点**：直接产出**连通性**（寻路要用的量）；实现最直观；与"每格 4 面墙"一一对应。
* **缺点**：① 只在中点附近取一个"点/小块"，遮挡或红线偏移时**只有是/否，没有程度**；
  ② 若墙只覆盖半格（半墙）或红线有断口，中点采样会漏；③ 交叉点附近两墙相接易串扰。

### 方案 B —— 墙段线采样法（**推荐**）

先按 `H` 把图正射重采样到 `k/8` 格线为正的平面图 → 提取红掩码 →
对 **144 条候选墙段**（竖墙 `(s+1)×s` + 横墙 `s×(s+1)`）沿**整条线**采样，算两个数：

* `cover` = 沿线上"搜索带内出现红"的长度占比；
* `conf` = 沿线上"看得见红 **或** 看得见暗色地面"的长度占比（**可判性**）。

再按 `cover` 与 `conf` 判三态。

* **优点**：① 144 条与竞赛标准表示**天然一一对应**，无需二次转换；
  ② `cover` 是连续量 → 可设阈值 + 不确定带，能表达"我看不太清"；
  ③ 对遮挡**天然鲁棒**：遮挡只影响局部，`cover` 会相应降低而不是翻成"无墙"；
  ④ 垂直穿过的另一条墙只贡献几毫米长度（被两端裁剪 `segment_trim` 滤掉）。
* **缺点**：比 A 多一次正射重采样；参数比 A 多两个（搜索半宽、裁剪比例）。

### 方案 C —— 红线骨架 + 图论补全

对红掩码做形态学细化取骨架 → 与格线求交 → 断裂处用图论补全。

* **优点**：不依赖"墙一定贴格线"，现场线画歪了也能测。
* **缺点**：骨架化在遮挡/断口处必然断裂，补全规则本身是个新问题；超参多、可解释性差。
  **对当前阶段过重。**

### 比选结论

| 维度 | A 格点-邻接 | **B 墙段线采样** | C 骨架+图论 |
|---|---|---|---|
| 信息量 | 连通性 | **墙段 + 置信度** | 墙段 |
| 遮挡鲁棒性 | 差（点采样） | **好（线采样）** | 中（依赖骨架不断） |
| 与竞赛"每格4墙"对应 | 直接 | **直接** | 需转换 |
| 能表达"不确定" | 困难 | **天然（cover 连续）** | 中 |
| 实现/调参成本 | 最低 | 低 | 高 |
| 对"墙贴格线"的依赖 | 强 | 强 | 弱 |

**结论：采用 B 为测量主干；A 不是竞争方案，而是 B 的一个输出视图** —— B 测出 144 条墙段后，
"A 问的相邻格之间有没有墙"就是两格共享的那条墙段，零额外成本。
（这也解释了为什么用户会觉得"这件事没有这么复杂"：两者确实等价，只是索引方式不同。）

## 4. 接口草案（**核心，请重点审这一节**）

### 4.1 输入

```python
extract_maze(
    frame: np.ndarray,              # 一帧 BGR 图（HxWx3）
    H_img2field: np.ndarray,        # 3×3，像素 → 场地系 [0,1]²（来自已有的 locate()）
    cfg: MazeConfig | None = None,  # 全部阈值走配置，不硬编码
    *,
    frame_index: int = 0,
    timestamp: float = 0.0,
    origin_id: int | None = None,   # 场地系原点角标记 ID，用于把迷宫绑定到场地方位
) -> tuple[Maze, np.ndarray, np.ndarray]   # (迷宫, 正射图, 红色掩码)
```

**为什么要求调用方显式传 `H_img2field`**：迷宫是"场地系里的东西"，没有场地系就没有迷宫。
不在这里重复做标记检测 —— 定位已经做过，重复检测会引入两套不一致的坐标系。

**正射图/掩码一并返回**是刻意的：调用方几乎总要出图或二次分析，重算既贵又可能与结果不一致。

上层便利封装（后续再加，先不加避免接口膨胀）：

```python
ArucoLocator.locate_maze(frame, loc=None) -> Maze      # 复用上一次 locate 的 H
```

### 4.2 输出数据结构

```python
OPEN, WALL, UNKNOWN = 0, 1, -1          # 三态，不是 bool

@dataclass
class Maze:
    size: int                            # 8
    valid: bool; reason: str

    # —— 用**墙段**索引（2·s·(s+1) = 144 条），不是"每格 4 面墙" ——
    # 相邻两格共享同一条墙段；用墙段索引天然不会重复存储、也不会两格说法不一致
    ew_state:  np.ndarray  # (s+1, s)  int8   竖墙在 x=i/s，跨 y∈[j/s,(j+1)/s]
    ns_state:  np.ndarray  # (s, s+1)  int8   横墙在 y=j/s，跨 x∈[i/s,(i+1)/s]
    ew_cover:  np.ndarray  # (s+1, s)  float  ← 测量量，保留给上层自己定阈值
    ns_cover:  np.ndarray  # (s, s+1)  float
    ew_conf:   np.ndarray  # (s+1, s)  float  ← 可判性，F1 的对策
    ns_conf:   np.ndarray  # (s, s+1)  float

    # —— 元数据：缺了就无法与定位结果对齐 ——
    frame_index: int; timestamp: float
    origin_id: int | None                # 场地系原点角标记 ID
    H_img2field: np.ndarray | None       # 只存内存，不序列化
    ortho_bbox_px: tuple | None          # 正射图 ←→ 原图 的映射参数

    red_ratio: float | None              # 场内红色占比（质量）
    flags: list[str]                     # has_unknown / disconnected / grid_misaligned / ...
    diagnostics: dict                    # sanity / grid_alignment / cover_median / conf_median

    # —— 访问器（把"墙段索引"翻译成下游习惯的视图）——
    def wall_state(i, j, d) -> int       # 格 (i,j) 在方向 d 上的三态；d: 0=N(+y) 1=E(+x) 2=S(-y) 3=W(-x)
    def cell_walls(i, j) -> tuple        # 四面墙三态，按 (N,E,S,W)
    def has_wall(i, j, d) -> bool
    def can_go(i, j, d) -> bool          # 邻接视图（用户原始思路要的量）
    def neighbors(i, j) -> list          # 可达邻格，**未知按不可达**（保守）
    def n_wall / n_unknown / n_segment
    def n_internal_wall() / expected_internal_walls
    def reachable_cells() -> (n, 全连通?)
    def sanity() -> dict                 # {internal_wall, expected_internal_wall, reachable, connected, loops}
```

**关键设计决定**：

1. **三态而非二态**。`UNKNOWN` 是必需品不是奢侈品：F1（遮挡）在真实照片里是常态。
   把"没看清"和"确认无墙"混成一个值，就是把系统性错误埋进结果里 —— 这正是 v1.0.1 那次
   事故的教训（内部自洽性抓不到系统性错误）。
2. **以墙段为主索引**。避免"同一条墙被相邻两格各存一份、还可能说法不一"。
3. **同时输出 `cover` 与 `conf` 两个原始量**，不只在内部用。上层将来想换阈值、换判据、
   做时序融合，都不用重跑图像处理。
4. **元数据必须带 `origin_id` 与 `H_img2field`**。角标记朝向与 ID 排布不固定（已有事实），
   同一个迷宫在不同机位下 `origin_id` 可能不同 → 迷宫结构脱离 `origin_id` 就没有意义。

### 4.3 判定策略（可配置，不是硬编码）

```
sure = conf >= conf_min                      # 先看可判性
state = UNKNOWN
state[sure & (cover >= cover_wall)] = WALL
state[sure & (cover <= cover_open)] = OPEN
其余 → UNKNOWN
```

**顺序很重要**：`cover` 低有两种完全不同的原因 —— "确实没墙"和"根本没看清"。
只有 `conf` 足够高时，低 `cover` 才允许被解释成"无墙"。

**三态 → 下游语义（已拍板 Q3）**：`UNKNOWN` **默认当有墙**。
落地在 `can_go(i, j, d, unknown_as_wall=True)` 与 `to_adjacency(unknown_as_wall=True)`：
默认视图里 UNKNOWN 一律"不通"，寻路绝不会穿墙。同时 `to_dict()` 会额外给出
`adjacency_optimistic`（`unknown_as_wall=False`）—— 两种解释都输出，不替调用方做取舍。

> ⚠ 本原型里 `conf` 的实现（"看得见红 **或** 看得见暗色地面"）是最粗糙的一环，
> `dark_v_max` 依赖现场光照。**正式场地必须重新标定**；这条是算法部分后续要打磨的重点，
> 接口上只要保住"`conf` 是一个独立输出量"就够了。

### 4.4 序列化（**邻接图优先**，已拍板 Q2）

| 格式 | 内容 | 用途 |
|---|---|---|
| **`to_adjacency()`** | **主输出**：`{neighbors, n_edge, n_cell_reached, connected}` | 寻路 / 下位机 / 上层算法 |
| **`to_adjacency_text()`** | `格号 (i,j) -> 邻格...` 文本 | 终端直接核对 |
| `to_dict()` / `to_json()` | `adjacency` 排最前，其后是次级视图与诊断 | 调试、留档、跨语言交换 |
| `cell_codes()` | 64 个 0..15 整数，每格 4 bit（bit0=N … bit3=W），**unknown 位置位** | 电脑鼠竞赛通行表示 |
| `to_bytes()` | 32 字节 | 下位机 / 串口下发 |
| `to_ascii()` | 字符迷宫 | 终端快速核对 |
| `render_structure()` | 纯结构示意图 PNG | **最终交付图** |
| `render_maze()` | 正射图 + 红掩码 + 三态叠加 | 复盘、定位问题 |

邻接图的具体格式见 §5.1。`cell_codes()` 与 `to_bytes()` 里 **unknown 按"有墙"置位**，
与 Q3 的默认语义一致。

### 4.5 配置项（落地为 `MazeConfig`；后续可迁到 `config.yaml` 的 `maze:` 段）

```yaml
maze:
  size: 8
  ortho_side_px: 1440        # 正射图边长（px）。取 1440 → 1px ≈ 1mm（场地 1440mm）
  ortho_margin: 0.06         # 四边外扩比例，把外圈红线完整含进来
  red_hsv_1: [[0,95,70],[10,255,255]]      # 红在色环两端，必须双区间
  red_hsv_2: [[170,95,70],[180,255,255]]
  morph_open_px: 3           # 形态学开运算，去椒盐误检
  search_halfwidth: 0.030    # 横向搜索半宽（场地单位）≈ 43mm（墙有厚度 + 残余误差）
  segment_trim: 0.25         # 每条墙段两端各裁掉的比例（避开交叉点串扰）
  samples: 48                # 沿墙段采样点数
  cover_wall: 0.55           # 覆盖率 ≥ 此值 → 墙
  cover_open: 0.30           # 覆盖率 ≤ 此值 → 无墙；中间 → 不确定
  conf_min: 0.60             # 可判性低于此值 → 不确定
  dark_v_max: 110.0          # ⚠ 现场光照相关，必须重标
  min_red_ratio: 0.004       # 场内红色占比低于此 → 整帧无效（没拍到红线）
  boundary_is_wall: true     # 外墙=场地边界（已拍板 Q1）；仍测量并上报外圈覆盖率
  field_size_mm: 1440.0      # 只用于把诊断量换算成 mm，不影响归一化结果
  align_warn_mm: 12.0        # 红线到最近 k/s 格线中位距离超此值 → grid_misaligned
```

### 4.6 输出图片（已实现，见 `out_maze/`）

**`_maze.png`（纯结构示意图，交付图）**：白底；实线粗黑 = 墙，虚线浅蓝 = 不确定；
格内标 `i,j`；角上标原点与 +x/+y；顶部 HUD 给 `wall / unknown / internal(perfect) / connected / flags`。

**`overlay/*_maze.png`（叠加图，复盘用）**：正射照片压暗 + 暗红 = 原始红掩码，
青色实线 = 判定的墙，黄色虚线 = 不确定。**一眼就能看出"算法判的墙"和"照片里的红线"在哪不一致。**

### 4.7 与现有包的关系（**已拍板 Q4：保持独立**）

`maze_extract.py` **永久作为独立脚本**留在项目根目录，**不并入** `aruco_locator` 包
（`aruco_locator/` 一行未改，v1.x 对外接口继续冻结）。
它已加入 `tools/make_release.py` 的 `TOP_FILES`，与 `calibrate_camera.py` /
`selftest_synthetic.py` 同级，随发行归档分发。

将来若确实要合并，好处也只在"少一次 import"，成本却是动一个已冻结的公开接口 —— 不划算。

## 5. 接口决策（**已拍板，2026-10-04**）

| 编号 | 问题 | **决定** | 落进代码的位置 |
|---|---|---|---|
| **Q1** | 迷宫外墙与场地系的关系 | **外墙 = 场地边界**。外墙落在 `k=0` / `k=8`；外圈红胶带同时扮演"场地标记"与"迷宫最外圈墙"两个角色，是同一个东西 | `MazeConfig.boundary_is_wall = True`（默认，且语义已确认正确） |
| **Q2** | 输出的主表示 | **邻接图**。`to_adjacency()` / `to_adjacency_text()` 是主输出；墙段三态、`cover`/`conf`、每格 4bit 位图降为**次级视图**（仍全部保留，不删） | `Maze.to_adjacency()`；`to_dict()` 里 `adjacency` 排在最前 |
| **Q3** | `UNKNOWN` 的下游语义 | **默认当有墙**（保守，绝不穿墙） | `can_go(i,j,d,unknown_as_wall=True)`、`to_adjacency(unknown_as_wall=True)`；同时提供 `unknown_as_wall=False` 的**乐观视图**，两种解释都给出，不替调用方丢信息 |
| **Q4** | 交付形态 | **永久保持独立脚本**。不并入 `aruco_locator` 包，v1.x 接口继续冻结 | `maze_extract.py` 留在项目根目录；已加入 `tools/make_release.py` 的 `TOP_FILES`，随发行归档分发 |

### 5.1 邻接图的具体格式（Q2 的落地）

**线性格号**：`k = j*size + i`（行主序，`i` 沿 `+x`、`j` 沿 `+y`）。

`to_adjacency()` 返回：

```json
{
  "index_rule": "k = j*size + i   (i 沿 +x，j 沿 +y)",
  "neighbors": { "0": [1, 8], "1": [0, 2], "2": [1, 10], "4": [5], "...": [] },
  "n_edge": 56,
  "n_cell_reached": 6,
  "connected": false
}
```

* `neighbors` **只列出有邻居的格**；孤立的格不出现在字典里（= 四面都通不出去）。
* `n_edge`：可通行关系条数（无向，每条只算一次）。
* `n_cell_reached` / `connected`：从格 `(0,0)` 出发的可达格数与是否全连通
  —— 迷宫必须全连通，**这个字段本身就是最强的质量指标**。

`to_adjacency_text()` 给终端直接看的文本：

```
  0 (0,0) -> 8,1
  1 (1,0) -> 2,0
  2 (2,0) -> 10,1
```

**同时输出乐观视图**：`to_dict()["adjacency_optimistic"]` 是 `unknown_as_wall=False` 的结果。
两个视图放在一起，既守住"不穿墙"的默认，又不把另一种解释藏起来。

### 5.2 其余两处按现有约定定死（无需再议）

* **索引约定**：`i` 沿场地 `+x`（列），`j` 沿 `+y`（行）；格 (i,j) 覆盖 `x∈[i/s,(i+1)/s]`、
  `y∈[j/s,(j+1)/s]`；方向枚举 `0=N(+y) 1=E(+x) 2=S(-y) 3=W(-x)`。
  与现有场地系（原点 = 离画面左下角最近的角点）严格一致。
* **`size` 可配**：默认 8，但代码不假设 8（`expected_internal_walls` 是通用式
  `2s(s−1) − (s²−1)`），以防场地实际不是 8×8。

### 5.3 由 Q1 带来的一个直接推论

既然外墙就在 `k=0`/`k=8`，那么**外圈覆盖率是一个纯免费、纯独立的绝对参照**：

* 外圈四边必须几乎满覆盖（实测 116/116 条 >50%，中位 80.4%）；
* 四边偏移量必须一致 → `boundary_uneven` flag；
* 场地系一旦锚偏（内顶点选错 / 单应错），外圈覆盖率会立刻变得不均匀。

这条自检把 v1.0.1 那次"内部指标全正常、位置偏 10~45mm"的事故，变成了**在线可检出**。
**建议**：正式比赛时每 N 帧（或每次机位变动后）跑一次外圈自检，作为定位结果的兜底校验。

## 6. 现状演示（原型跑在**不合格**数据上）

现有 39 张实拍都不合格（迷宫没全露出），但正好用来检验接口是否好用：

```
[IMG_20261003_163808.jpg] valid=True   wall=75/144 unknown=13 red=0.0629
      结构自检：内部墙 43（完美迷宫 49）  可达 44/64  连通=False  环数=None
      前提自检：红线到最近 1/8 格线 中位 3.60mm / p90 8.40mm
      flags=boundary_uneven,has_unknown,disconnected
```

* 同一静止场景、**不同机位**的多帧给出**完全相同**的结构（43 面内部墙、44/64 可达）
  → 解算是**可重复**的，失败是系统性的，不是抖动。
* 结构自检自己报了警（`disconnected`）→ **没有静默给出一个错迷宫**。这是接口设计的价值。
* 前提自检 3.60mm → 核心假设（墙贴 `k/8` 格线）成立。
* **两个视图一起看，立刻定位到问题所在**：

  | 视图 | 通路数 | 可达格数 | 连通 | 环数 |
  |---|---|---|---|---|
  | 默认（UNKNOWN 当有墙） | 56 | 44/64 | 否 | — |
  | 乐观（UNKNOWN 当可通过） | 69 | **64/64** | **是** | **6** |

  两张表放在一起说明：**把迷宫切断的正好就是那 13 条 UNKNOWN**（乐观解释下马上全连通），
  但乐观解释下又多出 6 个环 → 完美迷宫应有 0 个环。所以这份数据无论如何都不合格，
  而**接口让这个诊断只靠一次读 JSON 就能看出来** —— 不用改代码、不用重跑。
  这正是"同时输出 `cover`/`conf` 与两种邻接视图"的回报。

产物：`out_maze/*_maze.png`（结构图）、`out_maze/overlay/*_maze.png`（叠加图）、
`out_maze/*.json`（完整数据）。

## 7. 下一步

接口已定稿（§5），代码已按决策改完。剩下的事**只有一件依赖现场数据**：

1. **合成自检可以先做，不必等实拍。** `selftest_synthetic.py` 的渲染器本来就知道每面墙的真值，
   把红墙画进去就能造出"迷宫全露出"的合格图，直接给出**墙判定的准确率 / 召回率 / F1**，
   以及 `cover` / `conf` 阈值应该取多少。**这是当前性价比最高的一步。**
2. **拿到合格照片**（迷宫全露出、最好固定机位正俯视）后，在真实光照下重新标定
   `dark_v_max` / `cover_wall` / `cover_open` / `conf_min` —— 这是唯一必须现场数据的部分。
3. 用真实光照标定过的阈值复跑 §6 的流程，核对结构自检（连通性、内部墙数）是否转为通过。
4. 若现场光照变化大，把 `conf` 的实现从"暗色地面启发式"换成按现场标定的表面色聚类
   —— 这是算法部分唯一已知的薄弱点，接口不用变。
