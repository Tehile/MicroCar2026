# 评估：用「对角线法」选角标记的内顶点

> 提出人：用户（2026-10-04）。评估人：WorkBuddy。文中所有数字均可由仓库内脚本复现。

## 0. 一句话结论

**方案方向正确，而且比现有实现更简洁** —— 但有一个必须补的细节：**点乘要在"平面空间"里做**。
直接按原案在图像空间做点乘，正确率只有 **84.4%**（比现有的 `nearest` 还差）；
补上这一步之后是 **100%**，与现有那套需要调参的代价函数**完全等价**，
同时快 **14 倍**、且**没有任何需要调的超参**。

## 1. 原案

1. 四个标记**中心**两两配对成 3 种方案，取"两条连线**相交**"的那一种 → 真正的对角配对；
2. 沿对角线方向（指向对侧），对两个端点标记各自的 4 个角点做**点乘**，取最大者 = 内顶点。

## 2. 为什么第 1 步是对的（而且很漂亮）

凸四边形**只有对角配对**的两条线段相交（相邻边配对、对边配对都不交）。
而透视投影**保凸、保关联**，所以"哪一对相交"这个判据在任意相机姿态下都成立 ——
它跟"离场地中心最近"那种依赖距离比较的判据不同，**不吃透视各向异性的亏**。

压力测试（每格 80 个随机场景，`rot_jitter=±40°`、`cam_roll=±35°`）：

| tilt | fill | 帧数 | 配对余量中位 | 最小 | 多解帧 | 无解帧 | 选错 |
|---|---|---|---|---|---|---|---|
| 0.16 | 0.70 | 80 | 0.424 | 0.344 | 0 | 0 | 0 |
| 0.30 | 0.70 | 73 | 0.366 | 0.240 | 0 | 0 | 0 |
| 0.45 | 0.70 | 35 | 0.362 | 0.200 | 0 | 0 | 0 |
| 0.60 | 0.70 | 19 | 0.344 | 0.198 | 0 | 0 | 0 |
| 0.30 | 0.40 | 49 | 0.396 | 0.285 | 0 | 0 | 0 |
| 0.45 | 0.35 | 20 | 0.383 | 0.319 | 0 | 0 | 0 |

即便把透视倾斜拉到 0.60、取景缩到画布短边的 35%，仍然**没有一帧出现多解或无解**，
最小余量 0.198（0.5 = 交点正落在两段中点，最稳）。

实拍 36 帧（`samples/IMG_20261003_*.jpg`）余量中位 0.334、最小 0.319。

## 3. 第 2 步：必须补的那个细节

### 3.1 判据实测正确率

在**合成真值**上比。合成渲染器把内顶点**正好放在场地角点**上，
所以"离最近场地角点最近的检出角点"就是真值 —— 不需要任何角度推理。

200 个随机场景（199 帧四角齐全；`rot_jitter=±40°`、`tilt=0.16`、`cam_roll=±35°`）：

| `vertex_mode` | 做法 | 全对帧 | 正确率 | 错帧号 |
|---|---|---|---|---|
| `xdiag` | 原案：图像空间**原始点乘** | 168 | **84.4%** | 1, 6, 7, 9, 15, 17, 22, 24, 49, 66, 83, 95… |
| `nearest` | 离场地中心最近 | 186 | 93.5% | 9, 22, 24, 49, 75, 83, 95, 97, 132, 144… |
| `xdiag_unit` | 图像空间**单位向量**点乘 | 193 | 97.0% | 49, 83, 144, 154, 177, 184 |
| **`xdiag_plane`** | **平面空间**点乘 | **199** | **100%** | — |
| `auto`（现行默认，`w=0.1`） | 形状残差 + 距离余量加权代价 | 199 | 100% | — |

### 3.2 两层误差各自来自哪里

**① 图像空间原始点乘 → 84.4%：被投影各向异性偏袒。**
同一条对角线方向下，被透视"拉长"的那个角点，其偏移向量的模更大，
点乘天然更大 —— 于是选出的是"最长的角"而不是"对齐最好的角"。
归一化掉模长（→ `xdiag_unit`）修掉这一层，97.0%。

**② 图像空间单位向量 → 97.0%：角度量在了错的空间。**
透视在局部是一个**各向异性的线性映射（剪切）**，它会把角点偏角整体旋转；
而"指向对端的方向"也是在同一空间量的，两者的旋转**不同步**，
于是一部分 45° 安全边被吃掉，在少数强透视帧里翻盘。

**③ 修法：把方向和角点偏角都用"该标记自身四边形拟合出的局部仿射"拉回平面空间再比。**
这个仿射只用了该标记自己的 4 个角点 —— 不需要全局模型、不需要内顶点、
不需要场地尺寸，**没有鸡生蛋问题**。正确率 → 100%。

```python
# 该标记的局部仿射：平面正方形 → 图像四边形
src = np.hstack([MARKER_LOCAL, np.ones((4, 1))])      # 单位正方形四角
A, *_ = np.linalg.lstsq(src, obs[i].corners)          # 2×3
M = A[:2, :].T                                        # 平面方向 → 图像方向
Minv = np.linalg.inv(M)
d    = Minv @ (center_of_opposite - center_of_this)   # 方向拉回平面空间
offs = (Minv @ (corners - center).T).T                # 角点偏角拉回平面空间
pick = argmax(unit(offs) @ unit(d))
```

实测余量（实拍 36 帧）：最优角点与对角线方向的夹角中位 **2.44°**、最大 4.64°，
次优角点至少在 90° 外 → **角度余量 ≥ 85.5°**。

## 4. 全流程精度（不是只看顶点对不对）

| 场景 | `xdiag_plane` 位置均值/最大 | `auto`（现行默认）位置均值/最大 |
|---|---|---|
| 标准合成（60 场景，`rot_jitter=40`） | 0.513 / 1.075 mm | 0.513 / 1.075 mm |
| **强透视 `tilt=0.30`** | **0.500 / 1.120 mm** | 0.986 / **23.359 mm** |
| 小目标 `fill=0.40` | 0.594 / 1.204 mm | 0.594 / 1.204 mm |
| 3D 视差（3 个变体，30 场景） | 6.567 / 4.040 / 3.876 mm | **完全相同** |

*强透视那一行值得注意：现行 `auto` 出现了一个 23mm 的野值（选错内顶点），
`xdiag_plane` 没有。所以它不只是"持平"，在极端视角下更稳。*

**实拍端到端**（36 帧）：`auto` 与 `xdiag_plane` 的位置差 **max 0.0000mm**、
角度差 **max 0.0000°** —— 逐位一致。

## 6. 诚实的局限

1. **前提：四个标记中心必须构成凸四边形、且只有一种配对相交。**
   相机在场地上方时投影保凸，恒成立（已测到 tilt 0.60 仍 0 失误）。
   但**有标记被画面裁掉**、或**四点近乎共线**（相机贴地掠过）时会退化。
   代码已把这种情况识别为 `diagonal_pairing_degenerate` 并回退到 `nearest`。
2. **真正的硬约束：内顶点偏移方向与对角线的夹角余量 = 45° − |标记自身转角|。**
   所以角标记若被贴成**转角接近 45°**，余量归零。本次合成用 ±40° 已接近极限且全部通过，
   但真实布置若允许任意转角，这是唯一的硬伤。
   **注意这不是这个方案独有的**：`nearest` 是同一个根因（同一处的距离余量一起坍塌），
   而 `auto` 靠第二判据略强 —— 但它在 `tilt=0.30` 下反而出现了 23mm 野值，说明也不稳。
   → **结论：现场仍应坚持"内顶点朝场地中央"贴，这是所有方法的共同前提。**
3. 配对与方向都由**标记中心**决定，因此依赖中心检测精度。中心是 4 角平均，
   是标记上噪声最小的量，实测无问题。
4. 它没有"形状残差"这个第二判据 —— 但那个判据已被实测证明是**退化**的
   （见 `geometry._assignment_cost` 的说明），去掉并不亏。

## 7. 建议

**把 `vertex_mode` 默认值从 `auto` 换成 `xdiag_plane`**，理由：
- 精度持平（199/199 真值全对），强透视下更好（无 23mm 野值）；
- 快 14.4 倍；
- **彻底去掉 `vertex_margin_weight` 这个必须落在 [0.05, ∞) 一侧的"悬崖型"超参**
  （临界值实测 0.037，安全垫仅 2.7 倍，且调小的方向会**静默出错**）。

若采纳，应作为 **v1.1.0** 发布（默认行为变更），并在 CHANGELOG 注明
`vertex_margin_weight` 仅对 `auto`/`search`/`full` 有效。

> **已采纳（2026-10-04）**：默认值已改为 `xdiag_plane`，见 [CHANGELOG §1.1.0](../../CHANGELOG.md)。
