# 灰度输入实验（⚠ 不计入正式版本）

**问题**：把输入图片先转成灰度图像再跑算法，准确率会怎样变化？

**一句话结论**：**不会变。** 因为本包的整条计算链路本来就用灰度 —— `aruco_locator/detector.py`
是唯一接触彩色的文件，而且第一件事就是 `cv2.cvtColor(frame, COLOR_BGR2GRAY)`；
`corners.py` / `geometry.py` / `parallax.py` / `api.py` 里**没有任何** `COLOR_` 常量，`viz.py` 只画不读通道。
所以"预先转灰度"与"喂彩色"在数学上等价，实测**逐位一致**（位置差 0.0000mm、角度差 0.0000°、检出集合完全相同）。

本目录不在 `tools/make_release.py` 的打包树（`TREES`）里，**不会进归档**；
`aruco_locator/` 未做任何修改，实验全部通过公开接口 `create_locator` / `ArucoLocator.locate` 只读调用。

---

## 1. 实验矩阵（六种"灰度"口径）

| 模式 | 含义 | 与基线的关系 |
|---|---|---|
| `color` | 解码 BGR 原样送入（= 当前正式版本行为，**基线**） | — |
| `gray_cvt` | `cvtColor(BGR2GRAY)`，单通道送入 | **应当逐位一致** |
| `gray_cvt3` | 同上但复制成 3 通道送入 | **应当逐位一致**（验证"代码路径无关"） |
| `gray_decode` | 直接 `IMREAD_GRAYSCALE` 解码（libjpeg 的 Y 通道） | 只在实拍上有意义 |
| `gray_jpeg` | 灰度后重编码为 JPEG(q=95) 再解码（= 真把图存成灰度图） | 实拍/合成均有 |
| `gray_mean` | 三通道**未加权**均值 | 只用来量"光度公式"敏感度 |

方法要点：合成部分对**同一张渲染图**施加不同灰度化，差异只可能来自灰度化本身；
实拍部分逐帧与基线比对 Δx/Δy/Δθ/Δrms、检出集合、有效帧数与标志位。

---

## 2. 结果 A — 合成场景（有真值）

### 2.1 标准难度（40 场景，seed 20260922，blur 0.8 / noise 4.0 / gradient 0.06）

| 模式 | 有效 | 位置 均值/p95/最大 (mm) | 角度 均值/p95/最大 (°) | 与基线 Δ位置 (mm) | 与基线 Δ角度 (°) | 逐位一致 |
|---|---|---|---|---|---|---|
| `color` | 37 | 0.515 / 1.037 / 1.075 | 0.252 / 0.526 / 0.875 | — | — | — |
| `gray_cvt` | 37 | 0.515 / 1.037 / 1.075 | 0.252 / 0.526 / 0.875 | **0.000 / 0.000 / 0.000** | **0.0000** | **是** |
| `gray_cvt3` | 37 | 0.515 / 1.037 / 1.075 | 0.252 / 0.526 / 0.875 | **0.000 / 0.000 / 0.000** | **0.0000** | **是** |
| `gray_jpeg` | 37 | 0.509 / 1.024 / 1.209 | 0.221 / 0.625 / 0.722 | 0.169 / 0.273 / 0.288 | 0.178 | 否 |
| `gray_mean` | 37 | 0.526 / 0.940 / 1.284 | 0.246 / 0.675 / 1.257 | 0.166 / 0.363 / 0.468 | 0.199 | 否 |

### 2.2 压力难度（40 场景，blur 1.6 / noise 12.0 / gradient 0.14）

| 模式 | 有效 | 无效 | 位置 均值/p95/最大 (mm) | 角度 均值/p95/最大 (°) | 与基线 Δ位置 (mm) | 与基线 Δ角度 (°) | 有效数差异 |
|---|---|---|---|---|---|---|---|
| `color` | 29 | 8 | 0.620 / 1.246 / 1.348 | 0.420 / 0.995 / 1.540 | — | — | — |
| `gray_cvt` | 29 | 8 | 0.620 / 1.246 / 1.348 | 0.420 / 0.995 / 1.540 | **0.000** | **0.0000** | 0 |
| `gray_cvt3` | 29 | 8 | 0.620 / 1.246 / 1.348 | 0.420 / 0.995 / 1.540 | **0.000** | **0.0000** | 0 |
| `gray_jpeg` | 29 | 8 | 0.586 / 1.183 / 1.355 | 0.377 / 0.728 / 0.887 | 0.373 / 0.622 / 0.746 | 0.310 | 2 |
| `gray_mean` | 29 | 8 | 0.573 / 1.115 / 1.212 | 0.476 / 0.979 / 1.174 | 0.411 / 0.836 / 0.898 | 0.489 | 2 |

**读法**：`gray_cvt` / `gray_cvt3` 在标准与压力两档下都**逐位重合**（位置差恰好 0）。
`gray_jpeg` / `gray_mean` 改动的是**灰度值本身**（不是"灰度 vs 彩色"），
所以出现了 0.17~0.41mm / 0.18~0.49° 的微小扰动 —— 但绝对精度几乎没动
（标准档 0.515 → 0.509 / 0.526 mm，压力档 0.620 → 0.586 / 0.573 mm），
全部落在本次实验的噪声量级内。

## 3. 结果 B — 实拍 39 张（2026-09-25 三张 + 2026-10-03 三十六张，无测绘真值）

场地 1440mm。基线无效帧 10 个（`corner_markers_missing`×6、`target_marker_missing`×4）。

| 模式 | 有效/39 | 检出标记总数 | Δ位置 均值/p95/最大 (mm) | Δ角度 均值/最大 (°) | 原点异 | 有效异 | 检出集异 | 标志异 |
|---|---|---|---|---|---|---|---|---|
| `color`（基线） | 29 | 251 | — | — | — | — | — | — |
| `gray_cvt` | 29 | 251 | **0.000 / 0.000 / 0.000** | **0.0000 / 0.0000** | 0 | 0 | 0 | 0 |
| `gray_cvt3` | 29 | 251 | **0.000 / 0.000 / 0.000** | **0.0000 / 0.0000** | 0 | 0 | 0 | 0 |
| `gray_decode` | 29 | 251 | **0.000 / 0.000 / 0.000** | **0.0000 / 0.0000** | 0 | 0 | 0 | 0 |
| `gray_jpeg` | 28 | 253 | 0.058 / 0.152 / 0.169 | 0.072 / 0.591 | 3 | 3 | 30（白名单后 1） | 3 |
| `gray_mean` | 31 | 258 | 0.056 / 0.127 / 0.130 | 0.044 / 0.179 | 2 | 2 | 25（白名单后 1） | 2 |

**注意三件事**：

1. `gray_cvt` / `gray_cvt3` / `gray_decode` 三种"纯灰度输入"**与彩色输入完全一致**，
   连标志位都没变 —— 灰度输入对定位结果零影响。
2. `gray_jpeg` / `gray_mean` 的"检出集异 30 / 25"看着吓人，但那是**原始检出**；
   经过 `corner_ids` / `target_id` 白名单过滤后最终只有 **1 帧**的角标记集合不同。
   差异基本都是误检（ID 17 / 437 / 441 这类）的出现与消失。
3. 有效帧数会小幅摆动：`gray_mean` 实拍**多救回 2 帧**、`gray_jpeg` **少 1 帧**。
   这些是运动模糊/遮挡的边缘帧，本来就处在判定门限上下 —— 换灰度口径等于给它加了
   一点扰动，往哪边倒都是随机。**不能解读成"某种灰度化更准"**。

## 4. 结果 C — 为什么 `gray_decode` 也逐位一致？（反直觉，已查清）

`IMREAD_GRAYSCALE` 与 `IMREAD_COLOR`+`cvtColor` 得到的灰度图**并不相同**：

```
39/39 帧的灰度图逐位都不相同；最大像素差 8（0~255）；平均最大像素差 5.36
```

可是定位结果却逐位一致。逐像素解剖后原因很清楚 —— **差异只落在彩色区域**：

| 区域 | 像素占比 | 平均 \|Δ\| | 最大 \|Δ\| | \|Δ\|≥3 占比 |
|---|---|---|---|---|
| 近消色（max−min < 12） | 31.3% | **0.000** | 2 | 0.00% |
| 低彩 | 58.0% | 0.000 | 5 | 0.00% |
| 中彩 | 5.0% | 0.002 | 4 | 0.01% |
| 高彩 | 5.7% | 0.011 | 5 | 0.01% |
| **标记包围盒内（+12px 余量）** | 0.7% | **0.000** | **1** | **0.000%** |
| 标记包围盒外 | 99.3% | 0.001 | 5 | 0.001% |

全图仅 **0.08%** 的像素存在差异、`|Δ|≥3` 的只占 **0.001%**。机理：JPEG 内部存 YCbCr，
`IMREAD_COLOR` 要 YCbCr→BGR→灰度做一次往返，往返误差集中在**有彩色**的地方（红胶带、彩色背景）；
而**标记是黑白消色**的，往返近乎无损。39 帧汇总：标记区最大 `|Δ|` 中位 **1**、最大 6；
标记区外中位 **5**、最大 8。误差刚好避开了决定结果的区域。

## 5. 结果 D — 耗时（交错采样，每轮轮换顺序，30 次重复）

| 模式 | 均值 (ms) | 最小 (ms) | 相对基线 |
|---|---|---|---|
| `color` | 274.53 | 246.44 | 1.000× |
| `gray_cvt` | 269.44 | 253.78 | 1.019× |
| `gray_cvt3` | 277.90 | 240.88 | 0.988× |
| `gray_jpeg` | 311.81 | 266.38 | 0.880× |
| `gray_mean` | 265.14 | 218.93 | 1.035× |

**没有可测量的收益。** 各模式差异 ±3.5%，且与"谁更快"不一致
（`gray_cvt` 均值更快、最小值反而更慢）→ 纯属机器噪声。

单帧 ~270ms 由 `refine.enable=true` 的联合最小二乘主导。而预先转灰度省掉的是
`detector.py` 内部**两次** `cvtColor`，实测单次 `cvtColor(BGR2GRAY)` 在
2296×4080 上仅 **1.93ms**，两次 = **1.4%**；且调用方自己转一次还要花掉约一半。

## 6. 结论与建议

1. **算法对"彩色 vs 灰度"输入完全不变** —— 逐位一致，位置差 0.0000mm、角度差 0.0000°，
   检出集合、标志位、有效帧数全部相同。这是代码结构决定的（内部本来就只吃灰度），
   不是巧合。
2. **预先转灰度没有性能收益**（省 ~1.4%，落在噪声里），**也没有精度代价**。
   所以"要不要先转灰度"纯粹是**存储/带宽/接口**问题，与算法无关：
   如果上游设备或下游流程只方便给灰度，可以直接给，不必为算法回退到彩色。
3. **唯一会改变结果的是"换一种灰度算法"**，即 `IMREAD_GRAYSCALE`（Y 通道）/
   未加权均值 / 灰度+JPEG 重编码。这些改的是"哪张灰度图"。即便如此影响也极小：
   合成精度基本不变、实拍增量 ≤0.17mm / 0.6°，只有边缘帧的有效性会翻转
   （且方向随机，不是系统偏差）。
4. ⚠ **风险提示（唯一需要真正注意的一条）**：把图**存成灰度 JPEG** 等于**多引入一次
   有损压缩**。实拍中它改变了 **30/39 帧**的原始检出集合、并让 1 帧从有效变无效。
   若现场确要落盘灰度图，**必须用无损格式（PNG/PGM）或 JPEG q≥95**，
   并在新数据上重跑有效性统计 —— **不可假定与彩色等价**。
5. **对正式版本的动作：无。** 不需要改任何代码或默认值。本实验的结论是"维持现状即可"。

## 7. 复现

```bash
# 全部四组（合成 40 场景 + 实拍 39 张 + 耗时）
python experiments/exp_gray_input.py --json experiments/gray_std.json

# 压力难度合成
python experiments/exp_gray_input.py -n 40 --stress --no-real --json experiments/gray_stress.json

# 理想成像（排除模糊/噪声/光照不均）
python experiments/exp_gray_input.py -n 40 --ideal --no-real

# 只跑实拍与耗时（--no-real 的反面；默认就是全跑，可用 --glob 换样本集）
python experiments/exp_gray_input.py --glob "samples/IMG_20261003*.jpg"
```

`experiments/` 内容：

| 文件 | 说明 |
|---|---|
| `exp_gray_input.py` | 实验脚本（只读调用公开接口） |
| `gray_std.json` | 标准档原始结果 |
| `gray_stress.json` | 压力档原始结果 |
| `README.md` | 本报告 |

配置取仓库根目录 `config.yaml`（即正式默认档 `vertex_mode=xdiag_plane`、`refine.enable=true`）。
