# 快速开始

按"手上有什么"分四条路。**任何一条都不需要先装一堆东西**——`general_env` 里的依赖已经齐了。

---

## 0. 环境（三种路线都先做这一步）

```bash
conda activate general_env
python -V          # 期望 Python 3.12.x
```

| 项 | 值 |
|---|---|
| 解释器 | `C:/Users/liuru/.conda/envs/general_env/python.exe`（3.12.13） |
| 已有依赖 | cv2 4.11.0（contrib 版，含 aruco）/ numpy / scipy / pyyaml / aiohttp / pyserial / websockets / Pillow / qrcode / pandas |
| **不要做** | 不要在别的环境 `pip install opencv-python`（非 contrib，没有 `cv2.aruco`） |

依赖清单见 `Control/requirements.txt` 和 `RemoteControl/host/requirements.txt`，两份都只是**记录**。

## 1. 只有电脑：先把整条链路和九个页面跑通

```bash
cd Control
python tools/preflight.py        # 自检，退出码 0 才算过
python app.py                    # 起服务
```

浏览器开 **http://127.0.0.1:8770**。

没有电脑鼠？起设备模拟器（另开一个终端）：

```bash
cd RemoteControl/host
python -m host.sim.mouse_sim     # 协议逐字节一致，自带物理与迷宫探索
```

然后在界面顶栏【电脑鼠】里连 `tcp://127.0.0.1:5555`。

一条命令跑完全部判据（会自己起模拟器）：

```bash
cd Control
python tools/drill.py --sim              # I1~I68
python tools/drill.py --sim --keep       # 失败时保留 .tmp/drill 现场
python tools/browser_check.py --sim      # 九页真渲染 + 按钮真发请求（需服务已在跑）
```

## 2. 有一段场地视频：解出轨迹

```bash
cd "Auto Locate"
python -m aruco_locator.cli --source path/to/run.mp4 --out out/run1
```

产物（`out/run1/`）：

| 文件 | 内容 |
|---|---|
| `session.json` | **权威**：帧数、检出率、内参、每帧摘要、迷宫融合结果 |
| `trajectory.csv` | 逐帧位姿 `t_ms, x_mm, y_mm, theta_deg, quality` |
| `frames.jsonl` | 逐帧明细（角点、质量标志、耗时） |

在界面里跑同一条路：`#/video` 页选素材 → 起解析 → `#/track` 看轨迹。
**不要**手工 `python -m aruco_locator.session`——它不收 `--config`，会退回默认配置。
用 `Control/tools/video_session.py`（界面走的就是它）。

只要合成真值、不要素材：

```bash
cd "Auto Locate"
python selftest_synthetic.py
```

## 3. 有电脑鼠：连上、看、调、发车

1. **接线**：USB 转 TTL（CH340）或蓝牙 SPP 模块，默认 **115200 8-N-1**。真机口在本机是 `COM7`。
2. **确认固件档位**：连上先看 `PONG` 回的 `PROTO / FW`。远程档应为 **10 / 314**；
   若无声，多半是烧了比赛档（比赛档不响应串口命令）。
3. **界面**：`#/live` 看波形与 4 灯三态；`#/params` 改参数（写后自动回读校验）；
   `#/race` 发车/收车。**发车前轮子必须悬空或已在赛道上**，上位机会先独立校验电池。
4. **收车**：点【收车】后看**动作码归零**才算停住，`ACK OK` 不算。

只想要命令行、不开界面：

```bash
cd RemoteControl/host
python selftest.py                        # 纯协议断言，不需要硬件
python selftest.py --e2e                  # 再拉起模拟器做端到端
python basic_cmd_smoke.py COM7            # 真机基础指令冒烟
python monitor_smoke.py COM7              # 取流 + 实时监视
python link_pull_evt.py COM7 --mark-n 2   # 长跑唯一推荐（事件触发，在途恒 ≤1）
```

> `--mark-n 2` 不是随手写的：发车复合批次是全程最密突发，`N` 越大上行越密。
> 真机复测一律从 `N=2` 起，确认稳了再升，**`N=6` 会灌死模块**。

## 4. 要改固件：Keil 打开工程

| 目的 | 打开 | Target |
|---|---|---|
| 比赛（默认） | `RemoteControl/code_competition - V6++/USER/TEST.uvprojx` | `V6_4mm` |
| 远程档（上位机接管） | 同上 | `Target_Remote` |
| 只做算法对照 | `RemoteControl/code_competition/` | `Target_1` / `Target_Remote` |

- 切换 Target 后**先 Rebuild**（增量编译会串档）。
- 命令行批量重编 + 红线校验：

```bash
cd RemoteControl
python build_v6pp_modes.py                     # V6++ 五档全量 + 比 hex 哈希
python build_v6pp_modes.py --only Target_Remote
python build_v6plus_modes.py --incremental     # V6+；全量会触发批量删除护栏
```

- **UV4 的 exit code 不可信**（0=无错 / 1=仅有告警 / 2=有错），一律看构建日志里的 `N Error(s)`。
- **Keil 开着的时候命令行抢不到资源**，重编前先关 Keil。
- 编码：`code_competition/` 与 `V6+` 的 `.c/.h` 多为 **GBK + CRLF**，例外是 `UTILITY/utility.c` = UTF-8。
  用 GBK 回写 `utility.c` 会把中文注释整段变乱码——改之前先探编码。

## 6. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `ImportError: No module named host` | 在错误目录跑，或用了别的解释器 | `cd RemoteControl/host`，或用 `general_env` 绝对路径 |
| `cv2.aruco` 不存在 | 装了 `opencv-python` 而非 contrib | 换 `opencv-contrib-python`（`general_env` 已是） |
| 页面能开、九页全空 | 前端启动期抛异常 | 看红框提示的 stage；`Ctrl+Shift+R` 强刷（旧资源缓存） |
| 连上了但一切是死的 | 烧的是比赛档 / 波特率不对 | 看 `PONG` 的 proto；波特率 115200 |
| 取流十几秒后全静默 | 透传模块被灌满（`N=6`） | **断电复位**，降到 `N=4` 或 5 |
| 视频解析结果全无效 | 用了 `aruco_locator.session` 未带 config | 改用 `Control/tools/video_session.py` |
| 发车被拒 | 电池 < 7000 mV | 充电；这是有意为之的护栏 |

更多细节：`Control/README.md` §故障，`RemoteControl/README.md` §常见故障。
