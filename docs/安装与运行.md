# 安装与运行

命令以仓库根目录为起点，`python` 指已安装依赖的解释器。

---

## 1. 环境准备

### 1.1 解释器

| 项 | 要求 |
|---|---|
| Python | ≥ 3.10（开发与验证使用 3.12.13） |
| 操作系统 | Windows 10/11；纯 Python 部分未在 Linux/macOS 验证 |
| 关键依赖 | `opencv-contrib-python`（提供 `cv2.aruco`），不可用 `opencv-python` 替代 |

`cv2.aruco.ArucoDetector` 需要 OpenCV ≥ 4.7；`requirements.txt` 已限定 ≥ 4.8。

### 1.2 安装依赖

venv：

```bash
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
python -m pip install -U pip
pip install -r requirements.txt
```

conda（环境名任意）：

```bash
conda create -n micromouse python=3.12 -y
conda activate micromouse
pip install -r requirements.txt
```

可选依赖（`requirements-optional.txt`）：

| 包 | 用途 | 缺失后果 |
|---|---|---|
| `PySide6` | `RemoteControl/host` 桌面 GUI（`run_host.py`） | `host.api` 与 `Control` 不受影响，仅桌面 GUI 不可用 |
| `scipy` | 定位精化（`least_squares`） | 精化自动关闭，会话标记 `scipy_missing` |
| `qrcode` / `Pillow` | 采集服务二维码 | 降级为手输地址 |

### 1.3 自检

```bash
cd Control
python tools/preflight.py
```

检查项包括依赖版本、上游模块可导入、串口枚举、端口占用。退出码 0 表示通过；
`--quick` 跳过网络与 git 检查。没有硬件时串口一项显示为空，不影响其余检查。

## 2. 上位机（无硬件）

### 2.1 启动

```bash
# 终端 A：设备模拟器
cd RemoteControl/host
python -m host.sim.mouse_sim              # 默认 127.0.0.1:5555

# 终端 B：上位机服务
cd Control
python app.py                             # 默认 http://127.0.0.1:8770
```

`app.py` 参数：

| 参数 | 说明 |
|---|---|
| `--config` / `-c` | 配置文件，默认 `./config.yaml` |
| `--host` | 绑定地址，默认仅本机 |
| `--port` | 端口，默认 8770 |
| `--print-paths` | 打印解析后的上游路径后退出 |

浏览器打开 `http://127.0.0.1:8770`，在顶栏「电脑鼠」中选择 `tcp://127.0.0.1:5555` 建立会话。

### 2.2 判据验收

```bash
cd Control
python tools/drill.py --sim            # 端到端判据，自动起模拟器
python tools/drill.py --sim --keep     # 失败时保留 .tmp/drill 现场
python tools/browser_check.py --sim    # 九个页面渲染与请求验证（需服务已运行）
python tools/check_iface_table.py      # 文档 × 路由 × 上游符号一致性
```

判据编号与覆盖范围见 [`Control/docs/工具与校验.md`](../Control/docs/工具与校验.md)。

## 3. 离线定位

### 3.1 命令行单次解算

```bash
cd "Auto Locate"
python -m aruco_locator.cli --source /path/to/run.mp4 \
                            --out out/run1 -c config.yaml
```

`Auto Locate/samples/` 为本地评估素材，未纳入版本控制，需自备视频。

`--source` 接受图片、目录、视频文件或 `camera:0`。常用参数：
`--max-frames`、`--start`、`--save-video`、`--save-annotated`、`--json`、`--csv`。

产物：

| 文件 | 内容 |
|---|---|
| `results.csv` | 逐帧位姿 `t_ms, x_mm, y_mm, theta_deg, quality` |
| `results.jsonl` | 逐帧明细：角点、质量标志、耗时 |

`-c config.yaml` 不可省略：缺省时使用内置默认值，720p/4K 素材所需的 `detection.scales=[1,2,3]`、
相机高度与视差参数均不生效，结果会出现大量无效帧。

### 3.2 会话级调用（上位机与外部程序使用）

```bash
python Control/tools/video_session.py \
    --source /path/to/run.mp4 \
    --out out/session1 \
    --config "Auto Locate/config.yaml"
```

产物：

| 文件 | 内容 |
|---|---|
| `session.json` | 权威结果：帧数、检出率、内参、逐帧摘要、迷宫融合 |
| `trajectory.csv` | 逐帧位姿与时间轴 |
| `trajectory.png` / `maze_structure.png` | 轨迹与融合迷宫示意 |

直接执行 `python -m aruco_locator.session` 不会读取 `--config`，会退回内置默认配置。
`video_session.py` 是补全该参数的薄壳，契约见
[`Auto Locate/docs/会话级接口规范-视频文件处理.md`](../Auto%20Locate/docs/会话级接口规范-视频文件处理.md)。

### 3.3 合成真值自检

```bash
cd "Auto Locate"
python selftest_synthetic.py
```

不依赖任何素材，用于确认安装完整、解算链路可用。

## 4. 真机联调

### 4.1 接线与固件确认

| 项 | 值 |
|---|---|
| 物理层 | USB 转 TTL（CH340）或蓝牙 SPP |
| 串口参数 | 115200 8-N-1 |
| 端口 | 由系统分配，如 `COM7`；蓝牙配对后生成「传出」COM 口 |

连接后首页应收到 `PONG`：

- 远程档：`PROTO=10`、`FW=314`，可由上位机接管；
- 无响应：多为烧写了比赛档（比赛档不响应串口命令），需改烧 `Target_Remote`。

### 4.2 界面操作

| 页面 | 用途 |
|---|---|
| `#/live` | 遥测波形、四灯状态 |
| `#/params` | 41 项参数读写，写后自动回读校验 |
| `#/race` | 发车、收车 |
| `#/video` → `#/track` | 视频解析与轨迹回放 |
| `#/records` → `#/maze` | 记录列表与迷宫回放 |

发车前上位机独立校验电池电压，低于 7000 mV 拒绝发车。收车以动作码归零为准。

### 4.3 命令行联调

```bash
cd RemoteControl/host
python selftest.py                        # 协议断言，无需硬件
python basic_cmd_smoke.py COM7            # 真机基础指令
python monitor_smoke.py COM7              # 取流与实时监视
python link_pull_evt.py COM7 --mark-n 2   # 长时间取流（事件触发，在途 ≤ 1）
```

`--mark-n` 为批量深度，决定上行密度。真机复测从 `N=2` 起，逐级验证后提升至 `N=4` 或 `5`；
`N=6` 会在十余秒内使透传模块饱和，只能断电恢复。原理与容量计算见
[`docs/系统架构.md`](系统架构.md#33-遥测帧上行)。

## 5. 编译固件

### 5.1 Keil 工程

| 目的 | 工程 | Target |
|---|---|---|
| 比赛（默认） | `RemoteControl/code_competition - V6++/USER/TEST.uvprojx` | `V6_4mm` |
| 上位机接管 | 同上 | `Target_Remote` |
| 旧基线对照 | `RemoteControl/code_competition/USER/TEST.uvprojx` | `Target 1` / `Target_Remote` |

切换 Target 后必须 Rebuild，增量编译会沿用上一档的目标文件。

### 5.2 命令行重编

```bash
cd RemoteControl
python build_v6pp_modes.py                        # 五档全量 + 红线校验
python build_v6pp_modes.py --only Target_Remote
python build_v6plus_modes.py --incremental        # V6+
```

### 5.3 注意事项

- **UV4 退出码不可靠**：0 = 无错误，1 = 仅告警，2 = 有错误；判定以构建日志中的 `N Error(s)` 为准。
- **Keil 运行时命令行无法占用工程**，重编前先关闭 Keil。
- **源码编码不一致**：`code_competition/` 与 `V6+/` 的 `.c/.h` 多为 GBK + CRLF，
  例外是 `UTILITY/utility.c`（UTF-8）。改写文件前先确认编码，否则中文注释会损坏。
- 全量重编会触发批量删除护栏，日常使用 `--incremental`。

红线基线与资源占用见 [`docs/版本与发布.md`](版本与发布.md#2-固件五档与红线)。

## 6. 采集端（可选）

采集端已退出主链路（位置数据改由视频解算），保留用于机型能力复验与原始帧取证。

```bash
cd PhoneCamera/pc
start_service.cmd          # 端口 8765，token ab12cd34，数据落 ./data，限速 40 Mbps
```

面板地址 `http://<pc-ip>:8765/`。App 与 PC 处于同一局域网，扫码或手输 `ip:port` 配对。

构建 APK：

```bash
cd PhoneCamera/android/m0probe
gradle assembleDebug       # 无 wrapper，需外部 Gradle 8.9；local.properties 指向 Android SDK
```

采集数据落于 `PhoneCamera/pc/data/sessions/<sid>/`，未纳入版本控制。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: host` | 工作目录不是 `RemoteControl/host` | 切换到该目录，或设置 `PYTHONPATH` |
| `cv2` 无 `aruco` 属性 | 安装的是 `opencv-python` | 卸载后安装 `opencv-contrib-python` |
| 页面可打开但内容为空 | 前端启动期异常 | 查看页面提示的阶段；`Ctrl+Shift+R` 清除缓存 |
| 串口可打开但收不到数据 | 烧写了比赛档，或波特率不符 | 改烧 `Target_Remote`；确认 115200 |
| 取流十余秒后静默 | 透传模块被灌满 | 断电复位，降低 `N` |
| 视频解析全部无效 | 未传 `--config` | 使用 `video_session.py` 或显式 `-c config.yaml` |
| 发车被拒绝 | 电池电压低于 7000 mV | 更换或充电；该限制为有意设计 |
| 轨迹缩放错误 | `Control/config.yaml::arena` 与 `Auto Locate/config.yaml::field.field_size_mm` 不一致 | 两处场地尺寸保持相同 |
