# 系统架构

四层、两条边界、五条数据流。本文只讲**跨模块**的东西；每层内部的模块划分看各自 `docs/`。

---

## 1. 分层与职责

| 层 | 模块 | 只负责 | 明确不负责 |
|---|---|---|---|
| 采集 | `PhoneCamera/` | 手机端取帧（Camera2 连续流 + `SENSOR_TIMESTAMP` 抽帧）、分片回传、落盘校验 | 不解算位置，不做业务判断 |
| 定位 | `Auto Locate/` | 一张图/一段视频 → 0 号标记位姿 + 帧时间轴 + 迷宫多帧融合 | 不碰串口，不认识"电脑鼠" |
| 整合 | `Control/` | 九页界面、设备会话、记录、回放、发车收车编排 | 不自己实现串口协议，不自己实现定位 |
| 链路 | `RemoteControl/host` | 严格停等的命令/遥测通道、参数镜像、模拟器、离线分析 | 不做 UI，不做视觉 |
| 固件 | `RemoteControl/code_competition*` | 1 ms 中断里的运动/传感/中止兜底、链路协议引擎 | 不做规划优化以外的决策 |

**方向单一**：箭头只往下走。`Auto Locate` 不知道 `Control` 存在，`host` 不知道界面长什么样。

## 2. 两条边界（最容易踩错的地方）

### 2.1 `Control` ↔ `host`：同进程 `import`

```python
from host.api import MouseClient     # Control 直接 import 上游，不另起进程
```

- 同一个 asyncio 事件循环里，`MouseClient` 自己开**回调线程**。
- **纪律**：回调里只能把事件投进总线，不许调会阻塞等设备的 API（会抛 `ReentrancyError`）。
- 端点函数**零阻塞**：串口往返、扫盘一律 `run_in_executor`。
- 好处：遥测帧、参数镜像、会话状态只有一份，不存在"两个进程抢同一个串口"。

### 2.2 `Control` ↔ `Auto Locate`：子进程

```bash
python Control/tools/video_session.py --source <mp4> --out <dir> --config "Auto Locate/config.yaml"
```

- **不要**直接 `python -m aruco_locator.session`：它的 `__main__` 不收 `--config`，
  会退回内置默认配置（720p 必需的 `detection.scales=[1,2,3]`、内参、视差全部失效），
  结果是一堆无效帧，然后被误判成"这个视频不行"。`video_session.py` = 补 `--config` 的薄壳。
- 权威产物是会话目录里的 **`session.json`**；`video_session.py` 打的那行 JSON 只是给日志看。
- 只杀本次会话起的那个子进程；被杀记为 `cancelled`，不是 `failed`。

## 3. 五条数据流

### 3.1 视频 → 轨迹（离线定位）

```
mp4 ──► aruco_locator.session ──► <session>/session.json + trajectory.csv + frames.jsonl
              │                            │
              │ 每帧：位姿(x,y,θ) + 质量标志   └──► Control 轨迹回放页 / 迷宫融合
              └ 多帧融合：逐帧迷宫观测 → 墙图
```

关键设计：**位姿与时间轴一起给**。只给位姿不给"这一帧是第几毫秒"，回放就对不上遥测。

### 3.2 命令 → ACK（下行）

```
Control 端点 ──► MouseClient ──► 串口/蓝牙 ──► 固件 SysTick ISR
   ▲                                              │
   └──────────── ACK（首 token "OK" + 附加字段）──┘
```

严格停等：**在途最多 1 条**。`RTT ≈ 300 ms` 在 PC 侧 CH340 上，所以帧率 ≈ N / RTT。

### 3.3 遥测帧（上行）

- 统一帧 **载荷 30 B / 线上 38 B**，含转速、姿态、里程、坐标、红外/墙位、电源、迷宫与冲刺状态。
- 拉取一律用批量 `RATE PULL <n> <t>`；**禁止 `RATE FIX <hz>`**（连续发流会灌死透传模块）。
- `n=1` 停等、`n≥2` 批式，容量顶 13.3 Hz（安全顶见根 README 的安全红线）。

### 3.4 建图增量（`mapd`，协议 v10 起）

每帧捎带 3 条 × 2 B 的建图增量，**自带绝对坐标**，实时同步车内的迷宫。

> ⚠️ `MAP DUMP` 是 **Flash 存档快照**，不是实时墙图。要看实时图只能走 `mapd` 通道。

### 3.5 手机分片交付（`PhoneCamera` 内部）

```
App: POST /api/v1/files/init ──► PUT /api/v1/files/{id}（Content-Range + CRC32 分片）
                              ──► POST /api/v1/files/{id}/complete（整文件 SHA-256 通过才 verified）
```

只有三种状态：`partial / verified / failed`。`verified` 只由**整文件** SHA-256 通过产生。

## 5. 时钟

三套时钟，不要混：

| 时钟 | 来源 | 用途 |
|---|---|---|
| 墙钟 (`wall_clock_ns`) | PC | 落盘时间戳 |
| 发车毫秒 (`t_ms`) | 固件，发车清零 | 遥测时间轴（把每帧映射到"发车以来毫秒"） |
| 传感器时间戳 (`sensor_timestamp_ns`) | 相机/手机 | 抽帧间隔、滚动快门 skew |

`Control` 的 `clock` 端点族（`offset / mark / fit`）负责把三者对齐；蓝牙抖动不许污染时间轴。
