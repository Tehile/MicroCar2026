# 系统架构

各子系统内部的模块划分见其 `docs/`。

---

## 1. 分层与职责

| 层 | 模块 | 职责 | 不承担 |
|---|---|---|---|
| 采集 | `PhoneCamera/` | Camera2 连续取帧、按 `SENSOR_TIMESTAMP` 抽帧、分片回传与逐文件校验 | 位姿解算、业务判断 |
| 定位 | `Auto Locate/` | 单图/视频 → 0 号标记位姿、帧时间轴、多帧迷宫融合 | 串口通信、设备控制 |
| 整合 | `Control/` | 九页 Web 界面、设备会话、记录与回放、发车收车编排 | 串口协议实现、定位算法 |
| 链路 | `RemoteControl/host` | 严格停等的命令/遥测通道、参数镜像、设备模拟器、离线分析 | 界面、视觉 |
| 固件 | `RemoteControl/code_competition*` | 1 ms 中断内的运动控制、传感处理、中止兜底、链路协议引擎 | 路径规划之外的决策 |

依赖方向单向向下：`Auto Locate` 不感知 `Control` 的存在，`host` 不感知界面实现。

## 2. 集成边界

### 2.1 `Control` ↔ `host`：同进程导入

```python
from host.api import MouseClient
```

- 与上位机处于同一 asyncio 事件循环，`MouseClient` 内部自建回调线程。
- 回调线程内只允许向事件总线投递事件，不得调用会阻塞等待设备的 API（触发 `ReentrancyError`）。
- 端点函数保持零阻塞：串口往返、磁盘扫描通过 `run_in_executor` 执行。
- 收益：遥测帧、参数镜像与会话状态各只有一份，不存在多进程争用同一串口。

### 2.2 `Control` ↔ `Auto Locate`：子进程

```bash
python Control/tools/video_session.py \
    --source <mp4> --out <dir> --config "Auto Locate/config.yaml"
```

- `aruco_locator.session` 的 `__main__` 不接受 `--config`，直接调用会退回内置默认值，
  导致 `detection.scales`、相机高度与视差参数失效。`video_session.py` 负责补齐该参数。
- 权威产物为会话目录中的 `session.json`；该脚本打印的单行 JSON 仅供日志使用。
- 进程边界独立：仅终止本次会话对应的子进程，取消记为 `cancelled`，与 `failed` 区分。

### 2.3 进程模型

| 进程 | 数量 | 说明 |
|---|---|---|
| `Control/app.py` | 1 | 含 `host.api` 客户端，占用串口 |
| `video_session.py` | 按会话 | 每次解析一个子进程，结束即退出 |
| `host.sim.mouse_sim` | 0 或 1 | 无硬件时替代真机，TCP 5555 |

## 3. 数据流

### 3.1 视频 → 轨迹

```
mp4 ──► aruco_locator.session ──► <session>/session.json
                                  ├─ trajectory.csv   逐帧位姿 (x, y, θ) + 质量标志
                                  └─ trajectory.png   轨迹可视化
        └─ 多帧融合：逐帧迷宫观测 ──► maze_structure.png
```

位姿与时间轴同步输出。仅提供位姿而缺少「该帧对应第几毫秒」，无法与遥测时间轴对齐。

### 3.2 命令 → ACK（下行）

```
Control 端点 ──► MouseClient ──► 串口/蓝牙 ──► 固件链路层
   ▲                                            │
   └──────────── ACK（首 token "OK" + 字段）─────┘
```

严格停等：在途命令最多 1 条。PC 侧 CH340 的 `RTT ≈ 300 ms`，因此帧率 ≈ N / RTT。

### 3.3 遥测帧（上行）

- 统一帧载荷 30 B、线上 38 B，含转速、姿态、里程、坐标、红外/墙位、电源、迷宫与冲刺状态。
- 拉取使用批量命令 `RATE PULL <n> <t>`；禁止 `RATE FIX <hz>`（连续发流会饱和透传模块）。
- `n=1` 为停等，`n≥2` 为批式。容量上限约 13.3 Hz，安全档位见根 README §10。

### 3.4 建图增量（`mapd`，协议 v10 起）

每帧携带 3 条 × 2 B 的建图增量，带绝对坐标，实时同步车内迷宫。
`MAP DUMP` 为 Flash 存档快照，不是实时墙图；实时图只能经 `mapd` 通道获取。

### 3.5 手机分片交付（`PhoneCamera` 内部）

```
App: POST /api/v1/files/init ──► PUT /api/v1/files/{id}（Content-Range + CRC32 分片）
                             ──► POST /api/v1/files/{id}/complete（整文件 SHA-256 通过后置 verified）
```

文件状态仅三种：`partial`、`verified`、`failed`。`verified` 只由整文件 SHA-256 校验通过产生。

## 5. 时钟

系统内并存三套时钟，不得混用：

| 时钟 | 来源 | 用途 |
|---|---|---|
| 墙钟 `wall_clock_ns` | PC | 落盘时间戳 |
| 发车毫秒 `t_ms` | 固件，发车清零 | 遥测时间轴 |
| 传感器时间戳 `sensor_timestamp_ns` | 相机/手机 | 抽帧间隔、滚动快门偏差 |

`Control` 的 `clock` 端点族（`offset` / `mark` / `fit`）负责对齐三者；链路抖动不得污染时间轴。
