# Control 前端界面 · 文档（control/static）

> 本目录是 Control 上位机的 Web 前端。当前这版是对齐 **改版二十四**（上游
> RemoteControl 2.13.0 / 通信协议 9 / 30 B 统一帧 / 33 通道 / 41 参数四组）的
> **扁平化重设计**，于本次提交整合进主仓库、取代旧前端。

---

## 1. 定位与服务方式

- 前端由 `app.py` 托管：根路径 `/` 返回 `index.html`，`/static/` 前缀返回本目录
  下的全部静态资源（`assets/` 子目录在浏览器侧解析为 `/static/assets/...`）。
- **两种模式，一个开关**（`assets/lib.js` 的 `LIVE.on`）：
  - `LIVE.on === false`（**默认**）：**原型模式**。250 ms 模拟 tick 本地造数，
    不连串口、不起子进程。用于脱离设备做视觉评审。
  - `LIVE.on === true`：**真机模式**。启动时探 `GET /api/v1/health` +
    `GET /api/v1/caps`，探通就自动切真数据（WS 遥测 / REST 动作）。
  - **不做真假混合**：切换只发生在 `LIVE.on` 这一处，真值与假值不互相覆盖。
- 查看方式：
  - 正式：`python app.py`（在 `Control/` 仓库根），打开 `http://127.0.0.1:8770/`。
  - 纯前端预览：从本目录起静态服务器即可，但注意 `index.html` 用的是
    `/static/assets/` **绝对路径**，需支持该前缀的服务器（`app.py` 即满足）。

## 2. 路由与情景

- 路由基于 hash：`#/overview` `#/live` `#/params` `#/race` `#/maint`
  `#/video` `#/track` `#/data` `#/replay`。非法/空 hash 回退到 `overview`。
- 情景开关（**仅原型有效**，左轨下拉或 `?scene=`）：
  | 值 | 现场 |
  | --- | --- |
  | `ready` | 就绪 · 待发车 |
  | `run` | 运行中 · 冲刺 |
  | `estop` | 急停 · 锁存 |
  | `down` | 断连 · 两路都空 |
  | `oldfw` | 旧固件 310 · 4 灯判不了（三态显示「未知」） |
  | `novideo` | 无视频 · 只跑小车 |
- 进页面即开设备抽屉：`?dev=mouse|clock`。

## 3. 视觉语言（扁平工业图纸）

1. **纸白 + 细网格底**（背景 `#F2F1EC`，32 px 网格线），面板纯白；**1 px 硬边、
   0 圆角、无阴影、无渐变**。层级只靠面积、对比、留白。
2. **大色块承载状态**：黑 `#121316`（就绪/运行块）、蓝 `#2B4FF2`（主操作）、
   绿 `#00805A`（可以走）、琥珀 `#E39A00`（要看一下）、红 `#D62B1F`（别动）。
3. **数字等宽**（读数仪表，不是正文）；标签等宽小字 + 字距。
4. **零解释文案**：界面只放状态 / 数值 / 控件 / 门控 / 下一步；机制与背景归 `docs/`。
5. **三态纪律** `true / false / null`：`null` = 斜纹底 + 「未知」，绝不涂成「灭」或红。
6. **示意图代替说明文**：三栏来路、视频流水线、迷宫、轨迹、时间轴都画成图。

## 6. 九页面逐页

### `#/overview` 总览
- 主角：**「下一步」色块**（据当前状态推下一步动作）+ 本次会话黑块（时间/帧数/链路）。
- 三栏结构图进各模块；快捷指令直接触发动作。
- 记录项 foot 显示账本计数（如「账本 4/5」）。

### `#/live` 实时状态
四块（按评审意见精简，去掉大卡片、轮速类图表移出）：
1. **实时帧率**：大数字（40 px 等宽）+ Δ + 迷你曲线（`spark`）。
   **帧率表已删** —— 迷你曲线已经把"帧率变化"画出来了，表格是重复信息。
2. **拉取开关**：`拉取 | N [输入框] | 开始拉取 | 结束拉取` + 状态胶囊（拉取中 / 已结束）。
   - **切 N 的姿势：结束拉取 → 改 N → 开始拉取**。开流前上游会
     `configure(1, t_ms)`，档没在位就开流 ⇒ 设备按 n=1 发、界面却写着 n=3。
   - 门控：拉取中 ⇒ N 输入框锁住、只放【结束拉取】；停了 ⇒ N 可改、只放【开始拉取】。
   - 真机模式：`开始拉取` = `POST /api/v1/mouse/stream/batch`（先落 N）→
     `POST /api/v1/mouse/stream`（再开流）；`结束拉取` = 关流
     （上游 v2.1 的 `off()` 立刻丢弃在途请求，是排空蓝牙缓冲的排障手段）。
   - **【结束拉取】是最高权限且粘住**（改版四十七）：点下去 ⇒ 后端 `pull_mode="off"`，
     **切页、发车、复位、收车都不会把它开回来**；跨重连保持，进程重启回常开。
     面板状态词按 `link.state` 分（已停（手动）/ 链路疑似 · 复核中 / 链路无应答（串口仍开）/
     自动补流中），**红只给 `dead`** —— 手动停和"在等第一帧"都不是故障。
   - 原型模式：N 与开关只改本地，不打后端（打过去必然失败，只会一直弹"没连上后端"）。
   - **停了就是真的没有新帧**：读数停在最后一帧、帧龄往上走，页面给「拉取已结束」
     提示条；不接着假造 Hz。
3. **状态行 · 4 灯**：小条（`led-strip`），非大灯带；三态（亮 / 灭 / 未知）。
   卡内下半是**链路**四项（双列）：字节率 `bps` / 设备 `streaming` / 批次号 `seq` /
   序号缺口 `lost`。这四个是后端 `mouse.telemetry` 的**顶层字段**，不是帧内通道。
   - `bps` 直接取后端的，**不要拿 `rate × 30` 自己乘**：30 B 是帧长常量，
     真实字节率还含帧间静默与批头，前端算出来的只是理论值。
   - `streaming`（设备在不在发）与 `S.pulling`（人有没有点拉取）**是两码事**，
     不许互相顶替。
   - `lost` 由批次号跳号累计；**切到真机的第一拍不算缺口**（本地 mock 的 seq
     和设备 seq 毫无关系，直接相减会算出几百个假丢帧）。
4. **统一帧通道**：按 6 组展示（见 §7）；项 ≥4 的组排双列
   （窄屏自动隐去原始字段名，避免中文标签被折断）。
   - 卡头那个数字**跟着 `caps.unified_channels` 走**（协议 v10 = **32**，v9 = 33）。
     以前写死 `· 33`：`encAngle` 被协议删掉之后，界面还在报一个不存在的通道数。
   - 每项的值**带单位与精度**，取自通道码表（`speedL` = `0.0 cm/s`、`posX` = `1.50`）；
     以前一律 `fmt(v, 0)`，看起来像"协议只给了整数"。
   - **饱和要标出来**：v10 起 `irMm[4]` 是 u8，255 是**饱和值**不是距离
     ⇒ 显示 `≥255 饱和`。显示成 `255 mm` 就是给了一个没测到的距离。
   - **假精度不许给**：`batt` 在 v10 里是 `round(mV/50)` 的 u8 ⇒ 显示 `12.35 V`
     （50 mV 量子），不显示 `12347 mV`。
   - 派生键（`dirName`/`mazeTaskName`/`roadName`/`freemode`）**不重复列** ——
     它们与 `dir`/`mazeTask`/`goOrBack`/`flags` 是同一份事实，两处显示就是两条真相。
     只有出现**前端不认识的新键**时，链路区下方才多一行「另有 N 个未识别键」。
5. **手动运动 dpad**：方向键手动走（仅远程档生效）。

### `#/race` 比赛
- 左栏：竖直一排列出的统一帧通道卡（除帧率与手动运动）。
- 中栏：迷宫图（`draw.maze`，蓝 2×2 = 终点、蓝块 = 车）。
  - **三态**（协议 v10 起）：已知墙**实线**、未探明**点线**、没走到过的格**淡底**。
    `v/h` 的元素取值 `0` 可通 / `1` 有墙 / `2` 未探明。老记录（v9）只有 0/1，
    `2` 是增量建图才有的第三态。
  - **点线只画在探索前沿**（至少有一侧走过）。整片没走过的区域都画点线的话，
    16×16 就是一张虚线网 —— 那堆线既不是"墙"也不是"待定"，只是噪音，
    还把真正要看的边界盖住了。淡底已经在说"这里没数据"。
  - **一格都没探到时不涂底**：那时整张图就该是纯空白（"还没数据"），
    涂满一片灰反而像"已经有内容了"。
  - **轨迹用 40% 墨色，不是纯黑**：纯黑是**墙**的颜色。同色时一条穿过格心的线
    看上去就是一道墙 —— 图和墙互相冒充（实测时图上"多出来的墙"其实全是轨迹）。
  - 卡头三个标签：`尺寸` + **来路**（`固件增量` / `主机推断` / `等待数据`）+ `已探明 n/N`。
    两种图的"未探明"含义不同（`不知道` vs `没走到`），混在一起看会得出相反结论。
  - 图例右侧是**这张图的来路**（轨迹点数 / 累计帧 / 覆盖时长）；
    它放在卡头会把标题挤成"迷宫重 / 构"两行，所以并进图例行。
  - 卡下方两行：**图例**（一行，四条）+ **建图诊断**（条目 / 重锚 / 序号断 / 环溢出 / 坐标差 / 面冲突 / 对账，成对排一行）
    与**警告**（序号断过 / 环溢出 / 坐标差 ≥2 格 / N=1 建图跟不上）。判不了给 `—`，不给 `0`。
  - ⚠️ **对账数不进警告**：它是两条独立来路（固件绝对坐标 vs 主机相对朝向）的分歧数，
    主机那套本来就比固件粗，实测 3/47、长跑 54/370 —— **恒非 0 是预期**。
    做成告警就成了常亮红灯，现场会当噪音忽略；它的价值在**突变**（3 跳到 50）。
    所以只在**分歧过半**（且样本 ≥8）时才提一句。
  - ⚠️ **图例那行不许折行、诊断那行只许一行**（改版四十）：正方形地图的边长是
    `min(可用高, 可用宽)`，这两行每多占 1 px 垂直线，图就小 1 px（实测折行 ⇒ 366→339）。
    图例标签一律压到 2~3 字，解释（"探索前沿" / "无数据"）进 `title`。
  - ⚠️ 图上**不同时画两张**（一元素一真相）：主机推断那份只用于**对账**。
- **地图边长由中栏卡片自己的 `clientHeight` 现算**（`fitMaze()`，改版四十重写）：
  地图是正方形，宽度再富余也用不上，只能由较紧的一边定。
  口径：`可用高 = 卡片正文内高 − 上下 padding − 图例行 − 诊断行 − 1`、`可用宽 = 正文内宽`，
  下限 220（再小格子线就糊了，不如让页面滚）。
  - ✅ **量自身，不量 `window.scrollY`**。原先算的是 `body.getBoundingClientRect().top +
    window.scrollY` —— 那是**视口相对位移**：整页往下滚 ⇒ top 变小 ⇒ 可用高变大 ⇒ 每 250 ms
    的 `onTick` 重画就换一个边长。**"滚轮会缩放地图"就是这么来的，代码里根本没有缩放功能。**
  - ✅ 画布宽度**只由 `fitMaze()` 写 `style.width`**，CSS 里不再有 `width:100%`
    （否则它会把边长拉成卡片宽度，与"按高度算出来的边长"打架）。
    因此"布局好了没"的闸不能再用 `cv.clientWidth`（首帧恒 0 ⇒ 永远不画），改成 `cap != 0`。
  - 1400×710 实测 **366 px**（改版四十之前 351）。
- **三列各自滚**（改版四十）：`.main` 高度由 `fitMain()` 实测钉死（`flex:0 0 auto`，
  不能留 `flex:1` —— `flex-basis:0` 时行内 `height` **完全不参与计算**），
  左栏 / 中栏 / 右栏各自 `overflow-y:auto`。整页滚会把三列一起带着走。
  - 还要 `#view{display:flex;flex-direction:column;min-height:0}`：它默认 `display:block`，
    子元素的 `flex:1` **一点用都没有**（实测三列都不滚、列表把日志坞顶出 1762 px）。
- 右栏：检查 + **比赛发车**（76 px 大键）+ 停止并保存 / 收车 / 复位，竖直排列。
  - **【停止并保存】的四态**（改版四十）：`在记 · 停止并保存` / `保存中…` / `已保存 · <名> · N 帧` / `没记成`。
    车自己停下时后端**已经**收尾落盘了（`_maybe_finish_maze_rec`），所以：
    - 前端 1 s 轮询 `GET /mouse/maze/record` 拿状态（**全站以前一次都没调用过它**）；
    - 按钮进入"已保存"后**不可再点**，也不许再发 `stop`（那会写一份空记录）；
    - 状态里 `{ok:null, pending:true}` 是**占位**：`stop()` 从关掉记录到落盘有几毫秒~几十毫秒，
      1 s 轮询正好撞上时会把**上一次**的摘要当这一次。
  - **停止原因**（`STOPPED <reason>`）显示在「迷宫状态机」卡下方的绿条里：
    时间护栏到 与 红外护栏触发 在帧数据里长得**一模一样**，只有这条上行事件能区分。
    没停过就**不显示**（空着，不写"未知" —— 那看着像一条故障）。
    来路是 WS 的 `mouse.upevent`（`ws.py` 早就订阅了，`lib.js` 的 WS 分发曾漏掉这个分支，
    数据到浏览器门口被丢）。
- 已按评审意见去掉前墙双档。

#### 比赛页的拉取：**面板留着，但页面没有开关权**（改版四十一建 / 四十七改口径）

- 面板一行 `#rc-pull` = `C.pullPanel()`（与实时页同一个组件）：`实时帧率 · N · 【开始/停止拉取】`。
- **拉取默认常开**，这一页不再"进页开一次"，也没有"停车就停"：
  `NEED_PULL` / `GUARD_PULL` 两张表与前端看门狗已整段删除。
  面板在这里只干两件事 —— **看**（发车前帧龄/帧率）与**停**（人按【结束】，`pullIntent='off'` 粘住本会话）。
- **收车/复位不再停流**（改版四十七）：观察窗里只判"车真停了"（动作码），**流一直开着**。
  - 点【收车】/【复位】当拍进 `_pend`（按钮禁用 + 「收车中…」/「复位中…」+ toast + hint），
    **重复点被吞**（一条链路只排一条命令）。
  - 命令回来**不停流**，进观察窗：每拍看**动作码**，`motionTask ∈ S.motionStop`（`[0,5]`，由 `/caps` 下发）
    ⇒ `pinRunning(false)` + 收尾。窗口 8 s / 复位 10 s，超时也收尾并**如实**说"未确认"。
  - 为什么不能抢在回执前面停流（改版四十二的教训）：`maze_stop()` 里
    `_wait_fresh_frame()` 永远等不到新帧 ⇒ `reliable=null`。
    为什么不能只等回执（四十三的补充）：流本来就停着时后端 0.3 s 内回"判不了"，
    界面当场说「点【开始】拉一次帧即可确认」，**不假等** 2.5 s（更不能偷偷替人开流）。
  - 复位额外要求：动作码空闲 **且** 0.8 s 后 1.5 s 内确实有帧到达（复位前那一帧也可能是空闲）。
  - **等确认期间断链** ⇒ 如实说"未确认"，**不许**把 `resetTelemetry()` 归零的 `motionTask` 当成"车停了"。
- 旧的三信号跳变停流（`S.rec.on` 真→假 / `S.running` 真→假 / 观察窗确认 ⇒ `stopPullOnce()`）
  **已删除**（连 `_wasRun`/`_wasRec`/`_pullStopAt` 一起），留着只会让下一个人以为这页还在管拉取。

- **"车在不在跑"只看动作码**（改版四十三）：`S.running = motionTask ∉ S.motionStop`。
  `mazeTask` 是**迷宫流程态**（车停稳后可能仍在高位），拿它当门控就会出现
  "任务机已经 WAIT、发车键还是灰的"。发车键置灰的四个理由（未连接 / pending / 急停 / 真在跑）
  **同一个字符串**同时进 `title` 与 `#rc-hint` —— 灰着必须说得出为什么。
- **动作码表由后端下发**（`/caps.motions`，上游 38 项 + 中文短名），前端那份只作离线兜底；
  未知码显示 `未知(123)`，**不许**退回裸数字（现场看"动作 14"没法判读车在干什么）。
- **发车状态由命令与帧共同决定**（改版四十二）：`S.runPin` + `pinRunning()`/`applyRunning()`。
  命令回执后 2.5 s 内**钉住**结果（旧帧不许推翻），窗口过后**下一个到达的帧**说了算。
  没有这一层就会出现"收车成功 → 已发车 闪成 比赛发车 → 又变回 已发车"，而且**永久停在错的**
  （流已停，没有帧来纠正）。判据 **V18** 两个方向都验。
- **断开即归零**（改版四十三）：`applyHealth` 检 `connected` 下降沿 → `resetTelemetry()`
  （累计量 0 / 测量量 null / 曲线清空 / 4 灯未知 / `mazeView=null`）；上升沿补一次
  `syncPull(S.route)`。判据 **V20**。

- 删除是两步确认（5 s 内再点），按 `(时间, 记录 id)` 一对判定。

  与**库里就没有**（"还没有记录"）。一句"暂无数据"把两种情况糊在一起，
  人会去怀疑后端。
- **改版四十五：列表不再"50 条就到底"**（分页 + 搜索自动载全）：
  - 三个量**分开说**：`S.records.length`=**已载**、`S.recTotal`=**全库**（后端 `total`）、
    `visible()`=**当前筛出**。卡头写「已载 50 / 共 345 条」；未载全时发车/视频两个胶囊
    加 `≥`（它们只统计已载那批）、全选 `title` 写「全选已载的 N 行（另有 M 条没载入）」。
    **不许**在未载全时说"共 3 条发车"。

  - **搜索 / 切筛选时自动载全**（`ensureAll` → `?n=0`）：只在已载的 50 条里搜，

  - ⚠️ 页头那三个胶囊也是 `actions()` 现算的：续页不发 `state` ⇒ 必须由 `paint()`

### `#/replay` 回放
**一屏放下位置图与时间轴，不来回滚，且地图尽量大**（地图是正方形 ⇒ 只由**可用高度**决定）。
- **`fitStage()` 现算舞台高度**（`views/replay.js`）：布局顶边的文档坐标 → 视口底，
  减去日志坞高度和主区底内边距，取整后写到 `.rp-layout` 的 `height`。窗口一变就重算。
  CSS 里那条 `calc(100vh - 300px)` 只是 JS 未跑到的兜底；≤1220 宽是堆叠布局，
  `fitStage()` 会把内联高度**摘掉**。
- **左卡 = 位置图 + 时间轴，同一张卡**：
  - 地图 `flex:1` 吃掉剩余高度。canvas 边长 = `min(容器宽, 容器高)`，
    由 `draw.maze(cv, M, cap)` 的第三参传入 —— **不是**按宽度走正方形
    （那正是原来左栏 1000 px 宽 ⇒ 1000 px 高、整页被顶出去的原因）。
  - 卡头右侧带图例（已知墙 / 未探明 / 终点）。图例单占一行要 26 px，
    而地图按可用高度定边长 ⇒ 那 26 px 直接等于地图小 26 px。
  - 底部是 `scrub` 时间轴，**两行**：一行是 播放 · 1·2·4× · ±1 s · 时间码 · 帧号，
    另一行是拖动条（发车·收车标记 + **采样缺口带子**）。
  - **发车/收车标记只认动作码**（改版四十四，`paintMarks()`）：位置来自后端的
    `run_from_s` / `run_to_s`（`motionTask ∉ {0,5}` 全帧切段 + 300 ms 去抖），
    **不是** `rec.launch`（那只是"记录是怎么开的"），更不是进度条末尾。
    样子：2 px 竖线（发车蓝 / 收车绿）+ 加粗标签「发车 00:01.2」/「收车 00:23.1」，
    两线之间铺一条 3 px 淡色带 —— 还是这条 16 px 的条，**不是第二条时间轴**。
    `phases === null`（无动作码通道）⇒ **一根都不画**，只写「判不了」；
    `runFrom === null`（有通道但全程没动）⇒ 写「全程未动」。
    ⚠️ 它是**方法**不是 `mount()` 里的内联代码：判据要能直接驱动它验"判不了时不画"，
    重挂页面会把刚摘掉的 `phases` 重新拉回来（V22 踩过一次）。
- **右卡 = 状态，与实时页同一张码表**（改版四十六）：`CH.groups` 的 6 组 30 项 +
  4 灯三态，DOM 建一次、值逐帧刷（与 `live.js` 的 `[data-k]` 同一套）。
  - 值一律 `C.fieldValue(rec, sm, key)` —— 后端把整行通道压成 `v` 数组（与 `fields`
    同序），**前端不自算派生量**：`frontNear`/`irSwitch` 由后端按上游 `codec.py` 的
    恒等式补，4 灯三态由 `control/leds.py` 判（`fw<311` 那 4 位是预留恒 0，
    所以**没存 `fw` 就说"未知"**，绝不画成"灭"）。
  - 卡片吃满右栏高度、**正文自己滚**，卡头（运行 pill + `t`）常驻 —— 拖时间轴时
    它是读数锚点，跟着滚走就等于每次重新找。
  - 336 px 宽的双列里放不下「中文标签 + 原始字段名」（实测「双档命中 frontBoth」
    会折成"双档命/中"）⇒ 只留中文标签，字段名进 `title`。
  - 缺的东西如实说：老记录没有 `fw` ⇒ 4 灯「未知」+ 一句原因；实时页的**链路四项**
    （`bps`/`streaming`/`seq`/`lost`）记的是当时的连接状态，记录里没有，回放不装。
  - ⚠️ `CODE` 里 `frontNear`/`frontFar`/`frontBoth` 是**三个 0/1 位**，不是档位枚举
    （上游 `STATE_C_FRONT_FAR=0x08` / `STATE_C_FRONT_BOTH=0x10`）。以前三项共用

- **右栏 = 状态**：随帧变化的 KV（时刻 / 帧号 / 位置 / 朝向 / 迷宫任务 / 动作 /

## 7. 数据模型（assets/lib.js）

- **`S`** 运行时状态：`route` `scene` `log` `toasts` `params` `records` `recSel`
  `rateLog` `pullN` `pullMode:'batch'` `pulling`（拉取开关）`leds` 等。
- **`C`** 常量/能力：`NAV` `VIEWS` `channels` `records` `record/recordView`
  `maze/Maze` `icon` `util` `pullBatch` `setPull`。
- **统一帧通道**：对齐上游 v9（30 B 统一帧 / **33 通道** = v9.1 的 29 + 4 个 LED），
  前端按 6 个语义组展示（LED 四位单列成「状态行 · 4 灯」）：
  1. 运动与姿态（左/右轮速、陀螺角、编码器角、动作、朝向）
  2. 里程与位置（左/右里程、位置 X/Y）
  3. 迷宫判定（迷宫任务、左/前/右墙、前墙近/远端、双档命中、红外采样）
  4. 比赛冲刺（冲刺档位/标志、去回、冲刺试探、物体去向、前冲计数）
  5. 四路红外（前左/前右/左/右）
  6. 电源与链路（电池 mV、帧时基低 8 位、标志位）
- **41 参数（四组，page 115）**：
  | 组 | 范围 | 下发 |
  | --- | --- | --- |
  | 生产标定 `base` | 01–07 | SET + SAVE |
  | 红外测量 `ir` | 22–32 | SETQ + SAVE |
  | 电源监控 `batt` | 33–38 | SETQ + SAVE |
  | 运动控制 `motion` | 39–55（仅远程档生效） | SETQ + SAVE |
- **帧率采样 `rateLog`**：每批一条 `{ seq, n, ms, hz }`；`pullBatch(n)` 设 N
  （`n` 即 `S.pullN`，决定每批帧数，区间 1–16）。
- **拉取开关 `setPull(on, n)`**：
  | | 真机模式（`LIVE.on`） | 原型模式 |
  | --- | --- | --- |
  | 开始 | `POST /mouse/stream/batch`（落 N）→ `POST /mouse/stream`（开流） | 只改本地 `S.pullN` / `S.pulling` |
  | 结束 | `POST /mouse/stream {on:false}`（关流，丢弃在途） | 只改本地 `S.pulling` |
  - **顺序不能反**：先落 N 再开流。上游 `stream.on()` 每次都 `configure(1, t_ms)`，
    档没在位就开流 ⇒ 设备按 n=1 发、界面写着 n=3。
  - 事件走 `emit('health')` 而**不是** `emit('state')`：后者会整页重挂，
    把用户正在输入的 N 清掉。
- **记录 `records`**：5 条历史，字段 `id / start / dur / frames / launch（有无发车记录）
  / launchAt / video（关联视频会话 id，可空）/ ledger / gap / seed / mazeSeed / dir`。
  `recordView(rec, i)` 给出第 `i` 时刻的迷宫快照与截断到当前帧的轨迹。

## 10. 已知边界

- **原型模式下**没有一行网络请求；「连接」「开始记录」「视频解析」等只改本地状态
  或跑定时器。**真机模式**下这些都会真发请求（见 §1 的 `LIVE.on`）。
- 迷宫为确定性回溯生成（固定种子），不是真机地图。
- 回放的位置 / 迷宫墙图来自本地造的采样序列（`C.recordView`），不是真机数据。
- 参数表、比赛记录表、回放、迷宫图**还没接后端**（后端 shape 与前端不一致）——
  真机模式下这几页仍显示原型数据。
- 响应式做到 1280 宽可用；更窄未细调。底栏日志坞 sticky，主区留 56 px 底部内边距。
- 拉取开关在真机模式下依赖后端 `/mouse/stream` 与 `/mouse/stream/batch`；
  上游不支持批式拉取时后端回 501，前端如实报「没开起来」。

  实时状态页总高从 1158 px 降到 1010 px（1600 宽下能一屏看全）。

### 11.2 比赛记录页：控制面板置顶

- 原先「记录表在上、详情+操作在下」。记录一变长（真机几十条），选中条目后
  还得把页面滚到底才能点「回放」，操作路径和选中动作是分开的。
- 改为 **面板在上 + `position:sticky` 吸顶 + 列表独立滚动**：
  - 面板压到 121 px 高（原 ~236）：按钮从右栏竖排 5 个改成头行横排，
    KV 从单列 8 行改成四列两行；
  - 列表 `max-height: calc(100vh − 460px)` 内部滚，表头 sticky；
  - 三种窗口高度（1000 / 860 / 760）实测整页 `over=0`，不再出现内外双滚动条。
- 顺带修掉一个隐藏坑：`.main` 的 `overflow-x:hidden` 会让 `overflow-y` 变 `auto`，
  sticky 因此完全失效 —— 改 `clip` 后实测滚 400 px / 971 px 面板 top 恒为 70 px。
- 未采用「记录分页」：分页只是把列表变短，选中条目后按钮仍在列表下方，
  没解决「选中与操作分离」这个根因；吸顶则任何条数下按钮都在视野里。

### 11.3 回放页一屏化 + 实时页补链路信息

**回放页原来要上下滚才看得全。** 两个独立原因叠在一起：

1. 地图按**宽度**走正方形 —— 左栏 665 px 宽就是 665 px 高的图，
   加上时间轴卡必然超出一屏。改成 `draw.maze(cv, M, cap)`，
   边长 = `min(容器宽, 容器高)`，由容器高度决定。
2. 「参数」（41 项）和「记录」两张卡挂在右栏，**它们和时间轴无关**
   （静态快照），却把页面撑到 1400+ px。

改法：
- 位置图与时间轴**并进同一张卡**（省一个卡头 + 一个间距 ≈ 38 px，
  这 38 px 直接换算成地图大一圈）；图例并进卡头（再省 26 px）。
- 参数 / 记录压到底部一条摘要 + 底部抽屉（58 vh，fixed 覆盖）。
- `.rp-layout` 高度锁 `calc(100vh − 326px)`：1600×1000 实测 `over=0`，
  地图从 369 → 409 px（另测 860 高窗口也不滚）。
  > ⚠️ **这个常数后来被证明是错的**（在 1400×710 这类矮窗口上扣太多，
  > 地图只剩 219 px）—— 见 §11.4 改成按视口现算。此处保留原样，作为经过记录。
**实时页补的是"协议在传、界面没显示"的那批**：(见 §6 `#/live` 第 3、4 条)
- 后端 `mouse.telemetry` 顶层还有 `bps` / `streaming` / `flags` / `events`，
  前端一个都没用 —— 字节率是拿 `rate × 30` 自己乘的。
- 33 通道的值原来一律按整数显示，码表里写着的**单位与精度没人用**
  （`0.0 cm/s` 显示成 `0`、`1.50` 显示成 `2`）。
- `applyTelemetry` 只写 `k in S.tel` 的键 ⇒ 解码器现算的派生键**全部丢弃**。
  现在收进 `S.tel.extra`；页面上只报"还有 N 个未识别键"，
  因为 `dirName`/`roadName` 等四个与已有通道同义，摆两遍就是两条真相。
- 代价：页高 1010 → 1061（多出的链路区），1600×1000 下需滚 161 px 看手动运动。
  这是"信息完整性优先"的取舍 —— 链路四项 + 单位是诊断时真正会被问到的。

### 11.4 回放页：地图太小 —— 高度不再估算，改成现算

11.3 的 `calc(100vh − 326px)` 里那 326 是**估**出来的（页头 72 + 底条 45 + 内外边距）。
在 1600×1000 上估算刚好，在 1400×710 上就扣多了：实测地图只剩 **219 px**，
而左卡有 790 px 宽 —— 一眼就是"一个大白框里一个小方块"。

改法（三条都在给高度让路）：

1. **`fitStage()` 现算**：布局顶边（文档坐标）→ 视口底，减日志坞实测高度与主区底内边距，
   取整写到 `.rp-layout` 的 `height`；`resize` 重算。≤1220 宽（堆叠布局）摘掉内联高度。
   取整要**向下取 + 留 1 px**：算满会出现 1 px 溢出 ⇒ 整页冒出纵向滚动条 ⇒
   顶栏与卡片整体窄 15 px，看起来像布局抖了一下。
2. **页面底部摘要条搬进页头动作区**（「参数 · 记录」按钮）+ 摘要句进抽屉头：省 45+12 px。
3. **时间轴从 110 px 压到 80 px**：把"标题 / 时间码 / 帧号"那行并进按钮行；
   回放页的 `main` 上下留白 26/56 → 14/12、页头下边距 16 → 10（`body[data-route="replay"]`）。

实测（地图边长）：1374×710 **219 → 370**、1574×900 **409 → 560**、1254×660 277 → 320；
三档 `docH == 视口高`（`over=0`，无滚动条）。窗口矮到算出 < 360 px 时按 360 兜底，
宁可让页面滚 3 px 也不把地图压成缩略图。

> 记一笔**为什么不用分页/拖动**之类别的办法：地图是正方形，宽度再宽也用不上，
> 唯一能变大的方向是"可用高度"。所以问题不是"地图组件画小了"，
> 而是**别的元素在跟地图抢高度** —— 解法只能是把它们搬走或压扁。

### 11.5 协议 v10：地图三态 + 通道 32（改版三十九，前端侧）

上游把协议推到 PROTO 10，地图不再是"主机推断"而是**固件事实**（每走一格报该格四向可通位）。
前端这一侧只动四处：

1. **`draw.maze` 支持第三态**：`v/h` 的元素 `0` 可通 / `1` 有墙 / **`2` 未探明**。
   已知墙实线（`#18191C`/2 px）、未探明虚线（`#D5D3C9`/1 px，`dash [2,3.5]`）、
   没走到过的格淡底（`rgba(24,25,28,.05)`）。
   - **一格都没探到时不涂底**：那时整张图就该是纯空白，涂满灰反而像"已经有内容"。
   - 老记录（v9）只有 0/1 ⇒ 第三态自然不出现，同一段代码兼容两代记录。
   - ⚠️ `known()` 那个"两侧都没走过就画虚线"的旧判据**保留**：它管的是"这面墙是不是
     贴着已知格"，与三态是两件事（v9 记录全靠它）。
2. **比赛页卡头加来路标签**（`固件增量` / `主机推断` / `等待数据`）+ 一行建图诊断
   （条目 / 重锚 / 序号断 / 环溢出 / 坐标差 / 面冲突 / 对账）+ 一行警告。
   判不了给 `—` 不给 `0`。警告里**不含自动动作**：N=1 只提示"建图跟不上"，不偷偷改档
   （档是人设的）。
3. **通道数跟着 `caps.unified_channels` 走**（v10 = 32）；`encAngle` 整条删掉
   （协议已删，留着的话界面上那个 274.1° 会一直挂着、其实不动）。
4. **饱和与假精度**：`irMm` 到 255 显示 `≥255 饱和`；`batt` 按 50 mV 量子显示 `12.35 V`。

> 为什么这三件都必须在前端做：后端已经把三态、`stats`、`diff` 都算好了
> （`/mouse/maze/reconstruct` 的 `view`），前端**只需要画**。
> 前端一旦自己再推一遍（比如自己按 `visited` 猜"这面墙可不可信"），就是第二份真相。
