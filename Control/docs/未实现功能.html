未实现功能清单

改版二十五起界面换成「左轨导航 + 九个页面」（#/overview #/live #/params #/race #/maint #/video #/track #/data #/replay），旧的两级「子系统 → 模块卡」 与「未实现 · 见文档」卡片机制都没有了（那张卡是 SYS_DEF 渲染的，SYS_DEF 已删）。

这篇因此改成按页面记"接没接上后端"：前端目前是纯前端原型（零网络请求）， 所以九个页面绝大多数写的是「原型 · 未接线」，只有一处例外。 接线方案与逐页契约差异见 上位机整合设计方案.md §11.27。

原则：不在整合层伪造上游没有的能力。缺的是上游事实，就如实写"缺什么"。

2. 未接通项

2.1 视频复盘的未接通项

改版二十四把位置数据改成"一段视频 → Auto Locate 解析 → 轨迹"这条路，走通了； 下面这些是明确没做的，写清理由，不留"看起来像做了"的空壳：

没做 为什么 要做的话
网页上传视频 拍板②：不做。视频动辄几百 MB，走浏览器上传要把整个文件搬进内存/临时目录，而它本来就在这台机器上 真要做得先想清楚"传上去放哪、谁清理"
多段视频批量解析 当前一次只跑一个任务（一个子进程、吃满 CPU），排队等前一个结束 加一层任务队列；注意同时跑两个只会都变慢
轨迹与固件格子叠加 视频轨迹是视频坐标系里的相对位置；要和固件 posX/posY 画在同一张 8×8 图上，必须先有场地单应（相机外参）。外参随相机整块删了（arena 段只剩网格几何） 需要重新实测一次单应，不是"接一下就有了"
轨迹导出 trajectory.csv 本来就在 records/video/<id>/ 里（上游写的），直接拿文件即可；界面上的【导出】没做 本层只加一个下载端点，但要先定"导哪几列"
对轴（视频时间 ↔ 会话时间） 拍板③：识别侧保证时间轴一致，前端不处理。本层只做自洽校验（I38：帧号单调 / 时间戳不倒流 / VFR 只信帧号） 不打算做。做了就是第二套真相，两边不一致时没人说得清听谁的

视频入口只认服务器路径：video.root 目录里的文件列表 + 允许直接填绝对路径 （config.yaml 的 video.root / video.out_root）。这条约束写在 VideoAdapter 的路径检查里 —— 越界路径直接 404，不是"提示一下"。

上游没有的东西（不要假装有）：

  • mc.move 没有 turn(deg)（转向是按 cm/s + ms 的开环定长）；没有 rear（后退用负速度）。
  • mc 没有 caps()（能力协商未实现）。⚠️ 2026-10-05 起 registry.API_VERSION 可信 （上游每次都改，已到 2.2.1），但 host.__version__ 停在 2.1.0 ⇒ 两者不一致是上游的既有状况； 本层仍以 API_VERSION 为准并一律走能力探测，不靠版本号判能力。
  • ~~mc.maze 没有"停止跑迷宫"~~ ⇒ 2026-10-05 已被上游推翻（2.1.1 新增 MAZE STOP）。 现在的实情分两层，都要知道： · MAZE STOP（【收车】）存在：停车 + 复位发车状态 + 解锁急停 ⇒ 不必断电即可再发车； · 但车在运动时它不可靠：它只置一个"请退出"标志（linkMazeAbort），而标志的检查在 LESSON_Blind8() 的 while(1) 顶部，主循环却有 30 余处非协作式阻塞等待 （等的是编码器里程这类物理进度）⇒ 车在运动时程序正卡在那些循环内部，标志轮不到。 真机实测：回 OK 但 mazeTask 仍 SEARCH。 · ⇒ 可靠收车手段是 MCU RESET（【复位】，2.2.0） —— 整机软复位，BSS 清零把发车状态 一起清掉。代价是复位不复位物理位置（发车前必须人工把车放回起点角），且复位后 约 3 s 才有新遥测帧。由 I28 守（含"收车后能再发车"与"急停中发车回 ERR_ESTOP"）。
  • 课程参数的值读不回来（2.0.0）：固件 GET ALL / GET <name> 只查生产表（24 项）， 课程 14 项一律回 ERR_NAME；写侧（SET/SETQ）仍通。所以界面上课程组标着 「值读不到，可写」，SAVE 时要先把新值填进输入框。这不是本层漏做，是固件侧的读侧缺口。
  • 没有"事后回传课程日志"（2.0.0）：SCOPE/DUMP 整套删除，曲线只在 lesson/run 期间就地捕获。所以那个按钮已删除，路由也明确报错而不是返回空数组。
