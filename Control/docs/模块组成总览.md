# Control · 模块组成总览

> **本文是"静态地图"**：系统由哪些模块构成、谁依赖谁、数据落在哪、起哪个进程。
> 逐接口的语义、协议格式、判据细节不在这里 —— 那些分别在
> [`上位机整合设计方案.md`](上位机整合设计方案.md)（设计主线）与
> [`接口对照表.md`](接口对照表.md)（端点 ↔ 上游方法对照）里。
>
> 校验类工具统一在 [`工具与校验.md`](工具与校验.md)。

## 1. 一句话定位

**本机单进程 Web 上位机**（Python + 浏览器），把"电脑鼠实时链路"和"视频离线复盘"
合成一个界面。**只消费上游，不改上游源码**。

```bash
PY="C:/Users/liuru/.conda/envs/general_env/python.exe"   # 固定用这个环境
$PY tools/preflight.py        # 自检
$PY app.py                    # 起服务 → http://127.0.0.1:8770
```

三个硬约束（判据级别，不要顺手放宽）：

| 约束 | 内容 | 为什么 |
|---|---|---|
| 端点只绑 `127.0.0.1` | `app.py` 默认 `127.0.0.1:8770` | 本机自用；要开 `0.0.0.0` 必须先补鉴权 |
| 不 import `PySide6`/`pyqtgraph` | 判据 **I1** | Web 形态同时免掉与 Auto Locate 的环境冲突 |
| 上游凭据只在服务端 | 前端只见本层端点 | 永远拿不到真凭据 |

## 2. 与外部系统的关系

只有**两路**上游（改版二十四之后）：

| 上游 | 提供什么 | 怎么接 | 落在哪个模块 |
|---|---|---|---|
| `RemoteControl/host` | 鼠直控、参数表、遥测、波形、4 灯状态 | **同进程 import**（`host.api.MouseClient`） | `control/adapters/mouse.py` |
| `Auto Locate` | 一段视频逐帧的 ArUco 位置 + 帧时间轴 | **起子进程**（`python -m aruco_locator.session`） | `control/adapters/video.py` + 薄壳 `tools/video_session.py` |

⚠️ **`PhoneCamera`/`hostlink`/独立服务 8765/在线帧流定位已整块下线**（改版二十四）。
位置数据的唯一来路是"**一段视频 → Auto Locate 会话解析 → 轨迹**"，不是实时帧流。
老不说这点的地方（`release/归档说明.md` 等）都是历史快照。

> Auto Locate 的 `session` **不收 `--config`** ⇒ 必须经 `tools/video_session.py` 转接，
> 否则会静默用上游默认配置（内参失效，会被误判成"视频不行"）。

## 3. 分层拓扑

```
┌────────────────── 浏览器（control/static/，9 个页面 + 4 个核心件）────────────────┐
│  index.html ── shell.js 外壳 ── lib.js 内核/接缝 ── views/*.js 页面 ── draw.js 绘图 │
└────────────────────── REST /api/v1/* ─────── WS: JSON + 二进制 ─────────────────┘
                                  │
┌────────────────── 整合层（单进程，aiohttp）──────────────────────────────────────┐
│  app.py  装配 → ctx.Ctx 装配 → routes.register() 挂端点                          │
│                                                                                  │
│  ── 实时链路 ──                       ── 干扰 facts ──                            │
│  adapters/mouse.py  →  bus.Bus  →  ws.py  →  前端                                │
│        │ 订阅 Event.TELEMETRY                                                    │
│        ├──→ maze_rec.MazeRecorder   实验 8 记录（从发车到停止）                    │
│        └──→ map_live.LiveWallMap    v10 建图增量（比赛页墙图唯一真相）              │
│                                                                                  │
│  ── 离线批处理 ──                                                                │
│  adapters/video.py  → 子进程 Auto Locate  →  video_io.py 读产物                  │
│                                                                                  │
│  公共底座：config / clock / store / arena / leds / bus                            │
└──────────────────────────────────────────────────────────────────────────────────┘
                    │ 同进程 import                    │ 子进程 (Popen)
              RemoteControl/host                  Auto Locate
```

**关键箭头只有四条**，其余都不许反向：

| 数据流 | 方向 | 说明 |
|---|---|---|
| 设备 → 界面 | 单向 | 上游回调 → `bus.publish()` → WS → 前端 |
| 界面 → 设备 | 单向 | REST 动作 → 适配器 → 上游 `send_cmd` |
| 鼠 subscribe → 记录/建图 | 扇出 | `MazeRecorder` 与 `LiveWallMap` 各自订阅，互不依赖 |
| 视频 | 跨进程 | 本层只"起/停/查状态/读产物"，不看进程内部 |

## 4. 后端模块（逐个）

17 个 Python 文件。**每行最后一个符号都在对应文件里真实存在**。

### 4.1 入口与装配

| 文件 | 行数 | 职责 | 关键符号 |
|---|---|---|---|
| `app.py` | ~180 | 服务入口。建 `web.Application`、挂 no-cache 中间件、托管静态资源、启动后台任务 | `build_app`, `ui_no_cache` |
| `control/__init__.py` | 20 | 包定位 + 版本。`__version__="0.1.0"` | `__version__`, `API_VERSION` |
| `control/ctx.py` | 450 | **装配中心**：把 config / clock / bus / store / arena / 两个适配器 / 记录器装成一个 `Ctx`；后台 task 与 `sampler_loop` 也在这 | `Ctx`, `SessionError` |

### 4.2 公共底座

| 文件 | 行数 | 职责 |
|---|---|---|
| `control/config.py` | 324 | 配置载入校验。**未知键直接报错**（静默忽略 = 配置等于没配） |
| `control/bus.py` | 177 | 统一事件总线。多源线程 → 一个 WS 广播 + 一个二进制通道；必须走 `loop.call_soon_threadsafe` |
| `control/clock.py` | 319 | 统一主时钟。三条时间基各归各：**固件毫秒时基**（上游 `timesync`）/ 主机墙钟 / 视频帧时间轴 |
| `control/store.py` | 412 | 会话目录 + `timeline.csv` + `meta.json`（设计方案 §5） |
| `control/arena.py` | 146 | 坐标换算：固件格子 ⇄ 场地归一化 ⇄ 画布像素 |
| `control/leds.py` | 93 | 状态B1 的 4 个 LED 位 → **三态**（真/假/未知）。⚠️ `未知` 绝不画成"灭" |

### 4.3 业务核心

| 文件 | 行数 | 职责 |
|---|---|---|
| `control/adapters/mouse.py` | 4116 | **最大的一块**。包 `host.api.MouseClient`：连接、参数、动作、拉取、链路健康（PING 判死 + 命令让路闸 + 拉取自愈）、动作码表（`/caps.motions`）、决策差分、发车前的 `ensure_pull` |
| `control/maze_rec.py` | 2390 | 实验 8 记录器。**订阅 `Event.TELEMETRY`**（每帧一次），不订阅"有人看波形才发"的那条 |
| `control/map_live.py` | 411 | v10 建图增量通道 → 比赛页墙图（**三态**）+ 建图诊断。**这是界面那张图的唯一真相** |
| `control/adapters/video.py` | 347 | 视频会话执行器：子进程 + 状态轮询。要能取消（`kill`），且崩溃不至于带走本服务 |
| `control/video_io.py` | 384 | 视频产物读取 + 时间轴自洽校验。**只读文件，不 import cv2** ⇒ 可被判据直接喂合成产物验 |

### 4.4 HTTP 层

| 文件 | 行数 | 职责 |
|---|---|---|
| `control/api/routes.py` | 1941 | REST 路由表（§6.2 落地）。只负责"触发"与给元信息 |
| `control/api/ws.py` | 119 | WS 两条通道：JSON + 二进制。**payload > 64 KB 一律走二进制**（判据 **I10**） |
| `control/api/errors.py` | 116 | 上游异常 → HTTP 状态码。错误信息必须能照着做，`error.type` 带上游原始异常类型 |

## 5. 前端模块（`control/static/`）

目录分工与路由 frozen 约定见 [`control/static/README.md`](../control/static/README.md)（前端权威文档）。

### 5.1 四个核心件

| 文件 | 行数 | 职责 |
|---|---|---|
| `index.html` | — | 唯一 HTML。**顺序列出全部 assets 引用**（有新文件必须同步这里） |
| `shell.js` | 473 | 外壳：左轨导航 / 顶栏两灯 / 页面容器 / 日志坞 / 设备抽屉。**启动链 `boot()` 在这** |
| `lib.js` | 2699 | 原型内核 + **接缝层**：`act()`/`setPull()`/`pullBatch()`/`connectMouse()`/`videoStart()`/`renameRecord()`… 真机模式下这里**真的发请求**（`get()` 只读、`post()` 写）；发车状态的判定也在这一层（`pinRunning()` / `applyRunning()`，判据是**动作码**）；断开时的归零是 `resetTelemetry()` |
| `draw.js` | 331 | 扁平示意图：迷宫 / 帧率 / 视频轨迹。纯白底、1px 网格、实心色块、无阴影无渐变 |
| `style.css` | — | 样式（注意：**不一物二用**，改 CSS 前先看有没有别的块在复用同一条规则） |

### 5.2 九个页面（`views/*.js`）

全部经 `C.VIEWS.<route>` 注册，`shell.js` 按 `S.route` 取用；**九个 key 与九个文件一一对应**。

| 路由 hash | 文件 | 行数 | 页面 |
|---|---|---|---|
| `#/overview` | `overview.js` | 288 | 总览：两路状态 +  latest 读数 |
| `#/live` | `live.js` | 351 | 实时：波形 + 4 灯三态 + 拉取档位。大数 = **2 s 实测**，6 s 降为脚注趋势；未连接写 **0** 且曲线画贴底水平线 |
| `#/params` | `params.js` | 194 | 参数表（**依赖拉取在跑**：不先 `syncPull()` 就空表） |
| `#/race` | `race.js` | 681 | 比赛：墙图 + 发车/收车。⚠️ **舞台页**，需 `fitMain()` 现算高度；拉取**半手动**；收车/复位走**观察窗**（点击即 pending，看到动作码归零才停流） |
| `#/maint` | `maint.js` | 233 | 维护：标定分步 / 擦除（不可逆）/ 直控动作 |
| `#/video` | `video.js` | 297 | 视频复盘：选素材 → 起解析 → 看产物 |
| `#/track` | `track.js` | 209 | 轨迹回放（视频产物） |
| `#/data` | `data.js` | 585 | 记录管理：搜索/筛选/多选/批量删/导入；**滚到底自动续载**（已载 / 共 N 条分开说） |
| `#/replay` | `replay.js` | 479 | 迷宫记录回放：**从帧重放建**图，不读 `wall_rows` |

> **&lt;舞台页>**（`race` / `replay`）有专门的高度纪律：地图边长由**可用高度**决定，
> 且必须量自身、不量视口（`fitMain()`）。详见 static/README.md。

**拉取按页开门有两张表，不要合成一张**（改版四十一）：

| 表 | 含哪些页 | 管什么 |
|---|---|---|
| `NEED_PULL` | overview / live / params / race / maint | **进页开一次** |
| `GUARD_PULL` | overview / live / params / maint（**没有 race**） | 停了自己**补开**（带退避、静默） |

比赛页之所以只在第一张表里：那页是**半手动** —— 进页开一次，停车/收车/复位就停，
发车时由后端 `ensure_pull()` 兜。它在两张表里都出现过，于是"复位后不停弹开始拉流、
发不出命令"就成了那个循环。

**停流时机也分两档**（改版四十二）：【收车】必须等回执**回来之后**才停 ——
后端 `maze_stop()` 内部要等一帧新帧才能读任务机，帧先停了它就永远等不到
（`reliable=null`），界面只能瞎猜。【复位】则可以立刻停：它靠 `PING` 的 `rst=SW`
复核，不依赖新帧。

## 6. 运行时模型

**一个重要的事实**：PySide6 那套的事件循环 ≠ 这里的线程模型。这里有三类执行体：

| 执行体 | 谁在跑 | 纪律 |
|---|---|---|
| asyncio 主循环 | aiohttp + `ctx.start_background()` 的两个 task | 端点零网络零同步阻塞；设备往返/串口/扫盘一律 `run_in_executor` |
| 上游调度线程 | `MouseClient` 的回调线程 | 回调里**只能**把事件投进总线，不许调会阻塞等设备的 API（`ReentrancyError`） |
| 视频子进程 | `VideoAdapter` `Popen` 起 Auto Locate | 只杀**本次会话起的那个**；被杀是 `cancelled` ≠ `failed` |

后台两个 task：`mouse.sampler_loop()`（推波形 + 实验 8 自动收尾轮询）、`_bus_tap()`（留最新遥测供场地页算 Δ）。

|---|---|---|---|

## 8. 配置入口

`config.yaml`（324 行解释器 `config.py`）。相对路径一律相对 **config.yaml 所在目录**（= Control 根）解析。

新增配置项时注意**「新段同步」**那条纪律：同一种配置往往要在**四处**同时落地，
漏一处就会出现"改了没生效"。细则见 `上位机整合设计方案.md` §11 的对应小节。
