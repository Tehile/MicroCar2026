# Control · 工具与校验

> 六个脚本，回答三个问题：**能不能跑** / **跑起来对不对** / **文档要不要重导出**。
> 依赖由仓库根目录的 `requirements.txt` 提供，命令中的 `python` 指该解释器。

```bash
PY="python"                                # 已按仓库根目录 requirements.txt 安装依赖的解释器
export NO_PROXY="127.0.0.1,localhost"      # 本机端点必须绕过代理，否则请求会打去外网
```

## 2. `preflight.py` —— 启动前自检

> 按顺序把"会让人白折腾半小时"的事先排掉。每一项输出三段：**检查了什么 / 结论 /
> 不对时怎么改**。

```bash
$PY tools/preflight.py            # 全量
$PY tools/preflight.py --quick    # 跳过网络与 git（离线环境）
```

实际有 **11 个检查小节**，顺序按致命性排（少了前者就什么都跑不了）：

| # | 小节 | 查什么 |
|---|---|---|
| 1 | 配置 | `config.yaml` 能不能载入、键有没有写错 |
| 2 | 依赖 | 按仓库根目录 `requirements.txt` 安装，依赖是否齐全 |
| 3 | 上游仓库路径 | `RemoteControl` / `Auto Locate` 找得到吗 |
| 4 | 上游可 import | **只 import，不改它们** |
| 5 | 判据 **I1** | 不许引入 `PySide6` / `pyqtgraph` |
| 6 | 判据 **I9** | 上游仓库的工作区必须干净 |
| 7 | 串口 | **串口是独占的**，被占就没有第二个能连 |
| 8 | 视频复盘 | 离线链路（视频文件 → Auto Locate 会话解析） |
| 9 | 会话根目录可写 | 落盘的目录有没有写权限 |
| 10 | Control 自己的端口 | 8770 有没有被占 |
| 11 | 大方向冻结 | 宗旨与布局不得改动 |

第 8 节（视频复盘）在 `--quick` 下会跳过。

## 3. `drill.py` —— 端到端演练 + 判据

这是本项目的承重判据集。**每条判据都编号（`I*`），既可以自动跑也能单独被引述**。

```bash
$PY tools/drill.py                # 起临时服务，跑完整链路
$PY tools/drill.py --sim          # 额外起上游鼠标模拟器（有真数据）
$PY tools/drill.py --port 8899    # 8770 被占时换端口
```

改的正是"没数据也照常显示"的静默错，读数字验不出来。

`I60`~`I62` 是改版四十二新加的，同样在 `0e` 段：
- **I60** 命令占链路（`_cmd_inflight` / 上游 `_suspends>0`）时**一次都不复核**，
  且 `_cmd_exit` 把"停帧计时"挪到放手那一刻；
- **I61** 放手时清 `upstream:link_lost`（自己 suspend 出来的假阳性）、
  **保留** `cmd_timeout:*`（真没问出结果）；
- **I62** 拉取自愈（**改版四十七重写**）：`is_on=True` 但 30 s 没收到帧 ⇒ **仍要补**
  （这就是"发完车只能手动开"的正解，旧判据在这里恒绿因为它信了 `is_on`）；
  `_pull_mode="off"` ⇒ 一条开流命令都不许发；`_revive_tries=99` ⇒ **仍补**（无上限）；
  帧回来 `_revive_backoff` / `_probe_fail_rounds` 归零。

> **改版四十七（拉取默认常开）改了 5 条既有判据的语义**，全部在 `0e` 段，
> 都是"纯内存 + 假上游"，理由详见设计方案 §11.47：
>
> | 判据 | 现在的命题 | 关键负向 |

`I63`/`I64` 是改版四十三新加的，同样在 `0e` 段：
- **I63** 动作码表（`/caps` 的 `motions`）必须**盖住上游全部 38 项**、每项都有中文短名、
  `motion_stopped` 恰为 `{0,5}`（1/12/101 明确不在）。⚠️ 上游码表取不到时

- **I64** 收车：帧龄 9 s（没帧源）⇒ `waited=false`、`reliable=None`、**耗时 <1 s**；
  帧龄 50 ms ⇒ 仍走等待分支。两个方向缺一不可（详见 §11.43）。

`I66`/`I67` 是改版四十四新加的（回放的发车/收车按**动作码**标，详见 §11.44）：
- **I66** `motion_phases()`：三段（停/跑/停）的边界时刻、**去抖**（一串单帧"在动"
  夹在停里不许算成一段运行）、中途停过能数出来、三态（无帧 ⇒ `None`；全程停 ⇒
  非 `None` 但 `run_from_s is None`）。⚠️ `phases is None` 与"全程没动"是**两件事**，
  用空列表冒充就是替设备作证。
- **I67** 发车锚点 `first_run_t_ms` 只认 `motionTask`：① 任务机先起、电机后动 ⇒
  它**严格晚于** `first_task_t_ms`（旧判据会相等）；② 任务机在跑但车一直没动（卡死）⇒
  它是 `None` 而不是任务机那个时刻。附带验 `replay_view()` 的 `phases` 与帧自洽、
  以及"没有 motionTask 通道 ⇒ `phases is None` 且带 `note`"。
  ⚠️ 合成记录里运行段必须**长于 `PHASE_MIN_MS`(300 ms)**，否则会被去抖并掉 ——
  那时判据红的原因跟被测的东西无关（写这条时踩过一次）。

`I65` 是改版四十五新加的（记录列表分页，详见 §11.45），在 `0c4` 段（**临时文件**，不依赖模拟器）：
- **I65** 按页大小 3 翻 7 条记录（3/3/1）：各页 id 按序拼起来必须**等于一次全量**
  （顺序也一致）、`count_records()` 等于真实条数、偏移越界返回空列表、
  **缓存命中的那一遍与首次解析逐字段相同**。
  ⚠️ 分页最容易出的错不是"少一条"而是**重复/错位**（翻页期间新落一条记录，偏移整体后移
  ⇒ 下一页首条 == 上页末条），而界面上"同一条记录出现两次"根本看不出是错位。
  ⚠️ 样本必须**末页不满**（整页整除验不出"末页多给"）。
  负向验证（不改源码，用 monkeypatch 灌错实现）：忽略 `offset` ⇒ 拼出 9 条 / 唯一 3 条 ⇒ 判红；
  拿一页条数冒充总数 ⇒ 3 ≠ 7 ⇒ 判红。

`I68` 是改版四十六新加的（回放与实时参数同源，详见 §11.46），在 `0c3b` 段
（**纯内存 + 临时文件**，不依赖模拟器）：
- **I68** 造一条 32 通道的记录再调 `replay_view()`，钉四件事：
  ① `fields` **恰好** = 记录 `channels` 原序 + `(frontNear, irSwitch)`，**顺序也一致**
  （白名单只要再冒出来，长度或顺序就一定对不上）；
  ② 样本 `v` 与原始 row **逐列相同**（列错位的症状是"电池显示在陀螺角的位置"，看不出来）；
  ③ 派生量恒等式 `frontNear = wallFront & !frontFar`、`irSwitch = flags & 0x10`，
  且**缺一侧 ⇒ `None`**（摘掉 `frontFar` 那条要 `None`，不许按 `wallFront` 猜）；
  ④ 4 灯三态两方向：`fw=314` + `led=1/0/1/0` ⇒ `[True,False,True,False]`；
  **不存 `device` ⇒ 全 `None` 且必须有 `leds_note`**（老记录不许画成"灭"）。

### 3.2 `--sim` 的边界

- **不加 `--sim`**：跑不了需要活链路的那些（`I15`~`I17`、`I22`、`I23`、`I27`、`I28`、
  `I30`~`I33` 等）⇒ **这些会跳过**，不是通过。
- **加 `--sim`**：模拟器会破坏确定性相关的验证 ⇒ 相关项标 **SKIP**，**不硬过**。
- 8770 已有旧实例时会自动改用别的端口。

一句话：**看汇总要同时看 `PASS` 数和 `SKIP` 清单**，只看 PASS 数会被蒙。

## 4. `browser_check.py` —— 无头浏览器实测

> **九个页面真渲染 + 接缝真的接上了。** 用 CDP（`aiohttp` 就够了），不引入 Playwright
> —— 本机本来就有 Chrome，少一个 ~150 MB 依赖，多一条能随时重跑的命令。

```bash
$PY tools/browser_check.py                    # 默认连 http://127.0.0.1:8770
$PY tools/browser_check.py --sim              # 自己起服务 + 模拟器
$PY tools/browser_check.py --only V7          # 只跑某一组
```

### 4.1 核心是 `V6` —— 验"接缝真的接上了"

**要验的不是"界面把数据显示对了"，而是"点了按钮，请求到底有没有发出去"**。
做法：在页面里注入 `fetch` 记录器，点【应用】把每批帧数设成 3，然后去请求记录里
**找** `POST /api/v1/mouse/stream/batch`。找不到就是没接上 ——
而界面上一句"已下发"是**本地 toast，跟网络毫无关系**。

### 4.2 负向判据 `V5` —— 不许假绿

> **设备没连上时，界面不许说连上了。** 假"已连接"会让人以为可以去发车。

⚠️ `--sim` 与不带 `--sim` 两种情况**断言方向相反** —— 双向都点才叫判据。

⚠️ V21 的搜索词**取全库最后一条的 id**（`?n=1&offset=total-1`），不写死名字 ——
记录目录是活的，写死的词迟早不存在，那时"搜不到"会被当成功能坏了。
否定方向两条都验过（临时把 `onScroll` / `ensureAll` 变成空实现 ⇒ 判据转红，
分别报"滚 41 次仍 50 条"和"载入 50 条 / 命中 0 行"），验完立刻还原。
⚠️ V21 用 `reset()`（清空已载窗口再 `loadRecords()`）造"刚进页"的状态，
**必须先复位再造状态**：上一条判据留下的 344 条会让"首屏 50"恒假。
⚠️ V23 的三条腿**缺一不可**：只比键集合会放过"挂着 30 个标签、值全是 `—`"（那正是
白名单时代的症状）；只比个数会放过"两边都空"（`0 == 0` 也算相等，所以另有 ≥28 项这条）；
负向那条（摘 `fieldPos` ⇒ 全 `—`）是为了证明那些数字**真是从这条记录的样本里取的**，
而不是从别处抄来的。摘完必须还原，否则同一轮后面的判据看到的是空表。
⚠️ V23 的实时侧键集合取自 `#lv-ch [data-k]`（**渲染出来的 DOM**，不是 JS 里的常量）：
拿 `CH.groups` 直接比等于自己跟自己比 —— 两边都用同一张表，永远相等。

> 标"—"的是本项目当前未被 AI 逐条读透的组；**宁可留白也不猜**（下游自证原则）。
> 要看某组的确切命题，直接读 `tools/browser_check.py` 里对应的 `record("Vn", …)` 及其上方注释。

⚠️ **常见误会**：`--port` 是"连已有服务"，**不会自己起**。要验新后端必须自己先起一个
实例（用完关掉），否则连到的还是旧代码。

## 6. `neg_i30.py` —— 判据的变异验证

> 纪律：**一道从没红过的闸不算闸。**

守的是"两条来路同一个纪元"。做法是把修复撤掉再跑一遍：

- **A（现状）**：`_reset_epoch()` 清环 + 换差分器 + 零点交给发车后第一帧；
- **B（旧行为）**：只挪零点，不清环也不换差分器（就是当年修掉的那个 bug）。

要看的就一件事：B 里会不会出现**负 `t_ms`**（上一段/发车前的决策残留在新纪元里），
而 A 里不会。实测 **A 0 条 / B 11 条** —— 两者一样就说明这道闸根本没咬住。

⚠️ 它**特意保留在仓库里**（不像临时脚本那样用完删）：差分/纪元逻辑再动时，
重跑一次就知道闸还有没有牙。

## 7. `build_doc_html.py` —— 文档导出

```bash
$PY tools/build_doc_html.py              # 渲染 docs/ 下全部 .md
$PY tools/build_doc_html.py docs/x.md    # 只渲染指定文件
```

产物是自包含的暗色 HTML（无外部依赖、无 CDN、可离线打开）。

给人的是 html，它就代表"最新状态"。
