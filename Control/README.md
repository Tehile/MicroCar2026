# Control —— 电脑鼠整合上位机

> **方向已冻结**：总体设计宗旨与布局方案见
> [`docs/上位机整合设计方案.md`](docs/上位机整合设计方案.md) 开篇「总纲（冻结）」一节。
> 该节是全文上位约束，后续任务不得改变；界面只放**状态 / 数值 / 控件 / 下一步点哪**。

把两个既有模块合成**一个界面**。**改版二十四：手机相机那一路整块下线** ——
位置数据不再来自"手机实时帧流"，而是"**一段视频 → Auto Locate 会话解析 → 轨迹**"：

| 模块 | 提供 | 怎么接进来 |
|---|---|---|
| `../RemoteControl/host` | 电脑鼠直控、参数、遥测、波形、4 灯状态 | **同进程 import**（`host.api.MouseClient`） |
| `../Auto Locate` | 一段视频里逐帧的 ArUco 位置 + 帧时间轴 | **起子进程**（`python -m aruco_locator.session`，本层薄壳转交配置） |

服务是**本机 Web**（默认 `http://127.0.0.1:8770`），不依赖 PySide6 / pyqtgraph。

## 1. 三条命令

先按仓库根目录的 `requirements.txt` 安装依赖（见 [`../docs/安装与运行.md`](../docs/安装与运行.md)）：

```bash
python tools/preflight.py         # ① 环境自检：依赖 / 上游可 import / 串口 / 端口
python app.py                     # ② 起服务 → 打开 http://127.0.0.1:8770
python tools/drill.py --sim       # ③ 无硬件端到端演练：逐条判据验收（I1~I68，实际存在的编号见 docs/工具与校验.md §3.1）
```

`preflight.py --quick` 会跳过网络与 git 检查（快一点）。
`drill.py --keep` 保留 `.tmp/drill`（服务日志 + 判据改配置时用的那份副本），方便自己进去翻。

## 2. 手上什么都没有也能验全部功能

**无鼠、无视频、无场地**也能把九个页面和整条链路跑通。

| 缺什么 | 怎么办 |
|---|---|
| 没有电脑鼠 | 起模拟器：`cd ../RemoteControl/host && $PY -m host.sim.mouse_sim`，然后点顶栏【电脑鼠】连 `tcp://127.0.0.1:5555` |
| 没有视频 | `#/video` 页会如实写「素材目录里没有视频」，并把该目录的**绝对路径**给出来；丢一个 mp4 进 `video/` 再刷新即可（不用重启服务） |
| 没有场地 | `#/track` 画的是**视频里的相对位置**，不需要场地标定；`arena` 段只剩网格几何（8×8 / 格距 / 场地尺寸），相机外参随相机一起删了 |

一条命令把三者一起验：

```bash
$PY tools/drill.py --sim            # 起模拟器，把需要活链路的判据全跑一遍
```

界面本身也有无头判据（**第三版**，改版二十八）：`tools/browser_check.py --sim`
会起浏览器把九个页面真的渲染一遍，并验"点了按钮请求有没有真发出去"。见 §6。

## 4. 一次完整跑车

> 下面的步骤走的是**新界面的九页**（`#/overview` `#/live` `#/race` …）。
> ⚠️ 前端目前是**纯原型**：除「每批帧数 N」外，页面上的按钮**还不会真的发请求**。
> 所以这一节描述的是**目标流程 + 后端已经具备的能力**，"哪些还差接线"见
> 设计方案 §11.27 的 §三/§四。

**先手动连好，再测试。** 准备清单三项（电脑鼠 / 时间基 / 视频复盘）各自显示状态，
但**只有「电脑鼠」拦记录**（改版二十四：视频是离线批处理，跟"现在能不能记录"无关；
时间基未标定只影响跨机对齐）。电脑鼠没连上时【开始记录】点不动，服务端也会 409 拦住并给出清单。

```
① 点顶栏【电脑鼠】片 → 抽屉里选目标 → 【连接】
   连上后回读设备信息（口名 / 协议 / 固件 / 状态）
   ⇒ 若提示"被占用"：先关掉上游的 run_host.py（它独占串口）
② （可选）点顶栏【时间基】填时间偏移 —— 不填也能记，只是跨机对齐按 assumed 走
③ 进 #/live 实时状态：
     · 【每批帧数 N】填 3 再点【应用】⇒ 走批式（≈10 Hz）；填 1 = 退回停等
       （N 是**唯一接真后端**的参数，见 §6）
     · 看 4 灯状态行与统一帧通道卡，确认这条流是活的
④ 进 #/race 比赛，看右栏四项检查：
     · 能不能发（链路活、急停没锁存）
     · 电池够不够（低于上游 LAUNCH_MIN_MV 会被拒）
     · 任务机在 WAIT、记录已开
⑤ 顶栏【开始记录】→ 开鼠那一路；失败**全部回滚**，不留半个会话目录
⑥ 点【比赛发车】（`MAZE RUN RACE`）→ 跑车
⑦ 顶栏【急停】随时可停（**锁存**：触发后运动命令返回 ERR_ESTOP，必须【解锁急停】才能恢复）
⑧ 比赛卡【收车】= `MAZE STOP`（正常退出）；【复位】= 整机软复位（连不上时唯一出口）
⑨ 顶栏【停止记录】→ 收会话（时间轴落盘）
⑩ 进 #/data 比赛记录 → 会话表、导出；有视频的行可以【关联】到某个视频会话
```

**轨迹不在这一步产生**：它是"拍一段视频 → `#/video` 解析 → `#/track` 看"
这条**离线**路径的产物。谁拍的、用什么拍都行，只要视频里能看清场地标记。

**台面实验（电机/算参）走 `#/maint` 之外的实验入口**，与"场地上跑"是两套流程，
实验前**轮子必须悬空**。（新前端目前只保留了维护自检页，电机实验台还没有对应页面 ——
它在 `docs/未实现功能.md` 里记着。）

## 5. 会话目录里有什么

```
sessions/2026-09-27_0306_2rnl/
├── meta.json               # 可复现的全部信息：时钟偏移/不确定度/来源、**设备时基（mc.timesync 的结论）**、
│                           #   场地网格几何、视频能力、上游版本与 git HEAD、`counts.timeline_rows`
├── timeline.csv            # ★ 核心产物：每行必有 t_pc_ms
│                           #   列 = t_pc_ms, t_pc_iso, source, kind, ref, note, t_src, dev_ms
└── mouse/
    ├── raw.bin / raw.ts    # 原始字节流与时间戳
    ├── stream_unified.csv  # 统一帧（一条流，不再分 250/50/5 Hz）
    ├── text.log            # 设备 printf
    └── meta.json
```

> **改版二十四**：`camera.json`、`locate/`、`thumbs/`、`frames/` 都不再产生（相机与在线定位下线）。
> 老会话目录里若还有这些，**只读容忍、不删** —— 那是历史证据。

**`timeline.csv` 的后两列**说明**这一行的时间是哪一种**：

| `t_src` | 含义 |
|---|---|
| `send` | 帧真正**发出**的时刻（固件毫秒时基经 `mc.timesync` 换算）—— **准确的那种** |
| `arrival` | 只拿到"主机收到"的时刻（蓝牙/WiFi 抖动被算进去了） |
| `local` | 本层自己产生的事件（开会话、点按钮） |

> 改版二十四删掉了 `capture`（"相机帧真正拍摄的时刻"）：相机那一路下线后，
> 时间轴里不再有"另一个设备拍的某一帧"，视频那一路的时间轴归 **Auto Locate** 自己
> （它的 `trajectory.csv` 里逐帧带 `t_video_s` / `t_rel_s`，本层只读不自造）。

`dev_ms` 是"发车以来毫秒"，用来和上游的 `stream_*.csv`、`results.jsonl` 直接对齐。

**三套时间基各归各的负责方，不许合成一个数**：

| 时间基 | 谁负责 |
|---|---|
| 固件毫秒时基 → 本机单调秒 | **上游 `mc.timesync`**（min-delay 偏移 + 最小二乘 ppm） |
| 本机单调秒 → PC 墙钟 epoch | 本层（单调推进 + 周期性重锚，**保证不回退**） |
| 视频帧号 → 秒 | **上游 Auto Locate**（`fps` × 帧号；VFR 时只信帧号，本层只做自洽校验） |

PC 墙钟由**单调时钟推进**，不直接取 `time.time()`（会被 NTP 回拨，产生负的时间间隔）。

## 5b. 迷宫复盘记录放哪

### 每批帧数 n（全应用一个档位）

`n` **不是**"批内帧数的修饰符"，它就是**拉取档**：上游 `TelemetryPuller` 的 `kind` 由它决定。

| n | 是什么 | 帧率 |
|---|---|---|
| **1** | 停等（`TELEM`，一帧一答），`t_ms` 被忽略 | 1/RTT，真机 **4.4~6.5 Hz** |
| **2~16** | 批式（`RATE PULL n 100ms`） | n=3 ⇒ 目标 10 Hz |

所以「n 设回 1」= 回到停等，**不是**"批式但每批 1 帧"。

- 写入口只有一条：`POST /api/v1/mouse/stream/batch`，`{"n":1..16}`。
  **越界返回 400，不夹值** —— 夹到边界就是"界面说成功、设备按别的跑"。
- 读入口只有一条：`GET /api/v1/caps` → `mouse.pull = {n,t_ms,T_ms,fps,kind}`。
  ⚠️ 在 **caps** 里，不在 `/health` 里（踩过一次：判据钉在 `/health` 上恒拿 `None`）。
- **n=1 时 `fps` 给 `null`**：上游会按 `n/t_ms` 算出 `10.0`，而停等真机只有 4.4~6.5 Hz，
  拿它显示"目标 10 Hz"就是假数。
- **重连会恢复 N**：`mc.stream.on()` 每次都 `configure(1,…)`，所以适配器自己记 `_pull_n`
  并在 `connect()` 重放。不重放的表现是"设了 N、掉一次线又变慢"，而且**没有任何报错**。
- `t_ms` **不开放**：后端写死 100 ms。两个都能调等于让人直接撞 13.3 Hz 那个"只活 176 s"的顶格。

**I40** 守这个参数（`--sim` 才跑）：设 3 ⇒ `caps.pull.n==3` 且门面 `mode=="pace"`；
越界 99 ⇒ **必须 400**；恢复 1 ⇒ `pull.fps is None`、`kind=="stopwait"`。

### 拉取的开关：默认常开 + 手动最高（改版四十七）

拉取是**唯一持续占链路**的动作。改版三十一给了它"按页开门"（`auto_stream: false` +
`NEED_PULL`/`GUARD_PULL` 两张表 + 2 s 前端看门狗），四十七**把这套整套拆了**，
因为它制造了现场三个病：**发完车要手动开**、**复位后不停弹框又发不出命令**、
**切到记录页看一眼这一跑的遥测就断了**。

现在的口径只有四条（详细论证见设计方案 §11.47）：

| # | 口径 | 落点 |
|---|---|---|
| 1 | **默认常开** | `mouse.auto_stream: true`；连上即持续拉，含发车前后、复位/停车后 |
| 2 | **单一权威** | 后端 `_pull_mode ∈ {"auto","off"}`。页面、看门狗、自愈都不许各持一份 |
| 3 | **手动最高（粘住）** | 人按【结束】⇒ `"off"`，**任何自动路径都不许改回来**；跨重连保持，进程重启回 `"auto"` |
| 4 | **以帧为真相** | 判活只看"最近有没有收到新帧"（`_frame_grow_at`），**不看上游 `is_on`** |

第 4 条是这次的核心。发车链路是 `ensure_pull() → suspend(RATE OFF) → MAZE RUN → resume(RATE PULL ×3)`，
`resume()` 里第一条 `RATE PULL` 常被固件 1 ms 命令窗吃掉，但函数照样正常返回 ⇒
**`is_on=True` 而设备根本没在发帧**。旧代码拿 `is_on` 判"要不要补流"，
于是自愈永不触发 —— 发完车就只能手动开。

**断线判定放宽成"可撤销的疑点"**（四十七）：门槛 `LINK_SUSPECT_S` 4→**8 s**
（必须长于最长命令让路窗 ≈5.5 s）、要连续 `LINK_PROBE_ROUNDS=3` 轮 PING 无应答，
而且**只标黄/红，不断串口、不停流、不结束记录**；**一收到帧就自动撤销**。
前端只按 `/health` 的 `link.state` 上色（`ok/paused/no_pull/waiting/suspect/dead`），
红只给 `dead` —— 手动停、等第一帧、自动补流都不是故障。

**自愈无上限**：`REVIVE_GAP_S=2.5` 起指数退避到 `REVIVE_GAP_MAX=15.0`，**永不放弃**
（旧 `REVIVE_MAX=2` 补两次静默停手 = 又交给手动）。

⚠️ **删掉的东西别再找回来**：`NEED_PULL` / `GUARD_PULL` / `startPullGuard()` /
`guardBackoff()` / `LIVE.pullOffAt`（人工停 8 s 豁免）/ `REVIVE_MAX`。
<br>**比赛页不再"半手动"**：它现在和其他页一样，拉取默认开着。

**比赛页的拉取面板**（改版四十一建，四十七改口径）：
- 面板一行：`实时帧率 · 每批帧数 N · 【开始/停止拉取】`（与实时状态页同一个 `C.pullPanel()`）。
  它现在只干两件事：**看**（发车前帧龄/帧率）与**停**（人按【结束】，粘住）。
- 发车：先 `ensure_pull()` 确认帧龄 ≤0.35 s 再发 `MAZE RUN`（等不到 ⇒ **409 车不动**，与改版三十七一致）。
- **【收车】/【复位】走观察窗**（改版四十三）：点下去**当拍**给反馈（按钮禁用作「收车中…」/「复位中…」+ 提示），
  每拍看**动作码**——看到"没在动"（`/caps` 的 `motion_stopped`，即 0/5）才收尾；
  8 s（复位 10 s）没等到就收尾并如实说"未确认"。
  ⚠️ **四十七：收尾不再停流**（旧版"才收尾并停流"已废）。为什么不先停流仍然是硬约束：
  后端 `maze_stop()` 要等一帧新帧才能读任务机，帧先停了就永远等不到 ⇒ `reliable=null`
  ⇒ 界面只能瞎猜，然后被**停车前那一帧**翻回"已发车"。现在干脆不停，这个坑自然不存在。
- **判断"车在不在跑"看动作码，不看迷宫任务**（改版四十三）：`mazeTask` 是流程态（车停稳后可能仍在高位），
  拿它当门控就会出现"任务机已经 WAIT、发车键还是灰的"。

**看门狗已删除**（改版四十七）。原来那个 2 s 巡检 + 指数退避（2→4→8→16→30 s）补开，
与后端自愈抢**同一个 1 ms 命令窗**，而且 `n≥2` 开流失败要重试 `CMD_TRIES=3 × 2.0 s`
（一次最坏堵命令通道 6.5 s）⇒ 现场那个"失败→2 s 后重开→弹框→再失败"的循环。
现在补流**只在后端**（`_revive_reason()`，按帧、无上限退避、静默）。
晚到的 `setPull` 响应仍按请求令牌 `pullSeq` 丢弃，不许改 `S.pulling`。

⚠️ **参数页为什么也要拉**（实测）：停流时上游 `GET ALL` 会 **3 s 超时**
（只回 38/41 项），参数表变成"0 组"，看着像固件没参数。所以
`GET /mouse/params/grouped` 在停流时直接 **409 并说明原因**，**不返回空表**
（空表是"读到 0 项"这个假事实）。

三个开关端点：

| 端点 | 干什么 | 关键点 |
|---|---|---|
| `POST /mouse/stream/batch {"n":1..16}` | 改档 | **停流时也有效**，但回 `effective:false`（档记下了、设备还没变） |
| `POST /mouse/stream {"on":true}` | 开流 | **带档开**：n≥2 直接 `pace(n,100ms)`，回 `applied_n`。`on()` 每次把 n 归 1，所以不能"先 tune 再 on" |
| `POST /mouse/stream {"on":false}` | 停流 | 人工停**照停**（排障手段）并把 `pull_mode` 写成 `"off"`（**粘住**）；带 `{"auto":true}` 一律**忽略**，回 `{kept:true, reason:"always_on"}` |

界面的正确姿势：**结束拉取 → 改 N → 开始拉取**（拉取中 N 是禁用的）。

**I43**（`--sim`，五段正反都有）守"默认常开"：人工停 / 关流改 N 有效但没生效 /
带档开流 `applied_n=3` 且 `kind=pace` / **自动停一律忽略（`reason="always_on"`，`is_on` 不许变）** /
**人工停粘住**。
**I62** 守自愈：`is_on=True` 但 30 s 没帧 ⇒ **仍要补**；`pull_mode="off"` ⇒ 不补；
`_revive_tries=99` ⇒ **仍补**（无上限）。
**I57/I58** 守判死：只标不执行（`disconnects==0`、不停流、`mode` 不变）、8 s 门槛 +
连续 3 轮无应答、**出帧即撤销**。
**V11**（浏览器）守"切页不动流 + 手动停最高"：切 data/params **仍要拉**；人工停后
`pull_mode=="off"` 且切回 live **不许自己开**。
**V17** 守"手动停粘住"：停住后切走再回比赛页等 3 s 仍停。
**V24** 守"判死 ≠ 断开"：同一份 `connected:true` 喂三份 health ⇒ 判死/正常/人停三种说法，
红只给判死那一种。

## 7. 常见故障

| 现象 | 原因 / 怎么办 |
|---|---|
| **改完设置，config.yaml 打不开了** | 不应该发生：写回前会先自己解析一遍，过不了就整项不写并告警（`not_written`）。如果真遇到，说明是**手工编辑**改坏的 —— 看报错的行号，YAML 的缩进必须用空格且同级一致 |
| 不同数字的刷新节奏**不一样** | 不应该发生了：2.0.0 起只有**一条统一帧**，所有字段的更新节奏一样。若真看到某一路明显滞后，那是**那一帧的值如此**（不是"另一条流慢"）—— 先看这一页顶上的实测帧率与"最新一帧"年龄 |
| 「实时状态与参数设定」的红外/电压恒为 `—` | 那些量全在**同一条统一帧**里 ⇒ 恒为 `—` 只有一个意思：**帧没在来**（没连上，或遥测拉取没开）。2.0.0 起没有"另走一条路再问一次"这回事了（`SNAP` 已删）|
| 电池显示 `0 mV` | 比赛固件**从不打开电池监视**，那是"**没采**"不是"**没电**" —— 别去查电池。`battMv` 只在打开了监视的固件上才有意义 |
| 帧率只有个位数 Hz（不是 217） | **这是正常的**。2.1.0 起遥测由上位机逐条拉取，`n=1`（停等）可达帧率 = 1/往返 ≈ **4.4~6.5 Hz**（瓶颈是蓝牙透传的转发延迟，与串口速率无关）；把 **N 调到 3** 走批式才到 ≈10 Hz。界面上那个「（协议常量 217）」只是对照，不是"应该有"的值。⚠️ 界面大数是 **2 s 实测**（改版四十一），6 s 值只在脚注 —— 两个数不一致不是错 |
| 突然连 `PING` 都不应答了 | 蓝牙透传模块的缓冲被灌满了（上一轮持续推流所致），它**不会自愈**。**先把遥测拉取关掉**（顶栏【电脑鼠】窗口里的开关），等十几秒让缓冲排空 —— 不用断电，也不用拔线。这条正是 2.1.0 拉取模式的用处 |
| 界面自己断开了 / 状态行写「链路判死」 | 改版四十一起这是**有意的**：命令超时（`TIMEOUT`/`NO_REPLY`）或帧停 ≥2.5 s 时，本层会发 **PING ×2** 复核，不通就**停流 + 收尾记录 + 自动断开串口**，并在总览留一条 `link.dead`。断链**不自愈**，必须断电 3~5 s 再重连（重连后 N 会自己恢复）。想先确认不是误报，看「最新一帧年龄」—— 它一直在涨才是真断 |
| 任务机已经 WAIT 了，「比赛发车」还是灰的 | 改版四十三起**不该再出现**。发车键的门控只认**动作码**（`motionTask`：0=空闲 / 5=停车 都算停），不再看 `mazeTask`（那是迷宫流程态，车停稳后可能仍停在高位）。如果还灰着，看按钮 `title` 与旁边的 hint —— **灰着必须说得出为什么**（未连接 / 收车或复位进行中 / 急停锁存 / 车真的还在跑） |
| 「动作」显示的是数字（例如 14） | 旧版前端只有 5 项码表，5 及以后全落成裸数字。改版四十三起码表由**后端 `/caps` 的 `motions`** 现取上游 `MOTION_TASK_NAMES`（38 项）+ 中文短名，界面上写「左快转（14）」。**新固件加了码而这里没跟上**时会显示 `未知(123)` —— 那是提醒你码表要补，不是故障 |
| 拔线 / 停流之后帧率还是老数字 | 改版四十三起断开即归零：`applyHealth` 看到 `connected` 由真变假就 `resetTelemetry()` —— 帧率写 **0**、曲线清空、位置与墙回 `—`、4 灯回「未知」、比赛页那张迷宫图**清空并标注未连接**。以前它冻在最后一帧上（实测 10.41 Hz 一动不动，而帧龄一路涨到 8 s），看起来像界面卡住 |
| 点【收车】/【复位】之后按钮写着「收车中…」，要等几秒 | 这是改版四十三的**观察窗**（收车 ≤8 s、复位 ≤10 s）：命令回来之后**不停流**，要**看到动作码归零**才认账并停流。以前回执一到就喊"已收车"，那是抢答 —— 紧接着停车前那一帧又把它翻回"已发车"。窗口内两个键都禁用是防止一条链路上排两条命令 |
| 点【收车】弹了成功，按钮却**闪成「比赛发车」又变回「已发车」** | 改版四十二已修。原来三条错叠在一起：① 停流抢在收车回执前面 ⇒ 后端等不到新帧、只能"判不了"；② 前端拿"判不了"当成功；③ 手上那帧**停车前采的**（`mazeTask=2`）把它翻回去，而流已停、再没有帧来纠正。现在：**等回执再停流**、按后端 `reliable`/`state.task` 三态说话、回执后 2.5 s 内不让旧帧改这个状态。若仍看到「已发车」，先看这一行文案：可能是**真的没收住**（弹的是「还没收住」而不是「已收车」） |
| 发车后**一小段时间**没有数据（也就几秒） | 这是**命令让路**：`MAZE RUN` 是 urgent 命令，上游会先 `suspend()` 拉取、命令回来再 `resume()` 重发 `RATE PULL`（3 次重试，首条常丢）⇒ 整段 0.9~5.1 s 一帧都没有。**消不掉**（上游为"命令不被拉取挤掉"付的代价），记录里那一段有 `sent`/`ack` 两端锚点。改版四十二保证两件事：这段时间**不去 PING 打扰它**（PING 会抢掉 `RATE PULL` 的命令窗口）、万一 `resume()` 没把拉取叫回来会**自动补开一次**（最多 2 次）。若超过 5 s 还没帧，看日志里有没有「补开拉取」；两次都失败会直接写下一步该点什么 |
| 【视频会话】说「素材目录里没有视频」 | `config.yaml` 的 `video.root` 指向的目录里没有 mp4。那一行会把**绝对路径**写出来 —— 把视频丢进去再点【刷新列表】，不用重启服务 |
| 视频解析报「找不到这个视频」 | 填的是**服务器路径**，而且必须在 `video.root` 下（或给绝对路径）。本层不做网页上传（拍板②：视频是大文件，走文件系统比走浏览器稳） |
| 视频解析报「已经有一个任务在跑」 | 同一时刻只允许一个解析任务（它就一个子进程、也吃满 CPU）。等它跑完，或点【取消】—— 取消只杀**本层起的那一个** |
| 连串口报"被占用" | 串口是**独占**的。先关掉上游的 `run_host.py`（带 GUI 的那个）再连 |
| 【⑤ 发车】显示"未发车" | 还没点【发车 ARM】。没发车就没有 TIME 帧，帧的**发送时刻**就算不出来，时间轴只能退回记"到达时刻"（`t_src=arrival`） |
| 远程发车报 ERR_VALUE | `MAZE RUN` 只在**数据收集档**固件里实现，其余档位会拒绝 |
| 课程参数的值一列全是 `—` | **上游 2.4.0 已把课程调参整层删除**（`APP/lesson_lab.c` / `host/api/lesson.py` / 命令 `lesson.*` / `Event.LESSON` / 课程 14 项参数 id 8–21）⇒ 老版的"读侧缺口"现在**整块不存在了**。参数表 **2.5.0 起 41 项四组**（生产标定 / 红外测量 / 电源监控 / 运动控制）。跑在 2.4.0 上的界面会自动收起课程半屏并写明原因；如果还想跑老课程实验，得换回 2.3.x 的上游 |
| 想「停车后回传课程日志」找不到按钮了 | 2.0.0 删了 `SCOPE`/`DUMP` ⇒ 没有这条通道了。曲线在【执行实验】期间**就地捕获**并随结果返回；想再看一遍就重跑一次实验 |
| 迷宫记录里的任务迁移序列是空的 | 那个序列是**主机差分相邻帧**推出来的（不是设备事件流）：要么迷宫没跑起来，要么**帧一直没来**（先看实时状态与参数设定页的实测帧率）。注意 `SEQ` 跳变时中间缺帧 —— 那一段的边沿"当时没收到"，不等于"没发生过" |

| 记录点了【停止并保存】却没生成文件 | 空记录**不会**写成文件（一帧都没收到）。看「记录」那一行的帧数：如果是 0，先解决"帧没在来"（同上一条），别去找文件 |
| 记录没自动收尾、一直在记 | **这是预期的**：固件没有"迷宫结束"事件，自动收尾是**弱判据**。跑完点【停止并保存】即可（模拟器上尤其必须手点）|
| 比赛页点【发车】后没有状态 | 状态量在**统一帧**里，所以要**遥测拉取开着**才看得到（顶栏【电脑鼠】窗口里的遥测开关）。另外 `MAZE RUN` 只认数据收集档固件 |

| **发车被拦下、说电池太低** | 那是**上位机的保护闸**（上游 2.2.1），不是设备拒绝 —— **命令压根没发出去**。低电时红外发射管变暗 ⇒ 墙检测失效、电机行为不确定，真机事故就是"电机一直转且对红外不敏感"。⇒ 充电或换电后重试。确需台架调试，把电脑鼠**架离地面**后用逃生舱 `send_raw("MAZE RUN")` 强发。⚠️ 显示 `0 mV` 是"**电池监视未开启**"，不是没电，那种情况**不拦** |

| 车不动了、命令还回 OK、连【收车】也没用 | **卡死**：固件主循环有 30 余处**非协作式阻塞等待**（等的是编码器里程这类物理进度），而 `STOP` 会把 `freemode` 置 1 ⇒ 电机 PWM 恒 0 ⇒ 那些条件**永远不可能满足** ⇒ "越停越死"（看门狗也救不了：喂狗在 SysTick 中断里，主循环卡死对它不可见）。⇒ 点【复位】（上游 2.2.0 的 `MCU RESET`，整机软复位）。真机实测：卡住 → 复位 → 回 `WAIT` 约 1.1 s，**无需断电** |
| 【复位】点了但说"没复核到复位" | 看那一行的 `rst`：**仍是 `POR`** ⇒ 没复位成功（旧固件收到 `MCU RESET` 会回 `ERR_CMD`、`rst` 保持 `POR`）；**是 `—`** ⇒ 设备不答话，查串口。⚠️ 成功判据是 `rst == "SW"`，**不是"ACK 收到了"**（复位会与 ACK 抢链路，`accepted=False` 不代表失败） |
| 「比赛」页说"这台设备读不到比赛冲刺状态" | 冲刺状态（前墙双档 `frontNear`/`frontFar`、冲刺档位 `spurtMode` 等 10 个通道）是**上游 2.3.0 起才进帧**的。跑在更老的固件/上游上时这些字段不在帧里 ⇒ 界面**如实标注**，不会画成"未选 / 0"（那会让人以为车真没选档）。要测这条就用 2.3.0+ 的上游或模拟器 |
| 「比赛」页说"前墙双档对不上" | 那是**当场自校验**报出来的：`frontNear \| frontFar` 必须等于 `wallFront` 且两档互斥（同时命中也是错的）。对不上说明**帧解析或固件版本不匹配** —— 先确认上游与固件版本对得上（2.3.0 起才有这三项），别去改界面 |
| 「比赛」页发车回 400 / RACE 不支持 | `MAZE RUN RACE` 需要**支持比赛档的固件**（2.3.0 起的比赛档）。回 `ERR_VALUE` 就是"这个档位没这条命令" ⇒ 换固件；想跑 `BLIND` 走脚本/逃生舱（`MAZE RUN BLIND` 命令还在，只是界面只剩 RACE 入口） |
| **复位成功后立刻发车又撞墙/乱走** | 这是**已知且必然**的：复位**只复位固件、不复位物理位置** —— `mousePos`/`mapWall`/`stackIdx` 全被清零，而车还在迷宫原处 ⇒ 它会按"**我在起点 (0,0)**"的**错地图**行驶，既不认路也不认墙。⇒ **发车前必须人工把电脑鼠放回起点角**。另：复位后**约 3 s 才有新遥测帧**，别急着判读状态（此前读到的是旧帧或 `main()` 尚未初始化完的早帧） |
| 按了急停但车没立刻停 | 若你用的是**旧上游**（2.1.2 之前）：根因是固件每 1 ms 只消费一行命令，而拉取器在持续发 `TELEM` ⇒ `STOP` 与某条 `TELEM` 落进同一窗口就被丢掉，要等 2.5 s 超时重发。真机实测"转速归 0 用时 **3220 ms**"—— 那正好是 `MOVE RUN` 的时间护栏，也就是"**根本没生效**"。2.1.2 起上游给时间敏感命令加了"**让路**"（发送前暂停拉取），实测 0/5 重发、594 ms 停下 ⇒ **升级上游即可** |
| 电机不动但命令回 OK | 设备跑的是安全测试固件（`MOUSE_TEST_NO_MOTOR`），电机输出恒为 0。本层会**提前一行说清**，不会让你等到 90 s 超时 |
| 急停后一切运动命令被拒 | 急停是**锁存**的。点【解锁急停】才能重新控制 |
| 误差 8% 却写回了参数 | 不应该发生：本页的验收判定取**绝对值**（上游的 `error_ratio` 是带符号的，直接比 3% 会让 -8.9% 也算"通过"）。如果真遇到，先看界面上有没有"超线"提示 |
| 实验页说"上游缺少算参纯函数" | 上游版本不对（`solve_ratio` / `error_ratio` 是 1.3.0 才有的）。确认 `paths.remotecontrol_host` 指向最新那份源码 |
| 页面能开但一切都是死的 | 前端启动期抛了未捕获异常。现在会**把失败摆到界面上**（红框 + toast），照它写的 stage 去查 |
| **页面能开但主区空白 / 九页点进去都不动 / 控制台报某个 `assets/*.js` 404** | 浏览器把**新旧资源混着用了**：`index.html` 已换成新版（引用 `/static/assets/...`），但某个旧文件（`app.js` / `wsproto.js` / `views/mod_*.js`）还在缓存里 —— 或者反过来。服务端已给 `/` 与 `/static/*` 加 `Cache-Control: no-cache`（判据 **I20**），**强制刷新一次**（Ctrl+Shift+R）即可；此后不会再出现。⚠️ 改版二十五起那三个旧文件名**在磁盘上已经不存在**，所以"404 某个旧文件"只可能是缓存或反向代理 |
| 服务"没反应"、请求全超时 | 看它的输出（不在管道里就在终端）。三类已修原因：① 日志被同一条刷满 ② 子进程 stdout 用 PIPE 没读、缓冲写满把自己阻塞 ③ **某端点在事件循环上做了同步的设备往返 / 串口枚举 / 目录遍历** —— 症状是"服务端日志干净，但连纯内存的 `/health` 都超时"。见方案 §7.3 |
| **页面能开、顶栏状态不动、每一页都像是空的** | **页面那条 2.5 s 心跳没装上**（排在启动链的 `await` 后面，前面任何一步变慢就永不执行），此时页面**不报任何错**。按 F12 看 `C.state.health.uptime_s` 会不会涨；判据 **B22** 盯这个。根因在服务端，修法见方案 §6.4.2 |
| 连什么都连不上、但"服务还在跑" | 大概率是**一条"能打开但对端不存在"的串口把门面钉死了**：上游调度线程卡在 `serial.write` 上并握着命令锁 ⇒ 之后任何 `connect` 都永不返回，而 `/health` 照样 200。**重启 Control 服务**，并把那个可疑串口拔掉。此时 `/health` 里 `connect_in_flight` 会是 `true` |

## 8. 纪律（改代码前先读）

1. **只消费上游，不改上游源码。** 两个模块各有自己的取证体系，改了那些判据就不再成立。
   `tools/preflight.py` 与 `tools/drill.py` 都会看**上游目录**的 `git status`；
   注意 drill 判的是**增量**（开跑前拍一张、收尾再拍一张，只问"多出来什么"）——
   上游本身就是你在开发的东西，工作区常有几十条未提交改动，要求"全空"只会制造假警报。
2. **文本是唯一真相来源。** 文档改 `.md`，HTML 由 `python tools/build_doc_html.py` 生成；
   **禁止手改 `.html`** —— 必然与 md 分叉。
3. **依赖统一由仓库根目录 `requirements.txt` 提供。** 不在模块内单独安装或升级依赖，
   以免与 `Auto Locate` 所需的 `opencv-contrib-python` 冲突。
4. **不做上游已明确否决的事**。相机那一路的三条旧约束（不把 MJPEG 用于测量、不追求实时全帧率定位、
   不做手机端定位算法）随改版二十四**整块失效** —— 现在没有实时帧流可测，位置来自离线视频。
   仍然有效的是：**不重写 Auto Locate 的解析与时间轴**（它保证一致，本层只校验与显示）。
   服务只绑 `127.0.0.1`（默认 8770），要开 `0.0.0.0` 必须先补鉴权。
5. **心跳不许排在 `await` 后面。** 启动链里那条定时器（旧前端是
   `setInterval(refreshHealth, 2500)`；新前端是 `assets/lib.js` 的 `setInterval(tick, 250)`）
   必须站在最前面 —— 它挪到后面过一次，表现就是"整页静默死掉"（服务端日志干净、
   浏览器零异常）。启动链按"失败了会不会致命"排序，不按"先拿到什么"排序。
   ⚠️ 新前端的 `tick` 目前只推进本地模拟数据，**不代表 health 心跳**；接线时两者都要有。
6. **事件循环上不许同步摸设备、不许扫盘。** 同步的设备往返（上游很多调用带 3 s 超时）、
   串口枚举、目录遍历，一律 `run_in_executor`。签名是"服务端日志干净，但整个服务不答话"。
   不要往 `/health` 或 `/caps` 里加这类东西。
7. **一个页面只干一件事，换页不跳转。** 改版二十五起是**左轨导航 + 单页 hash 路由**
   （`#/live` `#/race` …），换页只切 `#main` 里挂载的视图，**不跳转、不开新标签** ——
   连接状态只有一份，两个标签会打架。
   加/改页面 = 改 `assets/lib.js` 的 `NAV` + 注册 `C.VIEWS.<id>` + 在 `index.html` 引脚本。
   ⚠️ **`control/static/**` 不再由本层维护**（要改界面行为走"提契约需求"）；
   本节其余各条仍然适用 —— 它们是**后端**的纪律。
