# Control —— 电脑鼠整合上位机

> **方向已冻结**：总体设计宗旨与布局方案见
> [`docs/上位机整合设计方案.md`](docs/上位机整合设计方案.md) 开篇「总纲（冻结）」一节。
> 该节是全文上位约束，后续任务不得改变；界面只放**状态 / 数值 / 控件 / 下一步点哪**。

把三个既有模块合成**一个界面**：

| 模块 | 提供 | 怎么接进来 |
|---|---|---|
| `../RemoteControl/host` | 电脑鼠直控、参数、遥测、波形、标定 | **同进程 import**（`host.api.MouseClient`） |
| `../Auto Locate` | ArUco 场地定位 | **同进程 import**（`aruco_locator`） |
| `../PhoneCamera/pc` | 手机俯拍采集与回传 | **跨进程 HTTP/WS**（独立服务 `:8765`） |

服务是**本机 Web**（默认 `http://127.0.0.1:8770`），不依赖 PySide6 / pyqtgraph。

## 1. 三条命令


## 2. 手上什么都没有也能验全部功能

**无鼠、无手机、无场地**也能把九页和整条链路跑通。

| 缺什么 | 怎么办 |
|---|---|
| 没有电脑鼠 | 起模拟器：`cd ../RemoteControl/host && $PY -m host.sim.mouse_sim`，然后点顶栏【电脑鼠】连 `tcp://127.0.0.1:5555` |
| 没有手机 | 【② 采集】页 →「离线会话导入」，用 `PhoneCamera/pc/data/sessions/` 里已有的真实会话 |
| 没有场地 | 【① 场地】页显示"坐标未标定"水印；定位结果照样算，只是固件格子与视觉格子对不上（`arena.calibrated=false`，不是 bug） |

一条命令把三者一起验：

```bash
$PY tools/browser_check.py --sim --shots .tmp/shots
```

会起模拟器、让服务端连上，再用无头浏览器把九个页面**真的渲染一遍**，
抓未捕获 JS 异常和坏请求，每页截图存到 `.tmp/shots/`。
不带 `--sim` 也能跑（会在 8765 起一个假上游相机，让二维码那两条判据跑得动）。

## 3. 界面：入口页只做导航，点卡片单开一个模块界面

主区是**两级**，**没有选项卡**：

1. **入口页只做导航** —— 四个子系统各一组，用**分割线与类别名称**竖排在一页里，
   组内是模块卡片。这里**不放控件、不放工作区**。
2. **模块界面** —— 点一张卡片**单开一个整屏界面**做那一个实验（一次只开一个），
   顶部一条【← 返回】回入口。地址栏记 `#/<子系统>/<模块>`，刷新、贴链接、后退都落得回去。

好处是"有哪些子系统、各自能做什么"一进门就在眼前，而真动手时屏幕上只有那一个实验的东西。

```
┌── 顶栏：设备状态，而且每个状态**本身就是按钮** ────────────────────────────────┐
│  [●电脑鼠] [●相机] [●定位] [●时钟]     点它 → 弹出该设备的窗口              │
│                                        （设参数 / 连接 / 看配对二维码）      │
├── 入口页：只做导航 ────────────────────────────────────────────────────────┤
│  ── 小车控制 — RemoteControl ─────────────────────────────────────────      │
│     实时参数 · 运动控制 · 校准例程 · 实验 8 · 无记忆走迷宫                    │
│  ── 相机 — PhoneCamera ──────────────────────────────────────────────      │
│     图像回传测试（实时灰度 / 彩色）                                         │
│  ── 定位 — Auto Locate ──────────────────────────────────────────────      │
│     定位测试 · 迷宫结构解析                                                 │
│  ── 综合运动 — 整体操作 ──────────────────────────────────────────────      │
│     综合运动台（原有两栏九页，推迟实现，当前保留）                             │
├── 页脚：实时读数 ｜ 服务日志                                                │
└───────────────────────────────────────────────────────────────────────────┘
                ↓ 点一张卡片 = 单开一个整屏模块界面
┌── 模块界面：← 返回   运动控制 · 小车控制 ─────────────────────────────────────┐
│    该模块的控件与读数（没有别的东西）                                         │
└───────────────────────────────────────────────────────────────────────────┘
```

**「综合运动台」里面才是原来的两栏**：左 = 场地 · 相机，右 = 小车 · 控制，**两栏同时在屏**。
底栏「整合」收起时占一行，展开是跨子系统合起来的产物（准备清单 · 会话 · ⑨ 数据）。

模块清单与完成度见 [`docs/未实现功能.md`](docs/未实现功能.md)。下面这张表说的是

## 4. 一次完整跑车

> 本节括号里的页号（①②…）都指**「综合运动台」界面里**的两栏九页 ——
> 入口页那张卡片点进去就是它（左栏场地 · 相机，右栏小车 · 控制）。

**先手动连好，再测试。** 底栏【整合】第一列是**准备清单**：三项（电脑鼠 / 手机相机 / 时间基）
各自显示状态。一路都没连上时，顶栏【开始记录】点不动，服务端也会 409 拦住并给出清单。

```
① 点顶栏【电脑鼠】：USB 线插好 ⇒ 在窗口的目标列表里**点选** ⇒ 再点【连接】。
   连上后回读设备信息（口名 / 协议 / 固件 / 状态）。
   ⇒ 若提示"被占用"：先关掉上游的 run_host.py（它独占串口）
② 点顶栏【相机】：
   · 手机与电脑接同一个 WiFi，打开手机 App
   · 窗口里显示**配对二维码** → 手机扫 → 点【手机扫好了 → 确认连接】
   · "服务可达"与"手机在线"是两件事；手机没连时采集会得到空会话（上游回 sent_to=0）
③ 【④ 标定】页做一次场地标定（只需一次，结果写回 config.yaml）
④ 【⑤ 发车】页确认三件事：
     · 能不能发（链路活、急停没锁存）
     · 时间对不对得上（点【发车 ARM】，等 2 个 TIME 帧，看偏移/频差/基准灯）
     · 有没有丢帧（seq_lost 必须是 0）
⑤ 【② 采集】页确认 plan.interval_ms = 0（不抽帧，每一帧都留）
⑥ 顶栏【开始记录】→ 三路同开，任何一步失败**全部回滚**，不留半个会话目录
⑦ 跑车。想让它自己跑迷宫就在【⑤ 发车】点【远程发车跑迷宫】
   （仅数据收集档固件实现；其余档位回 ERR_VALUE）
⑧ 顶栏【停止】→ 等投递完成 → **自动触发赛后批量定位**（权威数据，约 10 fps）
⑨ 展开底部【整合】栏 → ⑨ 数据：看轨迹 / 时间轴 / 无效帧统计，导出
```

**两段式定位**：在线段 ≈2 fps（受链路限）、赛后批量 ≈10 fps（覆盖每一帧、不占网）。
**权威数据是赛后那一段。**

**台面实验（标定位、调参）走【⑥ 实验】页**，与"场地上跑"是两套流程，实验前**轮子必须悬空**。
急停是**锁存**的：触发后运动命令返回 `ERR_ESTOP`，必须点【解锁急停】才能恢复控制。

## 5. 会话目录里有什么

```
sessions/2026-09-27_0306_2rnl/
├── meta.json               # 可复现的全部信息：时钟偏移/不确定度/来源、**设备时基（mc.timesync 的结论）**、场地标定、上游版本与 git HEAD
├── timeline.csv            # ★ 核心产物：每行必有 t_pc_ms
│                           #   列 = t_pc_ms, t_pc_iso, source, kind, ref, note, t_src, dev_ms
├── camera.json             # 相机会话引用（**不复制原始帧** —— 一场 3.9 GB）
├── mouse/
│   ├── raw.bin / raw.ts    # 原始字节流与时间戳
│   ├── stream_250hz.csv  stream_50hz.csv  stream_5hz.csv
│   ├── text.log            # 设备 printf
│   └── meta.json
└── locate/
    ├── results.jsonl       # ★ 权威结果：每帧一行，**无效帧也留档并带 reason**
    ├── results.csv
    ├── results_online.jsonl# 在线段的（可以更稀疏，供对照）
    └── run_meta.json       # 参数指纹、计数来源说明
```

**`timeline.csv` 的后两列**说明**这一行的时间是哪一种**：

| `t_src` | 含义 |
|---|---|
| `send` | 帧真正**发出**的时刻（固件毫秒时基经 `mc.timesync` 换算）—— **准确的那种** |
| `capture` | 相机帧真正**拍摄**的时刻（手机 `wall_clock_ns` 经标定偏移换算） |
| `arrival` | 只拿到"主机收到"的时刻（蓝牙/WiFi 抖动被算进去了） |
| `local` | 本层自己产生的事件（开会话、点按钮） |

`dev_ms` 是"发车以来毫秒"，用来和上游的 `stream_*.csv`、`results.jsonl` 直接对齐。

**三套时间基各归各的负责方，不许合成一个数**：

| 时间基 | 谁负责 |
|---|---|
| 固件毫秒时基 → 本机单调秒 | **上游 `mc.timesync`**（min-delay 偏移 + 最小二乘 ppm） |
| 本机单调秒 → PC 墙钟 epoch | 本层（单调推进 + 周期性重锚，**保证不回退**） |
| 手机 `wall_clock_ns` → PC 墙钟 | 本层（L2 最小延迟，**有偏上界**，带误差棒） |

PC 墙钟由**单调时钟推进**，不直接取 `time.time()`（会被 NTP 回拨，产生负的时间间隔）。

## 5b. 「实验 8」的复盘记录放哪

「实验 8」的**记录**与**会话目录**是两回事：会话目录是"整场三路数据"，
复盘记录是"**一次迷宫跑**的完整切片"，落在 `records/maze/`（`config.yaml` 的 `records.maze_root`）：

```
records/maze/2026-10-05_1712_a1b2.maze.json
```

一份自包含 JSON：**元信息**（起止/时长/`why`/`end_why`）、**全量 39 通道每帧**
（`channels` 列名 + `t_ms` 时刻 + `frames` 值数组）、**迁移序列**、**上行事件**、
**决策序列**（`decisions`，8 类：任务 / 路口 / 转向 / 直行 / 岔路 / 进格 / 朝向 / 终点）、
**完整性统计**（帧数 / `evq_seen` / `drop_seen` / `tiny`）、`wall`（重建结果）、
可选 `firmware_map`（固件墙图，作对账基准）。

> 老记录文件里没有 `decisions` 字段（本版新增）⇒ 读的时候会**从帧重放重建**
> 并标 `decisions_rebuilt`。**帧在，决策就在** —— 差分是纯函数。

### 右栏怎么用（时间线进度条 / 回放）

右栏**最顶上**那条就是时间线进度条，它驱动的不只是右边那条时间线，还有**左/中两栏的"此刻"**：

| 状态 | 进度条 | 三栏 |
|---|---|---|
| **运行中**（`● 运行中` 绿） | 停在最右（"现在"） | 全部跟着**最新帧**刷 |
| **已停止**（`■ 已停止` 灰） | 停在最右 | **仍然实时**（只是它不再产生新决策） |
| **回放中**（蓝） | 可拖，量程 = 这一段的时间长度 | 左/中显示**游标那一刻**，右栏**定位到那一刻** |

- 【进入回放】：**在跑的时候也能进**（取的是那一刻的内存快照，不落盘、不打断记录）；
  不在记录时用最近一条已保存的记录。
- **直接拖进度条 = 自动进入回放**（现场看到一屏数据想回看刚才那一刻，第一反应就是拖它）。
- 拖的是**时间**不是帧号：帧在时间上不均匀（真机 4.4~6.5 Hz，还会丢帧），
  按帧号拖会让"拖到中间"落在时间的偏早或偏晚。
- 【退出回放】= **立刻回到最新**（三栏马上跟回实时，进度条回到最右）。

⚠️ **回放和实时必须读到同一份决策** —— 右栏实时那条读的是记录器内存里的**常驻决策环**，
回放那条是从内存快照（`/maze/record/live`）或落盘文件里**重新差分**出来的。
**发车 = 开新纪元**：清两个常驻环 + 换一个全新的差分器，零点交给"发车后的第一帧"。
（旧实现只把零点往前挪、不换段，于是上一段的决策留在环里成了**负时间** ⇒
两条来路必然对不上。发车被拒时会**整套回滚**，不抹掉右栏正在看的那一段。）
实时环、快照、落盘三份**逐条相等**这条由判据 **I30** 钉住，见 §11.14。

右栏每一条决策都是**帧里返回值的差分**（上游 v2.0 删掉了事件流，只能主机差分）：
`路口 岔路口(T型,缺右) [TEE_FL] (1,0)` / `转向 TURN（转向动作）(1,0) 朝 东` /
`岔路栈 0 → 1` / `到达终点区 (7,7) 目标 (7,7)`。
⚠️ `GOAL` 报的是"进入了它认为的那个目标格"（帧只给一对 `goalX/goalY`，
而固件的判据是"两个目标格的并集"）—— 这处差异真机验收时要专门对一遍。

## 6. 判据 / 怎么重跑

```bash
$PY tools/drill.py --sim            # 逐条判（--sim 才会验 I15~I17 / I22~I23 / I27~I28 / I30：需要活链路）
$PY tools/check_iface_table.py      # 上游 ↔ Control ↔ 路由表 三方一致
$PY tools/browser_check.py --sim    # 入口页 + 模块界面 + 综合运动台九页，真渲染 + 逐条断言
$PY tools/browser_check.py --no-fake-cam   # 同上，但走"相机不可达"那条降级路（见下）
$PY tools/neg_i30.py                # I30 的变异验证：撤掉"开新纪元"的修复必须变红（纯内存，不连设备）
```

当前实测：

| 命令 | 结果 |

## 6b. Ctrl+C 收工之后，上游服务会怎样？

**默认：留着不停**（`camera.launcher.stop_on_exit: false`）。

理由：手机连的是那个服务，而"服务"这个语义本身就要求它比控制端活得久 ——
现场经常是 Control 重启一次、手机不该跟着断。收尾时日志会**写明**它还在跑：

```
[info] 上游相机服务仍在运行（PID 17912，由 Control 代启）—— 手机还连着它，所以默认不停。
       要停：点相机窗口的【停止】（或结束该 PID）；想让它随 Control 一起停，把
       camera.launcher.stop_on_exit 设为 true。
```

要让它跟着一起关，两条路（都不用改代码）：

- 相机窗口 →「上游程序」→ 勾上 **【收工时停止】** → 【保存设置】；
- 或直接把 `config.yaml` 的 `camera.launcher.stop_on_exit` 改成 `true`。

⚠️ 无论哪种，**只停本层代启的那个**（按进程句柄校验）。别人启动的服务一律不动 ——
我们没有它的父子关系，杀错了就是把人家的现场切断。

## 7. 常见故障

| 现象 | 原因 / 怎么办 |
|---|---|
| 顶栏【相机】显示"不可达" | 相机服务没在跑（窗口里会写明是 8765 连不上）。**点窗口里的【启动上游服务】即可**（本层代启 `pc/server.py`，不必去双击 `start_service.cmd`）；开窗口/点【配对】时默认也会自动代启。窗口底部那块红字就是**可照做的清单** |
| 点了【启动上游服务】报"端口已被别的程序占用" | 8765 上有别人的程序（不是相机服务）。关掉占用者，或把地址与代启端口改成另一对（设置里两处一起改）。**不要**去 `taskkill` 一个不认识的进程 |
| 点了【启动上游服务】报"进程已退出（返回码 1）"，日志里是 `UnicodeEncodeError` | 上游程序在打印自己的启动横幅时被**控制台编码**打断（简体中文机器默认 GBK，而横幅里有 `▶ ■` 这类字符）。本层已为子进程设 `PYTHONIOENCODING=utf-8 / PYTHONUTF8=1`，正常情况下不会再出现；若仍出现，说明该程序另有编码来源（自己设了环境变量或用了别的解释器） |
| 点了【启动上游服务】报"25 s 内没起来" | 窗口里会带日志尾巴。日志为空多半是子进程还在（Python 写文件是块缓冲）；先确认端口与地址一致、程序路径没写错。要手动接手就双击 `PhoneCamera/pc/start_service.cmd`（先确认 8765 空着） |
| 想自己管上游进程，不让 Control 插手 | 两个办法：设置里关掉「配对时自动启动」；或 `POST /api/v1/camera/service/pause {"on": true}`（**只影响本次运行**，不写配置） |
| **改完设置，config.yaml 打不开了** | 不应该发生：写回前会先自己解析一遍，过不了就整项不写并告警（`not_written`）。如果真遇到，说明是**手工编辑**改坏的 —— 看报错的行号，YAML 的缩进必须用空格且同级一致 |
| 不同数字的刷新节奏**不一样** | 不应该发生了：2.0.0 起只有**一条统一帧**，所有字段的更新节奏一样。若真看到某一路明显滞后，那是**那一帧的值如此**（不是"另一条流慢"）—— 先看这一页顶上的实测帧率与"最新一帧"年龄 |
| 「实时参数」的红外/电压恒为 `—` | 那些量全在**同一条统一帧**里 ⇒ 恒为 `—` 只有一个意思：**帧没在来**（没连上，或遥测拉取没开）。2.0.0 起没有"另走一条路再问一次"这回事了（`SNAP` 已删）|
| 电池显示 `0 mV` | 比赛固件**从不打开电池监视**，那是"**没采**"不是"**没电**" —— 别去查电池。`battMv` 只在打开了监视的固件上才有意义 |
| 帧率只有个位数 Hz（不是 217） | **这是正常的**。2.1.0 起遥测由上位机逐条拉取，可达帧率 = 1/往返 ≈ **4.4~6.5 Hz**（瓶颈是蓝牙透传的转发延迟，与串口速率无关）。界面上那个「（协议常量 217）」只是对照，不是"应该有"的值 |
| 突然连 `PING` 都不应答了 | 蓝牙透传模块的缓冲被灌满了（上一轮持续推流所致），它**不会自愈**。**先把遥测拉取关掉**（顶栏【电脑鼠】窗口里的开关），等十几秒让缓冲排空 —— 不用断电，也不用拔线。这条正是 2.1.0 拉取模式的用处 |
| **图像回传测试一片空白** | 先看那一行「监视道」：<br>· **`上游未推过画面 · 手机端需开启预览`** ⇒ 手机侧的问题（画面源是手机 App 上行的缩略图；App 不出画面，PC 端就没有）。Control 这边一切正常，去手机 App 里把预览打开<br>· `已收到 · seq N` 在涨而画面不出来 ⇒ 渲染侧（到顶栏【相机】看服务是否可达）<br>· `未订阅上游` ⇒ 反代没连上，点【灰度】重开一次 |
| 日志里反复出现 `MJPEG 订阅者断开` | **正常事件**（info）：你切页 / 刷新 / 点【停止】时浏览器会关掉这条流。只有 `MJPEG 上游读取中断`（warn）才是真故障 |
| 相机窗口里二维码是空的 | 配对信息（含 token 的网址 + 二维码矩阵）**只从相机服务读**，本层不自己拼 —— 拼出来的码指向一个不存在的服务，比没有码更坏。所以**先看状态是不是"不可达"**；服务在跑却仍然没码时，窗口会写明"无二维码矩阵"，按上面的网址/配对码手输一样能连 |
| 连串口报"被占用" | 串口是**独占**的。先关掉上游的 `run_host.py`（带 GUI 的那个）再连 |
| 采集 `sent_to=0` | 采集指令发出去了但**没有任何手机接收** ⇒ 手机会话是空的。检查配对页的网址与 token |
| 【⑤ 发车】显示"未发车" | 还没点【发车 ARM】。没发车就没有 TIME 帧，帧的**发送时刻**就算不出来，时间轴只能退回记"到达时刻"（`t_src=arrival`） |
| 远程发车报 ERR_VALUE | `MAZE RUN` 只在**数据收集档**固件里实现，其余档位会拒绝 |
| 课程参数的值一列全是 `—` | **这是 2.0.0 固件的读侧缺口**：`GET ALL` / `GET <name>` 只查**生产表**（24 项），课程 14 项一律回 `ERR_NAME`。**但它是能写的** —— 把新值填进输入框再按 SAVE 即可（不填就没有值可落盘）|
| 想「停车后回传课程日志」找不到按钮了 | 2.0.0 删了 `SCOPE`/`DUMP` ⇒ 没有这条通道了。曲线在【执行实验】期间**就地捕获**并随结果返回；想再看一遍就重跑一次实验 |
| 「实验 8」的任务迁移序列是空的 | 那个序列是**主机差分相邻帧**推出来的（不是设备事件流）：要么迷宫没跑起来，要么**帧一直没来**（先看实时参数页的实测帧率）。注意 `SEQ` 跳变时中间缺帧 —— 那一段的边沿"当时没收到"，不等于"没发生过" |
| 实验 8 的迁移序列看着"少了几条" | 看界面上的「事件流不完整」块（来自帧 `flags` bit7 的 `EVQ`）。**事件行与遥测帧共用一个 1 字节序号**，序号跳变就说明丢过 —— 丢了**补不回来**，只能复位重跑。记录文件里也如实记着这一段的完整性 |
| 记录点了【停止并保存】却没生成文件 | 空记录**不会**写成文件（一帧都没收到）。看「记录」那一行的帧数：如果是 0，先解决"帧没在来"（同上一条），别去找文件 |
| 记录没自动收尾、一直在记 | **这是预期的**：固件没有"迷宫结束"事件，自动收尾是**弱判据**。跑完点【停止并保存】即可（模拟器上尤其必须手点）|
| 实验 8 点【发车】后没有状态 | 状态量在**统一帧**里，所以要**遥测拉取开着**才看得到（顶栏【电脑鼠】窗口里的遥测开关）。另外 `MAZE RUN` 只认数据收集档固件 |
| 跑完迷宫后别的运动命令都被拒 | 无记忆走迷宫跑起来后 `mouse_task` 停在 `MAZESEARCH`，运动互斥判据因此一直"忙"。**先点【收车】**（上游 2.1.1 的 `MAZE STOP`：停车 + 复位发车状态 + 解锁急停）⇒ 不必断电就能再发车。⚠️ 若任务机**仍停在 SEARCH**，说明车还在动 —— `MAZE STOP` 只置"请退出"标志，而标志的检查在主循环 `while(1)` 顶部、车在运动时轮不到检查（真机实测）⇒ 改用【救援】 |
| **发车被拦下、说电池太低** | 那是**上位机的保护闸**（上游 2.2.1），不是设备拒绝 —— **命令压根没发出去**。低电时红外发射管变暗 ⇒ 墙检测失效、电机行为不确定，真机事故就是"电机一直转且对红外不敏感"。⇒ 充电或换电后重试。确需台架调试，把电脑鼠**架离地面**后用逃生舱 `send_raw("MAZE RUN")` 强发。⚠️ 显示 `0 mV` 是"**电池监视未开启**"，不是没电，那种情况**不拦** |
| **发车时回 ERR_ESTOP** | 急停是**锁存**的：不解锁的话固件会收下请求、再被 ISR 每帧把速度清零，现场看起来就是"发了车却不动"。⇒ 先点【解锁急停】（发的就是 `STOP`） |
| 车不动了、命令还回 OK、连【收车】也没用 | **卡死**：固件主循环有 30 余处**非协作式阻塞等待**（等的是编码器里程这类物理进度），而 `STOP` 会把 `freemode` 置 1 ⇒ 电机 PWM 恒 0 ⇒ 那些条件**永远不可能满足** ⇒ "越停越死"（看门狗也救不了：喂狗在 SysTick 中断里，主循环卡死对它不可见）。⇒ 点【救援】（上游 2.2.0 的 `MCU RESET`，整机软复位）。真机实测：卡住 → 复位 → 回 `WAIT` 约 1.1 s，**无需断电** |
| 【救援】点了但说"没复核到复位" | 看那一行的 `rst`：**仍是 `POR`** ⇒ 没复位成功（旧固件收到 `MCU RESET` 会回 `ERR_CMD`、`rst` 保持 `POR`）；**是 `—`** ⇒ 设备不答话，查串口。⚠️ 成功判据是 `rst == "SW"`，**不是"ACK 收到了"**（复位会与 ACK 抢链路，`accepted=False` 不代表失败） |
| **救援成功后立刻发车又撞墙/乱走** | 这是**已知且必然**的：复位**只复位固件、不复位物理位置** —— `mousePos`/`mapWall`/`stackIdx` 全被清零，而车还在迷宫原处 ⇒ 它会按"**我在起点 (0,0)**"的**错地图**行驶，既不认路也不认墙。⇒ **发车前必须人工把电脑鼠放回起点角**。另：复位后**约 3 s 才有新遥测帧**，别急着判读状态（此前读到的是旧帧或 `main()` 尚未初始化完的早帧） |
| 按了急停但车没立刻停 | 若你用的是**旧上游**（2.1.2 之前）：根因是固件每 1 ms 只消费一行命令，而拉取器在持续发 `TELEM` ⇒ `STOP` 与某条 `TELEM` 落进同一窗口就被丢掉，要等 2.5 s 超时重发。真机实测"转速归 0 用时 **3220 ms**"—— 那正好是 `MOVE RUN` 的时间护栏，也就是"**根本没生效**"。2.1.2 起上游给时间敏感命令加了"**让路**"（发送前暂停拉取），实测 0/5 重发、594 ms 停下 ⇒ **升级上游即可** |
| 电机不动但命令回 OK | 设备跑的是安全测试固件（`MOUSE_TEST_NO_MOTOR`），电机输出恒为 0。本层会**提前一行说清**，不会让你等到 90 s 超时 |
| 急停后一切运动命令被拒 | 急停是**锁存**的。点【解锁急停】才能重新控制 |
| 误差 8% 却写回了参数 | 不应该发生：本页的验收判定取**绝对值**（上游的 `error_ratio` 是带符号的，直接比 3% 会让 -8.9% 也算"通过"）。如果真遇到，先看界面上有没有"超线"提示 |
| 实验页说"上游缺少算参纯函数" | 上游版本不对（`solve_ratio` / `error_ratio` 是 1.3.0 才有的）。确认 `paths.remotecontrol_host` 指向最新那份源码 |
| 【② 采集】显示"已跳过探测" | 相机不可达时本层**一个相机请求都不发**（每个端点要干等 2 s）。修好相机后点「重探一次」 |
| 页面能开但一切都是死的 | 前端启动期抛了未捕获异常。现在会**把失败摆到界面上**（红框 + toast），照它写的 stage 去查 |
| **页面能开、入口页卡片空或模块界面空，或写着"前端启动失败 … reading 'mod_params'"** | 浏览器把**新旧资源混着用了**：`index.html` 已是新版（会加载 `mod_*.js`），而 `wsproto.js` 还是缓存里的旧版（没有 `C.mods`）⇒ 六个模块脚本全部注册失败。服务端已给 `/` 与 `/static/*` 加 `Cache-Control: no-cache`（判据 **I20**），**手上这台浏览器强制刷新一次**（Ctrl+Shift+R）即可；此后不会再出现 |
| 服务"没反应"、请求全超时 | 看它的输出（不在管道里就在终端）。三类已修原因：① 日志被同一条刷满 ② 子进程 stdout 用 PIPE 没读、缓冲写满把自己阻塞 ③ **某端点在事件循环上做了同步的设备往返 / 串口枚举 / 目录遍历** —— 症状是"服务端日志干净，但连纯内存的 `/health` 都超时"。见方案 §7.3 |
| **页面能开、顶栏状态不动、每一页都像是空的** | **页面那条 2.5 s 心跳没装上**（排在启动链的 `await` 后面，前面任何一步变慢就永不执行），此时页面**不报任何错**。按 F12 看 `C.state.health.uptime_s` 会不会涨；判据 **B22** 盯这个。根因在服务端，修法见方案 §6.4.2 |
| 连什么都连不上、但"服务还在跑" | 大概率是**一条"能打开但对端不存在"的串口把门面钉死了**：上游调度线程卡在 `serial.write` 上并握着命令锁 ⇒ 之后任何 `connect` 都永不返回，而 `/health` 照样 200。**重启 Control 服务**，并把那个可疑串口拔掉。此时 `/health` 里 `connect_in_flight` 会是 `true` |
| 场地页坐标看起来镜像 | `arena.fw_to_arena.y_flip` / `x_flip` 猜错了。这两个是布尔量，**错了不报错**，必须靠【④ 标定】实测 |

## 8. 纪律（改代码前先读）

1. **只消费上游，不改上游源码。** 三个模块各有自己的取证体系，改了那些判据就不再成立。
   `tools/preflight.py` 与 `tools/drill.py` 都会检查三个仓库的 `git status` 是否干净。
2. **文本是唯一真相来源。** 文档改 `.md`，HTML 由 `python tools/build_doc_html.py` 生成；
   **禁止手改 `.html`** —— 必然与 md 分叉。
3. **环境固定 `general_env`。** 不要为了图快在别的环境装包。
4. **不做上游已明确否决的事**：不把 MJPEG 用于测量；不追求实时全帧率定位；
   不做手机端定位算法。服务只绑 `127.0.0.1`（默认 8770），要开 `0.0.0.0` 必须先补鉴权。
5. **心跳不许排在 `await` 后面。** `app.js` 里那条 `setInterval(refreshHealth, 2500)`
   必须站在启动链最前面 —— 它挪到后面过一次，表现就是"整页静默死掉"（服务端日志干净、
   浏览器零异常）。启动链按"失败了会不会致命"排序，不按"先拿到什么"排序。
6. **事件循环上不许同步摸设备、不许扫盘。** 同步的设备往返（上游很多调用带 3 s 超时）、
   串口枚举、目录遍历，一律 `run_in_executor`。签名是"服务端日志干净，但整个服务不答话"。
   不要往 `/health` 或 `/caps` 里加这类东西。
7. **入口页只做导航。** 功能控件一律进**单开一个整屏模块界面**（`#mod`）；换界面只切
   `#sys` 上的 `.mod-open`，**不跳转、不开新标签** —— 连接状态只有一份，两个标签会打架。
   加/改模块 = 改 `app.js` 的 `SYS_DEF`（+ 注册 `C.mods`），**别在 `index.html` 里手写卡片**。
